Web API 加密逻辑分析
    第 3 阶段：DevTools Sources 调试

    学习目标
        能说明 Sources 中生成源码、原始源码、Source Map 和 Pretty Print 的区别
        能从 Network 的 Initiator 进入 Sources，并把发起位置当成调用链索引而不是字段生成位置
        能根据已观察到的路径片段、字段名和响应键搜索候选代码
        能正确选择行断点、条件断点、Logpoint、XHR/fetch 断点、事件监听器断点和异常断点
        能在暂停时阅读暂停原因、Call Stack、Scope、Watch、this 和异步调用来源
        能区分同步调用栈、异步来源、当前调用帧和被选择的调用帧
        能记录调试器对时序、超时和动态字段有效期造成的干扰
        能在不修改请求和页面代码的条件下形成一份可复核的调用链证据记录

    本阶段不学习
        不提供真实站点案例、靶场、练习或实战任务
        不使用 Replay XHR、Edit and Resend、Copy as cURL、Copy as fetch 或其他请求重放功能
        不修改请求 URL、查询参数、请求头、Cookie、请求体或响应
        不使用 Local Overrides、Snippets、代理、CDP、浏览器自动化或注入脚本改变页面行为
        不使用 Hook、Monkey Patch、函数替换、属性劫持或原型修改
        不绕过反调试、混淆、验证码、风控、权限、付费内容或 DRM
        不分析哈希、HMAC、AES、RSA、Web Crypto、CryptoJS 或具体签名算法
        不还原 webpack、Vite、Worker、Service Worker 或 WASM 的内部实现
        不把暂停时看到的值直接改写为复现代码

    版本与资料状态
        Chrome DevTools 会随浏览器版本更新
        Sources 中的按钮位置、侧栏名称、菜单名称、图标和快捷键可能变化
        同一功能在不同语言界面中可能使用不同文字
        Source Map、异步调用栈和 Ignore List 的显示方式也可能随版本变化
        本阶段按照功能含义讲解，不依赖固定按钮位置
        开始记录前需要写明浏览器名称、完整版本、操作系统和界面语言
        如果当前界面与教程不同，应先在 DevTools 当前版本的命令菜单或设置中按功能名称查找
        本阶段编写时未能连接 Chrome DevTools 在线官方文档
        因此只采用稳定的调试器概念，不把版本相关界面细节写成固定事实

    Sources 的证据范围
        能直接观察
            当前 DevTools 展示的脚本资源和源码表示
            当前断点是否已设置、是否已启用以及暂停发生的位置
            当前暂停原因
            当前可见的同步调用栈和异步调用来源
            被选择调用帧对应的 Scope、this 和表达式求值结果
            当前界面是否显示 Source Map、Pretty Print 或 Ignore List 状态
        不能直接证明
            当前显示的原始源码一定与部署时生成代码完全匹配
            Source Map 一定正确、完整或属于当前构建
            函数名称一定是开发者编写时的原始名称
            Initiator 所在函数就是目标字段的生成函数
            某个高熵值一定经过加密
            某个字段一定由当前页面线程产生
            服务端如何验证请求
            暂停状态下观察到的时序与正常运行时相同
        结论原则
            暂停位置、当前帧和当前可见变量可以记录为观察事实
            沿调用栈得到的调用先后关系可以记录为当前运行的调用链证据
            字段用途、算法类型和业务含义仍属于推断
            无法进入的异步来源、缺失源码和未命中断点应记录为未知

    调试范围与授权记录
        调试前需要确认
            页面、脚本和账号都在已记录的授权范围内
            允许使用浏览器开发者工具进行只读调试
            允许重复触发的页面操作不会产生未授权真实数据变更
            当前操作不涉及其他用户数据
        本阶段允许
            打开 Sources
            查看当前页面已加载的源码
            搜索已观察到的非敏感字符串
            设置和删除 DevTools 断点
            在暂停时读取必要的局部值
            记录脱敏后的调用链和位置
        本阶段不允许
            编辑第三方生产源码
            向页面注入新代码
            调用会修改状态的函数
            修改变量、属性、DOM、Storage 或网络请求
            把凭证、个人数据和完整敏感值复制到笔记
        停止条件
            调用链进入未授权页面、扩展或第三方上下文
            Scope 或响应中出现其他用户数据
            调试要求绕过权限、风控、付费或 DRM
            继续暂停可能导致真实事务处于不确定状态

    一次调试会话
        概念
            从固定调试环境开始，到完成一条调用链记录为止，称为一次调试会话
        每次会话需要记录
            对应的第 2 阶段采集编号
            浏览器名称和完整版本
            操作系统和界面语言
            页面构建标识或可见版本信息
            页面是否经过重新加载
            Disable cache 状态
            Source Map 是否启用并可用
            Ignore List 是否启用
            目标代码运行在主页面、子 frame、Worker 还是其他执行上下文
            断点类型和设置位置
            暂停开始时间、恢复时间和暂停持续时间
        会话之间不要直接合并
            页面重新加载可能取得不同构建
            缓存状态可能改变脚本来源
            Source Map 可能在某次会话加载成功、另一次失败
            登录状态和动态字段可能随时间变化

    Sources 的主要区域
        源码导航区域
            用于选择页面加载的脚本和其他可查看资源
            常见视图会按页面、来源、frame 或资源路径组织文件
            具体分组名称取决于 Chrome 版本和当前页面结构
        源码编辑区域
            用于查看生成源码、原始源码或格式化后的源码
            行号区域可用于设置行断点
            一行包含多个可暂停位置时，界面可能显示列级或行内暂停位置
        调试侧栏
            用于查看断点、调用栈、Scope、Watch 和暂停控制
            暂停后通常会显示暂停原因和当前调用位置
            侧栏顺序和折叠状态可能变化
        底部抽屉或 Console
            暂停时可在当前选择的调用帧上下文中求值
            求值并不天然只读，必须遵守本阶段的只读表达式限制

    页面、frame 与执行上下文
        顶层页面
            浏览器当前标签页的主文档通常是顶层页面
            顶层页面脚本在主 frame 的执行上下文中运行
        子 frame
            iframe 可以加载自己的文档和脚本
            子 frame 与顶层页面可以有不同来源和不同全局对象
            顶层页面中的断点不会自动覆盖另一个 frame 中不同的脚本实例
        执行上下文
            Console 和调试器求值依赖当前选择的执行上下文或调用帧
            同名全局变量在不同 frame 中可能表示不同对象
            记录值时必须同时记录所属 frame 或上下文
        页面导航
            导航可能销毁旧文档及其执行上下文
            旧调用帧不能作为新页面当前执行状态的证据
            导航后需要重新确认源码、断点和构建标识

    Worker 与 Service Worker 意识
        Worker
            Worker 在独立线程和独立全局环境中执行脚本
            主线程的同步调用栈不会包含 Worker 内部的同步调用帧
            主线程行断点不会命中 Worker 中另一个脚本实例
        Service Worker
            Service Worker 可以介入符合其作用域的网络请求
            页面请求的最终来源不一定只包含页面脚本
            本阶段只记录 Service Worker 是否参与，不分析其内部实现
        排查意义
            如果主页面找不到字段名或断点始终不命中，需要检查目标逻辑是否位于其他上下文
            不能因为主线程没有观察到生成逻辑，就断言浏览器端不存在该逻辑

    生成源码
        概念
            浏览器实际加载并执行的 JavaScript 表示称为生成源码
            生成源码可能经过打包、转译、压缩、模块拼接或名称缩短
        证据价值
            生成源码与当前加载资源直接相关
            没有可用 Source Map 时，生成源码是定位实际执行位置的重要依据
        限制
            一行可能包含大量语句
            函数名和变量名可能已变化
            模块边界可能不再对应开发时文件
            生成源码可读性低不代表逻辑不存在

    原始源码
        概念
            DevTools 可通过 Source Map 展示构建前的源文件表示
            原始源码可能是 TypeScript、JSX 或构建前 JavaScript
        证据价值
            文件结构和名称通常更便于阅读
            断点可能由 DevTools 映射到生成代码的可执行位置
        限制
            原始源码显示依赖 Source Map
            显示出来不证明映射文件与当前部署字节完全匹配
            某些源文件可能缺失内容、名称或完整路径
            原始源码中的一行可能映射到多个生成位置，也可能没有可执行映射

    Source Map
        作用
            Source Map 描述生成代码位置与原始源码位置之间的映射
            DevTools 可以据此显示原始文件、原始名称和对应位置
        Source Map 不做什么
            不执行代码
            不恢复已经不存在的运行时状态
            不保证还原所有变量名和函数边界
            不保证映射属于当前构建
        常见状态
            可用且映射成功
            声明了 Source Map 但文件无法取得
            Source Map 存在但部分源文件缺失
            Source Map 与当前生成文件不匹配
            当前 DevTools 设置禁用了 Source Map
        记录要求
            当前查看的是生成源码还是原始源码
            Source Map 地址只记录脱敏后的路径结构
            Source Map 是否成功加载
            断点设置在原始位置还是生成位置
            暂停后实际显示的原始位置和生成位置
        敏感信息
            Source Map 可能包含源文件路径、文件名和嵌入的源码内容
            不应未经检查直接共享 Source Map

    Pretty Print
        作用
            Pretty Print 对难以阅读的生成文本进行换行和缩进显示
            它可以让压缩代码的语句边界更容易观察
        不能恢复
            原始变量名
            原始文件结构
            原始注释
            原始模块边界
            原始业务语义
        位置记录
            Pretty Print 后的界面行号是格式化表示中的位置
            记录时需要注明使用了 Pretty Print
            如果能够取得生成文件位置，还应同时记录生成文件的行号和列号
        常见错误
            把格式化后的源码称为原始源码
            因为代码已经换行就认为 Source Map 已加载
            只保存格式化位置，导致其他环境无法定位同一生成字节

    Ignore List
        作用
            Ignore List 用于减少某些脚本对单步调试和调用栈阅读的干扰
            DevTools 可能自动忽略已知第三方脚本，也可以由用户配置
        可能影响
            某些调用帧被折叠或弱化显示
            单步进入可能跳过被忽略脚本
            暂停行为可能因版本和设置而变化
        分析要求
            记录 Ignore List 是否启用
            调用链出现缺口时检查是否有帧被忽略
            不能仅凭折叠后的调用栈认定中间没有函数
            临时查看被忽略帧时仍不得修改代码

    从 Network Initiator 进入 Sources
        前置证据
            使用第 2 阶段已经编号的请求
            已记录请求方法、脱敏后的路径、Type、Initiator 和发生时间
            已记录该请求是否经过重定向、预检或 Service Worker
        进入方式
            Initiator 列或请求详情可能提供源码位置或调用链入口
            能否直接跳转取决于请求类型、调用来源和当前 DevTools 版本
            无法跳转时应记录界面实际显示的 Initiator 文本
        Initiator 的含义
            它提供请求由何种资源或调用路径触发的线索
            它可能指向调用 fetch 或 XHR 的包装函数
            它也可能只显示 Parser、Redirect、Preflight、Script 或其他来源类型
        Initiator 不能证明
            该位置生成了所有请求字段
            该位置最先接收用户输入
            该位置执行了哈希或加密
            该位置设置了浏览器自动添加的请求头
        记录方式
            请求采集编号
            Initiator 的界面表示
            可见源码文件和行列位置
            是否存在同步或异步调用来源
            跳转后查看的是生成源码还是原始源码

    选择搜索线索
        优先使用直接观察到的稳定文本
            脱敏后的请求路径片段
            不包含秘密的字段名称
            自定义请求头名称
            响应中的稳定键名
            可见错误代码或固定消息片段
        不搜索敏感值
            Authorization 值
            Cookie 值
            Token 值
            个人数据
            完整动态签名值
        线索质量
            较长且稳定的路径片段通常比单个通用单词更容易缩小范围
            字段名可能同时出现在类型定义、日志、解析代码和请求构造代码中
            搜索命中只证明文本存在，不证明命中位置在当前调用链上执行

    搜索范围
        当前文件搜索
            只在已经打开的源码表示中查找文本
            适合确认同一文件中的相邻使用位置
        全部已加载来源搜索
            在 DevTools 当前已索引的来源中查找文本
            搜索结果可能包含页面脚本、第三方脚本和 Source Map 原始文件
        文件名快速打开
            根据文件名或路径选择已经加载的资源
            适合从 Initiator 文件名继续定位
        版本差异
            快捷键和入口可能因操作系统、Chrome 版本和键位设置而不同
            教程记录功能名称，不固定快捷键

    搜索未命中的解释
        目标字符串可能被运行时拼接
        路径可能来自配置对象或服务器响应
        字段名可能通过计算属性形成
        字符串可能经过编码后才出现
        目标代码可能在尚未加载的按需模块中
        目标逻辑可能位于 Worker、Service Worker、扩展或其他 frame
        生成源码可能压缩或改写了表示
        DevTools 当前搜索索引可能只包含已经加载的来源
        结论限制
            搜索未命中只能记录为“当前已加载来源中未找到该文本”
            不能写成“前端不存在该逻辑”

    可执行位置
        JavaScript 不是每个文本行都能独立暂停
        空行、注释、声明边界或映射缺失位置可能没有可执行代码
        DevTools 会把断点绑定到可执行位置
        断点标记的外观可能表示已绑定、未绑定、禁用或当前命中状态
        具体颜色和形状随版本与主题变化
        记录时写明“已绑定”或“未确认绑定”，不要只记录颜色

    行断点
        作用
            当执行到绑定的源码位置时暂停 JavaScript
            适合已经知道候选执行位置的情况
        设置前确认
            当前文件属于正确的 frame 或执行上下文
            当前查看的是生成源码还是原始源码
            行上存在可执行位置
            目标代码尚未执行或可以在授权范围内再次触发
        命中后记录
            暂停原因
            当前文件、行号和列号
            当前选择的调用帧
            同步调用栈
            可见异步来源
            相关 Scope 值
        限制
            一次命中只证明该次运行经过此位置
            未命中不证明该代码永远不会执行

    条件断点
        作用
            每次到达绑定位置时求值一个条件表达式
            条件求值为真时暂停
        适用情况
            同一行被频繁执行，只关注满足已知只读条件的调用
            只关注某个公开测试输入的类型、长度或固定非敏感标记
        风险
            条件表达式本身会被执行
            属性读取可能触发 getter 或 Proxy trap
            函数调用可能修改状态、发送请求或改变时序
            复杂表达式会增加每次经过该位置的开销
        本阶段限制
            只使用字面量、局部变量读取、typeof、严格相等和无副作用的长度读取
            不赋值
            不递增或递减
            不调用函数或方法
            不读取已知访问器属性
            不把完整秘密写进条件

    Logpoint
        作用
            到达绑定位置时求值表达式并把结果写入 Console
            通常不会像普通行断点一样暂停
        适用情况
            记录频繁经过位置的非敏感、只读值
            减少反复暂停造成的时序变化
        风险
            Logpoint 表达式仍会执行
            求值会增加运行开销
            getter、Proxy trap 和函数调用仍可能产生副作用
            Console 输出可能泄露秘密或个人数据
        本阶段限制
            只记录类型、长度、布尔状态和脱敏标识
            不输出完整请求、Cookie、Token、密钥或个人数据
            不调用 JSON.stringify 或其他可能执行自定义逻辑的方法
            无法确认只读时不使用 Logpoint

    XHR/fetch 断点
        作用
            当 XHR 或 fetch 发起的请求 URL 与指定文本匹配时暂停
            暂停位置通常接近请求发起调用，具体位置由实现和版本决定
        适用情况
            Network 已确认候选请求属于 XHR 或 fetch
            Initiator 入口不足以定位请求发起代码
            路径片段在源码中无法直接搜索到
        匹配文本
            使用不含域名秘密和凭证的稳定 URL 片段
            片段过短可能命中过多请求
            片段过长可能被动态参数影响而无法命中
        覆盖范围限制
            不保证捕获 Document 导航
            不保证捕获表单导航
            不保证捕获 sendBeacon
            不保证捕获图片、脚本、样式和媒体资源加载
            不保证捕获 Worker 或其他上下文中未附加的执行
        结论限制
            未命中时先核对 Network Type 和请求机制
            不能据此断言页面没有发出该请求

    事件监听器断点
        作用
            在指定类别的事件监听器运行时暂停
            可以从点击、提交、键盘或其他事件入口观察调用链
        适用情况
            已知请求由明确的页面事件触发
            尚不知道事件处理函数位于哪个文件
        限制
            同一事件可能有多个监听器
            事件可能经过委托、捕获和冒泡路径
            框架可能使用统一事件分发器
            命中的第一个监听器不一定最终发起请求
        记录要求
            事件类别和事件名称
            当前 target 与 currentTarget 只在确认读取无副作用时记录其脱敏摘要
            暂停位置和调用栈
            是否继续运行后才进入请求发起链

    异常断点
        Pause on exceptions
            JavaScript 抛出异常时暂停
            可用于定位被代码捕获后未明显显示的错误来源
        未捕获异常
            异常最终没有被当前代码处理
            暂停位置可以提供抛出点和调用栈
        已捕获异常
            某些版本可以选择同时在已捕获异常处暂停
            开启后可能产生大量与目标无关的暂停
        记录要求
            当前模式是只暂停未捕获异常，还是也暂停已捕获异常
            异常名称和脱敏后的消息
            抛出位置和调用栈
            后续是否被代码捕获
        限制
            异常断点只说明发生了异常
            不能单独证明异常与目标请求存在因果关系

    debugger 语句
        JavaScript 源码中可以存在 debugger 语句
        调试器已附加且暂停未被禁用时，执行到该语句可能触发暂停
        它属于页面原有代码时，可以记录为暂停原因
        本阶段不向第三方生产源码添加 debugger 语句
        看到大量 debugger 语句时只记录事实，不进行绕过或移除

    暂停与恢复
        暂停
            JavaScript 在当前执行位置停止继续运行
            页面其他依赖主线程的工作可能同时停止推进
        恢复
            让程序继续执行，直到结束、再次命中暂停条件或发生其他暂停原因
        暂停时必须先记录
            暂停原因
            当前文件和位置
            当前帧
            调用栈
            暂停开始时间
        不应执行
            不修改局部变量
            不修改对象属性
            不调用页面函数
            不强制返回
            不跳过函数执行

    Step over
        作用
            执行当前语句，并在当前调用层的后续可暂停位置停下
            当前语句调用的普通函数通常不会逐句进入
        适用情况
            已经确认当前函数，只想观察同一函数内值何时变化
        限制
            当前语句触发异步工作时，后续暂停位置可能不在预期的同步顺序中
            压缩代码和 Source Map 会影响界面显示的下一位置

    Step into
        作用
            尝试进入当前语句将要执行的函数调用
        适用情况
            需要确认某个包装函数调用了哪个内部函数
            需要沿参数传递方向进入下游调用
        限制
            一行可能包含多个函数调用
            引擎优化、内建函数、Ignore List 和映射状态可能导致跳过或跳转
            进入的函数不一定与目标字段相关

    Step out
        作用
            继续执行当前函数剩余部分，并在返回到调用方后的可暂停位置停下
        适用情况
            已确认当前函数不是目标层
            需要返回调用方继续检查参数来源或返回值使用位置
        风险
            当前函数剩余代码会真实执行
            如果剩余代码发送请求或修改状态，Step out 不会阻止这些行为
            使用前必须确认执行剩余代码仍在授权范围内

    单步位置跳动
        可能原因
            一行包含多个语句或多个可暂停列位置
            生成代码与原始源码映射不是一行对一行
            编译器合并、拆分或重排了表达式
            Ignore List 跳过了部分帧
            当前操作跨越 Promise、定时器或事件回调边界
            JavaScript 引擎对不可观察的内部步骤进行了优化
        记录原则
            记录实际暂停位置，不根据视觉顺序补写未观察步骤
            必要时同时查看生成源码位置
            无法解释的跳转记录为未知，不写成确定的控制流

    Call Stack
        同步调用栈
            显示当前暂停点尚未返回的同步函数调用帧
            最上方通常是当前执行的最新帧
            较下方帧表示调用当前帧的上层调用
        每个调用帧可能显示
            函数名或匿名标记
            文件名
            行号和列号
            是否来自被忽略脚本
        选择调用帧
            选择不同帧会切换源码位置、Scope、this 和 Console 求值上下文
            选择旧帧不会让程序倒退到该函数当时的早期语句
            实际暂停点仍然是最上方当前帧的位置
        名称限制
            压缩、打包和匿名函数会降低函数名可信度
            Source Map 可能提供原始名称，也可能缺失或错误
            记录时以文件位置和调用关系为主，函数名为辅助

    异步调用来源
        异步边界
            Promise、async/await、定时器、事件和消息传递会跨越同步调用栈边界
            回调真正运行时，安排它的同步函数通常已经返回
        DevTools 显示
            某些版本会在 Call Stack 中显示异步调用来源或异步祖先
            它表示调度关系线索，不是当前尚未返回的同步调用帧
        限制
            异步来源可能被截断
            浏览器设置、性能限制和代码结构会影响可见深度
            Worker 消息两侧不一定显示为一条连续调用栈
        记录方式
            同步帧与异步来源分开记录
            写明异步边界类型
            不把异步祖先写成当前正在执行的函数

    Scope
        作用
            显示当前选择调用帧可访问的变量绑定
        常见分组
            Local
            Closure
            Script
            Module
            Global
        版本与代码差异
            不是每次暂停都会出现所有分组
            分组名称和顺序可能变化
            块级作用域可能以单独层次出现
        阅读顺序
            先确认当前选择的调用帧
            再读取函数参数和 Local
            再检查 Closure 中真正被引用的外层变量
            最后才查看更大范围的 Script、Module 或 Global
        证据限制
            Scope 显示的是当前暂停时可见状态
            它不自动提供变量过去的值
            对象内部属性可能在后续展开时发生变化
            读取访问器属性可能执行代码

    this
        this 的值取决于函数调用方式和代码模式
        不同调用帧可以有不同的 this
        箭头函数没有自己的 this 绑定，而是使用词法环境中的 this
        选择调用帧后再记录该帧的 this
        this 为 window、undefined、DOM 对象或业务对象都不能单独证明函数用途
        不展开包含敏感数据的完整对象

    Watch
        作用
            在暂停和单步过程中重复求值指定表达式
            结果基于当前选择的调用帧和执行上下文
        适合记录
            typeof value
            value === null
            Array.isArray(value)
            已确认是普通数据属性的字符串或数组 length
        风险
            Watch 表达式会实际执行
            切换调用帧后同名变量可能表示不同值
            getter、Proxy trap 和函数调用可能产生副作用
            表达式错误可能来自当前帧中变量不可见
        本阶段限制
            不赋值
            不调用业务函数
            不调用对象方法
            不序列化完整对象
            不读取完整凭证和个人数据
            不把 Watch 结果当作历史轨迹

    暂停时的 Console 求值
        求值上下文
            Console 通常在当前选择的调用帧中解析变量
            切换调用帧后，表达式结果可能变化
        只读表达式仍需审查
            普通标识符读取通常不会修改状态
            属性读取可能调用 getter
            Proxy 属性读取可能触发 get trap
            类型转换可能调用用户定义逻辑
            展开对象或复制对象可能暴露敏感字段
        禁止表达式
            赋值表达式
            ++ 或 --
            delete
            new
            await 页面业务函数
            函数调用和方法调用
            DOM、Storage 和网络修改操作
        记录要求
            表达式原文
            当前调用帧
            脱敏后的结果
            是否确认表达式无副作用

    调用链追踪顺序
        第一步：固定请求证据
            选择第 2 阶段的一条候选请求
            记录采集编号、时间、Type 和脱敏路径
        第二步：读取 Initiator
            保存 Initiator 的界面表示
            如果可跳转，记录目标文件和位置
            如果不可跳转，不根据名称猜测源码位置
        第三步：确定执行上下文
            确认主 frame、子 frame、Worker 或其他上下文
            确认生成源码、原始源码或 Pretty Print 表示
        第四步：搜索稳定文本
            先搜索路径片段
            再搜索字段名、自定义头名和稳定响应键
            每个命中只列为候选位置
        第五步：选择最小干扰断点
            已知可执行位置时优先使用普通行断点
            只知道 XHR 或 fetch 路径时使用对应 URL 断点
            只知道页面事件入口时使用事件监听器断点
            条件断点和 Logpoint 必须通过副作用检查后再使用
        第六步：重复同一授权操作
            使用与采集会话一致的公开测试输入和页面状态
            只触发一次操作
            不同时改变缓存、语言、时区或登录状态
        第七步：记录暂停现场
            暂停原因
            当前位置
            同步调用栈
            异步来源
            当前帧参数、Local、必要 Closure 和 this
        第八步：沿调用链移动
            先确认当前函数的输入和输出角色
            根据证据选择 Step into、Step over、Step out 或新的行断点
            每次只验证一个调用关系
        第九步：与 Network 对照
            比较暂停时可见的非敏感字段结构与 Network 中的字段结构
            只记录名称、类型、长度和位置关系
            不在本阶段判断具体算法
        第十步：停止并恢复
            到达本阶段边界后停止继续深入
            记录恢复时间和暂停持续时间
            检查该次请求是否因暂停而超时或失效

    从调用链识别数据流位置
        输入位置
            函数参数或外层变量中首次出现目标字段结构
        转换位置
            值的类型、长度、编码表示或字段位置发生变化
        组装位置
            多个字段被放入同一个对象、查询结构或请求体结构
        发送位置
            组装结果被传给 XHR、fetch 或包装层
        当前阶段只记录
            输入名称和类型
            转换前后类型与长度
            对象中的字段位置
            调用方和被调用方位置
        当前阶段不判断
            转换是否属于加密
            算法名称
            密钥、IV、nonce 或签名规则

    观察、派生事实、推断与未知
        直接观察
            断点在文件某位置命中
            当前帧参数包含某字段名
            调用栈显示函数 A 调用了当前函数 B
            当前值类型为 string，长度为某个观察值
        派生事实
            两个已记录位置属于同一次暂停的同一调用栈
            某字段在进入函数前后长度发生已计算的变化
            同一会话中某对象结构与 Network Payload 的键集合相同
        推断
            某函数负责签名
            某字段用于防重放
            某段高熵文本是密文
            某个闭包变量是密钥
        未知
            缺失的异步来源
            未加载的按需模块
            Source Map 是否与部署构建匹配
            服务端怎样使用该字段
        写作要求
            推断必须同时写出依据和替代解释
            没有直接证据时保留未知
            不把函数名中的 sign、encrypt、token 当作算法证明

    调试器对程序行为的干扰
        时序改变
            暂停会延长真实经过时间
            定时器、事件、Promise 后续和网络超时可能因此改变顺序
        动态字段
            timestamp 可能在恢复发送时已经过期
            nonce 或一次性值可能因重复操作发生变化
            短期 Token 可能在暂停期间失效
        网络结果
            请求可能在暂停前尚未发送
            请求可能已经发送，但响应处理在暂停期间被延迟
            页面或服务端可能因超时进入不同分支
        并发与竞态
            Worker、其他标签页和服务端不会因主线程暂停而全部停止
            共享状态可能在暂停期间继续变化
        证据要求
            记录每次暂停持续时间
            标记请求是在暂停前、暂停中还是恢复后发出
            暂停过的 Timing 不作为正常运行时性能证据
            请求超时或动态字段失效时，不把失败解释为算法错误

    调试器不能反向执行
        选择较旧调用帧只改变查看上下文
        它不会把程序恢复到该帧先前的执行时刻
        Step out、Step over 和 Resume 都会继续向前执行
        错过关键位置后需要在相同授权条件下重新运行
        重新运行属于新的调试会话或新的暂停记录
        两次运行的动态值不能默认相同

    断点没有命中的排查顺序
        检查断点是否启用
        检查断点是否绑定到可执行位置
        检查暂停是否被全局禁用
        检查代码是否在设置断点前已经执行
        检查页面是否在设置后重新加载或导航
        检查当前文件是否属于正确构建
        检查 Source Map 是否失效或位置映射改变
        检查是否设置在原始源码但没有对应生成位置
        检查 Ignore List 是否影响单步或暂停观察
        检查代码是否运行在子 frame、Worker 或 Service Worker
        检查目标请求是否确实由 XHR 或 fetch 发起
        检查 URL 断点片段是否出现在实际请求 URL 中
        检查条件表达式是否始终为假或求值失败
        检查目标分支是否在本次公开测试输入下执行
        检查缓存或旧页面是否避免了目标代码重新运行
        最终记录
            写“本次会话中断点未命中”
            写明已经排除的条件
            保留尚未排除的替代解释
            不写“该函数不会执行”

    找不到目标源码的排查顺序
        确认脚本资源已经加载
        清除 Sources 搜索过滤条件
        检查当前搜索范围是否包含全部已加载来源
        检查路径是否由多个字符串片段拼接
        检查字段是否使用计算属性或映射表
        检查按需模块是否尚未加载
        检查子 frame 和 Worker 上下文
        检查是否只有生成源码而没有 Source Map
        使用 Network Initiator 和 XHR/fetch 断点重新取得执行入口
        仍找不到时
            记录搜索词、搜索范围和构建标识
            记录“当前已加载来源中未定位”
            不进入 Hook、注入或反调试绕过

    调用栈出现缺口的排查顺序
        检查缺口是否位于异步边界
        检查 Ignore List 是否折叠了调用帧
        检查 Source Map 是否只显示部分原始帧
        检查是否跨 frame 或 Worker 消息边界
        检查 DevTools 是否限制了异步栈深度
        检查函数是否由浏览器内部或原生实现调用
        不能恢复时
            分别记录缺口前后的已观察位置
            把中间关系标记为未知
            不根据函数名称补写调用关系

    常见错误
        把 Initiator 当成字段生成函数
            问题
                请求发起包装层可能只接收已经组装好的数据
            修正
                沿实际调用栈记录参数进入和转换位置
        把 Pretty Print 当成 Source Map
            问题
                Pretty Print 只改变显示格式
            修正
                分别记录格式化状态和 Source Map 状态
        只看原始源码，不核对生成位置
            问题
                Source Map 可能缺失、过期或不匹配
            修正
                对关键暂停同时保存可见的原始位置与生成位置
        把搜索未命中当成逻辑不存在
            问题
                字符串可能动态生成，代码也可能尚未加载
            修正
                记录搜索范围，并使用运行时断点取得入口
        把断点未命中当成函数不会运行
            问题
                上下文、构建、时机、条件和映射都可能不正确
            修正
                按固定顺序排查并保留未知
        在 Watch 中调用函数
            问题
                表达式可能修改状态或重复发送请求
            修正
                只使用经过副作用审查的读取表达式
        展开完整对象并复制
            问题
                对象可能包含凭证、个人数据或访问器属性
            修正
                只记录必要字段名称、类型和脱敏摘要
        把异步祖先当成同步帧
            问题
                安排回调的函数通常已经返回
            修正
                同步调用栈和异步来源分开记录
        选择旧帧后认为程序已回退
            问题
                选择帧只改变查看上下文
            修正
                错过位置时重新运行相同授权操作
        忽略暂停造成的超时
            问题
                动态字段或请求可能在暂停期间失效
            修正
                记录暂停持续时间，不把超时直接解释为逻辑错误
        一次单步验证多个猜想
            问题
                无法区分哪个观察支持哪个结论
            修正
                每次只验证一个调用关系或一个字段变化
        根据函数名判断算法
            问题
                名称可能被压缩、映射错误或只是业务命名
            修正
                本阶段只记录数据流位置，算法留到后续阶段

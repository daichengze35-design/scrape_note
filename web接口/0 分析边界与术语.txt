Web API 加密逻辑分析
    第 0 阶段：分析边界与术语

    学习目标
        能区分字符编码、二进制文本编码、URL 编码、序列化、压缩、哈希、MAC、加密和数字签名
        能说明 Cookie、Token、JWT、timestamp、nonce、TLS 分别解决什么问题
        不根据字段名、Base64 外观、十六进制外观或高熵值直接断定“加密”
        能把观察到的事实与尚未验证的推断分开记录
        能说明一个分析任务是否处于自己拥有或明确授权的范围内

    本阶段不学习
        不定位前端代码
        不调试浏览器请求
        不修改、重放或复现任何接口
        不分析 DRM、许可证、受保护媒体播放链路
        不绕过登录、权限校验、验证码、风控、访问频率限制或付费限制

    Web API 加密逻辑分析
        概念
            Web API 是浏览器或其他客户端通过 HTTP、HTTPS、WebSocket 等方式与服务端交换数据的接口
            Web API 加密逻辑分析是确认客户端在发送或接收数据时，是否进行了编码、序列化、压缩、哈希、认证、签名或加密等处理
        目标
            正确分类每个数据处理步骤
            找到经过验证的输入、输出和约束条件
            记录结论的证据来源与不确定部分
        不应把以下概念混为一谈
            请求可以使用 HTTPS，但请求字段未必经过应用层加密
            请求可以有 sign 字段，但 sign 未必是数字签名
            请求可以有 token 字段，但 token 未必可解码或可验证
            数据可以是 Base64、Hex 或高熵文本，但未必是密文

    分析范围与授权边界
        可以分析的对象
            自己开发、拥有或获得明确书面授权的 Web 应用
            授权范围内的账号、请求、前端代码和测试数据
            公开文档、公开协议规范和自己生成的示例数据
        不在本课程操作范围内的行为
            绕过登录、权限校验、验证码、风控、访问频率限制或付费限制
            获取、复用、伪造或分享他人的 Cookie、Token、密钥或会话
            对未授权生产系统修改请求、重放请求、压力测试或采集数据
            获取 DRM 密钥、许可证、受保护媒体明文或规避播放限制
        记录原则
            观察到的请求字段、响应字段和浏览器行为属于事实
            未阅读产生逻辑或服务端验证逻辑前，只能把字段标记为“待分类字段”
            字段名为 sign、token、encrypt、data、key 不构成算法结论

    数据与字节
        字符
            人能阅读的文本单位，例如 A、a、1、你
        字节
            计算机传输和处理的数据单位
            网络请求体、文件和密码学输入最终都以字节形式处理
        字符串
            一组字符构成的文本值
        字节串
            一组字节构成的数据值
        重点
            同一段文本经过不同字符编码后，得到的字节可能不同
            密码学算法处理的是字节，不是“看起来相同”的文本
            在后续分析中，字符编码、换行、空格、字段顺序和 URL 编码都可能改变最终输入字节

    字符编码
        概念
            字符编码规定字符如何转换为字节，以及字节如何解释为字符
        UTF-8
            UTF-8 是常见的字符编码
            ASCII 字符在 UTF-8 中通常占 1 个字节
            常见中文字符在 UTF-8 中通常占多个字节
        特点
            字符编码不使用密钥
            字符编码不提供保密性
            知道编码规则后，任何人都可以把字节还原为字符
        易混淆点
            UTF-8 不是加密算法
            “乱码”通常表示字符编码解释不一致，不能据此认定数据被加密

    二进制文本编码
        概念
            把字节表示为可传输、可复制或可打印的文本
        Base64
            Base64 把字节转换为有限字符集合组成的文本
            Base64 常见字符包括大小写字母、数字、+、/ 和 =
            = 常用于 Base64 补位，但 Base64 文本不一定包含 =
        Hex
            Hex 用 0-9、a-f 或 A-F 表示每个字节的十六进制值
            一个字节通常对应两个 Hex 字符
        特点
            Base64 和 Hex 使用公开规则
            Base64 和 Hex 不使用秘密
            Base64 和 Hex 不是加密
        易混淆点
            Base64 解码后得到的内容可能是明文、压缩数据、密文或任意二进制数据
            Hex 文本很长、字符范围很小，不代表它是哈希或密文

    URL 编码
        概念
            URL 编码把 URL 中不适合直接出现的字节表示为 %HH 形式
            HH 是一个字节的两位十六进制表示
        常见场景
            查询参数
            application/x-www-form-urlencoded 请求体
            URL 路径中的特殊字符
        特点
            URL 编码不使用密钥
            URL 编码不是加密
            URL 编码不是序列化
        易混淆点
            空格可能表示为 %20，也可能在表单编码中表示为 +
            同一文本在 URL 编码前后的字节表示不同，后续签名分析必须记录实际规则

    序列化
        概念
            序列化把结构化数据转换为可以传输或保存的文本或字节
        常见格式
            JSON
            application/x-www-form-urlencoded
            MessagePack
            Protobuf
        JSON
            JSON 常用于 HTTP 请求体和响应体
            JSON 中字段顺序、空白、字符转义和数字写法都可能影响最终字节
        表单编码
            application/x-www-form-urlencoded 常把键值对表示为 key=value，并用 & 连接多个字段
        重点
            同一业务数据可以序列化成不同字节
            当后续机制依赖请求体字节时，不能只比较“字段含义是否相同”
        易混淆点
            JSON 不是加密
            序列化不是压缩
            序列化结果可以在后续被哈希、签名或加密

    压缩
        概念
            压缩使用可逆规则减少数据体积
        常见格式
            gzip
            Brotli
            zstd
        特点
            解压通常不需要秘密
            压缩结果可能没有可读文本结构
            压缩结果可能呈现高熵外观
        易混淆点
            高熵不能证明数据已加密
            无法直接阅读的数据可能是压缩数据，也可能是任意二进制数据

    哈希
        概念
            哈希函数把任意长度的输入字节计算为固定长度的摘要
        常见算法
            SHA-256
            SHA-512
            MD5
        特点
            相同输入字节与相同算法会得到相同摘要
            摘要长度由算法确定，不由原文长度确定
            常规使用中不能从摘要还原原始输入
        用途
            数据比对
            完整性指纹
            后续认证机制的组成部分
        限制
            仅有哈希不能证明消息来自某个身份
            哈希不提供保密性
        易混淆点
            一个 64 个 Hex 字符的字段可能是 SHA-256 摘要，也可能只是普通文本
            必须依据产生逻辑或验证逻辑确认算法，不能只凭长度判断

    MAC 与 HMAC
        MAC
            MAC 是 Message Authentication Code 的缩写
            MAC 使用共享秘密为消息计算认证标签
            验证方持有同一秘密后，可以验证消息是否被修改，并确认发送方掌握该秘密
            MAC 不提供保密性
        HMAC
            HMAC 是基于哈希函数构造的 MAC
            HMAC-SHA-256 表示使用 SHA-256 的 HMAC
            HMAC-SHA-256 不等于普通 SHA-256
        易混淆点
            “把参数和一个字符串拼接后再 MD5”不能仅凭字段名认定为 HMAC
            只有明确存在密钥参与和对应验证关系时，才能把机制分类为 MAC 或 HMAC

    加密
        概念
            加密使用密钥把明文转换为密文，以保护内容的保密性
            只有持有正确密钥的一方才能还原明文
        对称加密
            加密和解密使用同一秘密，或使用可等价推导的秘密
            AES 是常见的对称加密算法
        非对称密码学
            使用成对的公钥和私钥
            RSA 和椭圆曲线算法可以用于不同的密码学用途
        完整性
            加密本身不必然提供防篡改能力
            某些认证加密模式同时提供保密性和完整性
        本阶段的判断限制
            仅凭密文长度不能确认算法
            仅凭 Base64 或 Hex 外观不能确认算法
            仅凭高熵不能确认算法或密钥来源

    API 请求签名
        概念
            API 请求签名是业务语境中的总称
            服务端通常用它校验请求完整性、来源、时效或特定业务规则
        可能的实现类型
            HMAC
            其他共享秘密 MAC
            非对称数字签名
            服务端保存的自定义验证规则
        判断原则
            必须根据签发方、验证方和密钥关系分类
            不能只根据字段名 sign、signature 或 auth 判断类型
        重要关系
            API 请求签名不自动等于数字签名
            API 请求签名不自动等于加密
            API 请求签名不自动代表用户已经登录或拥有资源权限

    数字签名
        概念
            数字签名通常由私钥签发、公钥验证
            数字签名用于验证签名者持有私钥，并验证消息完整性
        特点
            数字签名的主要目的不是保密内容
            数字签名不是“把消息加密后得到的字段”的同义词
        与 MAC 的区别
            双方共享同一秘密时，通常属于 MAC 类机制
            由私钥签发、公钥验证时，才属于数字签名

    身份认证、授权与状态载体
        身份认证
            验证请求主体是否拥有其声明的身份或凭证
        授权
            在已识别请求主体后，判断其是否有权执行某项操作或访问某项资源
        关系
            认证成功不表示一定获得目标资源的授权
            请求签名可能证明客户端具备某种认证材料，但不自动代表用户权限
        Cookie
            浏览器会按照 Domain、Path、Secure、SameSite 等规则自动携带 Cookie
            Cookie 可以保存会话标识，也可以保存其他状态
            Cookie 本身不等于登录凭证
        Token
            Token 是系统定义的凭证或状态值
            Token 可以是不透明随机值，也可以携带可解析声明
            Bearer Token 的持有者通常可被视为凭证持有者，因此不能泄露或共享
        JWT
            JWT 是一种令牌表示格式
            JWT 不自动等于加密
            JWT 的签名、加密和验证细节在后续密码学阶段学习

    timestamp、nonce 与重放
        timestamp
            timestamp 表示某个时间点或时间值
            服务端可据此限制请求有效期
            timestamp 单独存在时，请求仍可能在有效窗口内被重复提交
        nonce
            nonce 是一次请求使用的唯一值
            nonce 可以由随机数或唯一序列生成
        重放防护
            只有服务端校验唯一性、有效期以及与请求身份或内容的绑定时，nonce 才能参与重放防护
            请求中出现 nonce 字段，不等于服务端一定实现了重放防护
        易混淆点
            timestamp、nonce、requestId 和 traceId 的业务作用可能不同
            必须依据实际产生和验证逻辑判断字段作用

    TLS 与应用层数据处理
        TLS
            HTTPS 通常通过 TLS 保护客户端和服务器之间传输中的 HTTP 通信
            TLS 可提供传输中的保密性、完整性和服务器身份验证等能力
        应用层数据处理
            前端 JavaScript 在发送请求前可以对字段进行编码、序列化、压缩、哈希、MAC、签名或加密
            这些处理与 TLS 处于不同层次，可以同时存在
        判断原则
            使用 HTTPS 不证明请求字段经过应用层加密
            某个字段经过应用层加密也不能替代 TLS
            网络层看到 TLS 流量，不足以判断应用层字段的具体处理方式

    DRM 边界
        DRM
            DRM 是受保护内容的授权、许可证和播放控制体系
        本课程边界
            加密媒体分片、许可证请求和受保护解码路径属于 DRM 或受保护媒体范围时，不纳入本课程分析对象
            本课程只保留 DRM、许可证和受保护媒体的术语识别
            本课程不讲解获取密钥、许可证、明文媒体或规避播放限制的方法

    未知字段的记录方法
        原则
            先记录事实，再形成分类结论
            不使用“肯定是加密”“一定是签名”等无证据表述
        字段记录模板
            字段名称
                例如：sign、data、token、timestamp
            出现位置
                URL 查询参数、请求头、Cookie、请求体或响应体
            原始值
                保留必要的长度、字符集和编码信息；不记录或传播真实凭证
            变化条件
                哪些公开测试数据变化后，该字段是否变化
            已观察事实
                例如：字段只包含 Hex 字符；字段长度为 64 个字符
            当前分类
                编码、序列化、压缩、哈希、MAC、加密、认证状态或待分类字段
            证据来源
                请求记录、公开文档、自己拥有的前端代码或已授权测试结果
            置信度
                已验证、部分验证或未验证
        记录示例
            字段名称
                sign
            已观察事实
                字段只包含 Hex 字符，长度为 64 个字符
            当前分类
                待分类字段
            正确结论
                当前只能说明该字段具有固定长度和 Hex 文本外观，不能确认它是 SHA-256、HMAC、数字签名或加密结果

    常见错误判断
        Base64 就是加密
            错误
                Base64 是二进制文本编码
        HTTPS 就不存在应用层加密
            错误
                TLS 和应用层数据处理可以同时存在
        有 sign 字段就是数字签名
            错误
                sign 可能是 MAC、哈希、自定义校验值或其他字段
        有 nonce 字段就一定防重放
            错误
                是否防重放取决于服务端验证策略
        高熵数据一定是密文
            错误
                高熵数据也可能是压缩结果或其他二进制数据
        Cookie 一定是登录凭证
            错误
                Cookie 可以保存多种状态，具体作用由系统决定
        JWT 一定可解密
            错误
                JWT 是令牌表示格式，不自动代表加密

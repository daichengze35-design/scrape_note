Web API 加密逻辑分析
    第 5 阶段：签名逻辑还原

    学习目标
        能把签名生成链拆成字段来源、字段选择、排序、规范化、序列化、字符编码、密码学入口、输出封装和请求放置
        能从第 2 阶段的 Network 记录回到第 3 阶段的 Sources 调用链
        能区分 JavaScript 业务对象、签名输入表示、签名输入字节和浏览器最终请求表示
        能准确记录普通对象、数组、键值对序列、URLSearchParams、FormData、Headers、字符串和字节视图的差异
        能说明 Object.keys、Reflect.ownKeys、Array.prototype.sort 和 JSON.stringify 的顺序边界
        能说明 URL 编码、form 编码、Query、路径、Header 和 Body 怎样改变签名输入
        能记录 timestamp、nonce、请求标识和会话状态的来源与生成时机
        能在不能反向执行时，通过上游断点和新的调试会话逐段建立数据流证据
        能形成不包含秘密值和可执行签名器的签名行为规范

    本阶段不学习
        不提供真实站点、靶场、练习或实战任务
        不编写能够生成真实签名或发送请求的程序
        不修改、阻断、重放、伪造或自动发送任何请求
        不使用 Hook、Monkey Patch、Local Overrides、Snippets、代理注入或函数替换
        不调用页面签名函数生成新值
        不提取、猜测、暴力搜索、导出或传播密钥、Token、Cookie、密码和会话材料
        不探测服务端签名验证分支或根据错误响应试探内部规则
        不绕过认证、授权、验证码、风控、付费限制或 DRM
        不进入 webpack、Vite、混淆控制流、Worker、Service Worker 或 WASM 的内部实现

    规范与版本状态
        本阶段涉及 ECMAScript、WHATWG URL、Fetch、Encoding、XHR 和多个 RFC
        这些规范和浏览器实现会更新
        已核对的稳定事实包括
            普通对象的自有键顺序
            Object.keys 与 Reflect.ownKeys 的键范围
            Array.prototype.sort 的默认比较与稳定性
            JSON.stringify 的属性访问和特殊值规则
            URLSearchParams 的有序重复键、排序和 form 编码规则
            encodeURIComponent 与 form 编码的差异
            Headers 的名称和值规范化边界
            FormData 的有序条目和浏览器生成 multipart boundary
        仍需按目标环境记录
            浏览器名称与完整版本
            JavaScript 引擎版本
            HTTP 客户端库和版本
            Headers guard 与受限字段行为
            multipart boundary 的实际值
            Service Worker 或其他运行时层是否参与
        不能从 API 迭代视图推断最终传输层字节顺序

    “签名”用词边界
        业务字段名
            sign
            sig
            signature
            token
            auth
        字段名不能证明密码学类别
        候选机制可能是
            普通哈希摘要
            MAC 或 HMAC
            数字签名
            校验和
            编码或随机值
            缓存值
            服务端预先下发并由页面转发的值
        分类依据
            实际原语
            密钥关系
            输入字节
            算法参数
            输出怎样进入请求
        本章中的“签名逻辑”
            表示产生业务校验字段的完整客户端处理链
            不预先断言该字段属于数字签名

    还原的定义
        完整还原
            形成一份可审计的行为规范
            不等于写出可执行签名器
            不等于能够生成、伪造或重放请求
        四条证明轴
            输入字节
                原语实际接收了哪些字节
                字段、顺序、分隔、编码和长度是什么
            算法参数
                实际执行的原语、算法、模式和完整参数是什么
            密钥模型
                无密钥、共享秘密、私钥、派生密钥还是不透明句柄
            输出封装
                原语输出经过哪些编码、截断、拼接并放到请求哪个位置
        部分还原
            四条证明轴中任意一条缺少直接证据
            字段包含条件或分支仍存在核心未知
            只能写为“部分规范”

    结论绑定范围
        每项结论都需要绑定
            BUILD-ID
            CAPTURE-ID
            DEBUG-SESSION-ID
            浏览器与版本
            页面构建
            请求类别
            实际执行分支
            生成源码位置与原始源码位置
            同一次函数调用
        不能跨范围扩展
            一个端点的规则不能自动用于另一个端点
            一个内容类型的规则不能自动用于另一种 Body
            一个构建的规则不能自动用于新构建
            一个成功分支的规则不能自动用于错误或重试分支

    执行实例与证据编号
        EXECUTION-ID
            表示一次页面操作触发的一次具体请求生成执行
            同一操作重新运行必须使用新的 EXECUTION-ID
        EVIDENCE-ID
            每条证据必须引用 BUILD-ID
            每条证据必须引用 CAPTURE-ID
            每条证据必须引用 DEBUG-SESSION-ID
            每条证据必须引用 EXECUTION-ID
            暂停证据还需要引用暂停位置、调用帧和暂停序号
        TRACE-GROUP-ID
            可以把同一构建、请求类别和分支下的多个执行组织为一个研究组
            TRACE-GROUP-ID 不会把多个执行变成同一次调用链
        允许组合
            多次执行可以共同支持一个行为规范
            每条数据流边必须在至少一次明确 EXECUTION-ID 中直接观察
            静态赋值或调用关系可以辅助说明不同执行为何属于同一代码结构
        禁止组合
            不能把一个执行的具体输入值与另一个执行的具体输出值写成同一值流
            没有共同 EXECUTION-ID 的暂停现场不能证明端到端具体值身份
        完成定义修正
            行为规范可以由多个已编号执行共同建立
            端到端具体值链只有在同一 EXECUTION-ID 内完整观察时才能成立

    证据等级
        UNKNOWN
            证据缺失、矛盾或无法绑定当前构建
        CANDIDATE
            只有名称、长度、外观、搜索命中或 A/A、A/B 相关性
        OBSERVED
            同一次执行中观察到相关调用路径
            四条证明轴尚未齐全
        ESTABLISHED
            单项结论在实际运行边界取得直接证据
            已绑定构建、分支、采集和调试会话
        VERIFIED
            在 ESTABLISHED 基础上又有当前规范、服务端验证实现或独立已知结果验证
        注意
            请求成功不能单独把任何结论提升为 VERIFIED
            置信度按单项结论记录，不能给整条链只写一个统一分数

    三层请求表示
        JavaScript 业务对象
            页面代码中的对象、数组、Map、字符串或其他容器
            还可能包含不会发送的内部字段
        签名输入表示
            经过筛选、排序、规范化和拼接后的文本或字节
            不一定与最终请求结构相同
        浏览器请求表示
            Request、Headers、URLSearchParams、FormData 或客户端库形成的请求
            浏览器还可能添加或规范化字段
        Network 表示
            DevTools 对浏览器请求的解析和显示
            不等于签名时中间文本
            不必然等于传输层原始字节
        记录原则
            每一层单独保存证据
            不把不同层的相同字段名视为同一字节表示

    从 Network 回到 Sources
        第一步
            选择第 2 阶段已经编号的请求
            记录方法、脱敏路径、内容类型和候选字段位置
        第二步
            记录 Network 中候选字段的最终文本表示
            不复制真实凭证或完整敏感值
        第三步
            使用 Initiator、XHR/fetch 断点或已知发送位置进入 Sources
            Initiator 只作为入口线索
        第四步
            在发送边界观察 JavaScript 可见的 URL、method、headers、body 和候选字段
            只读取类型、长度、结构和脱敏摘要
        第五步
            沿当前调用栈找到请求配置、字段组装、规范化和密码学入口
        第六步
            为每一步建立独立证据编号
            不因为函数名包含 sign 就跳过中间步骤

    发送边界
        可能位置
            fetch 调用
            XMLHttpRequest 的 open、setRequestHeader 或 send 附近
            Request 构造
            HTTP 客户端库的发送适配器
            页面自己的请求包装函数
        需要观察
            method
            URL 或 path
            Query 的当前表示
            Headers 当前视图
            Body 类型和长度
            候选结果字段
        不能证明
            当前对象就是最终传输字节
            浏览器不会继续添加 Header
            Service Worker 不会继续修改请求
            服务端实际验证了候选字段

    敏感值记录优先规则
        本规则优先于本章后续所有“记录实际字符串”“记录序列化器输出”或“记录编码前文本”表述
        只有已经确认不包含凭证、个人数据、密码、密钥、Token、Cookie 或会话材料的公开测试文本，才可以记录完整原文
        含有或可能含有敏感数据时
            原文只在当前授权调试会话的内存中观察
            不复制到笔记、截图、HAR 共享副本或日志
            只记录类型、字符长度、字节长度、编码、字段路径、分隔结构和脱敏占位符
            为同一会话内的值分配临时 VALUE-ID，而不记录值本身
        低熵秘密
            不通过保存普通哈希摘要规避本规则
            密码、短 PIN 和可枚举秘密的摘要仍可能支持离线猜测
        完整还原含义
            还原规则不要求保存某次真实敏感输入
            使用字段结构、长度、位置和转换规则即可形成可审计规范

    调试器不能反向执行
        在发送位置暂停后不能回到已经执行完的上游语句
        选择旧调用帧只改变查看上下文
        上游追踪顺序
            记录当前暂停现场
            找到当前值的赋值、参数或返回来源
            在更上游设置普通行断点
            恢复或结束当前会话
            重新执行同一个已授权操作
            建立新的 DEBUG-SESSION-ID
        禁止合并
            不能把第一次运行的 timestamp 与第二次运行的签名输出拼成同一次数据流
            不能把不同构建或不同分支的帧拼成一条调用链

    字段来源
        来源类别
            常量
            公开输入
            页面可见状态
            Storage 中的授权测试状态
            先前响应中的授权数据
            时间源
            随机源
            运行时环境
            服务端预先下发值
            未知
        首次出现
            记录第一次观察到该值或该字段结构的位置
            第一次搜索命中不等于第一次运行时出现
        数据流证明
            实际参数传递
            返回值传递
            赋值关系
            同一对象引用
            明确复制或序列化关系
        不能证明数据流
            两个值文本相等
            两个变量名称相似
            A/B 中同时变化

    字段包含
        完整包含
            原字段值按明确表示进入签名输入
        派生包含
            字段摘要、长度、编码结果或转换值进入签名输入
        条件包含
            只在某个内容类型、分支或值存在时进入
        包含证据
            同一次执行中观察该字段沿数据流进入最终原语参数
        不能仅凭
            字段出现在请求中
            字段在候选函数附近
            字段变化时签名也变化

    字段排除
        排除结论需要限定
            当前构建
            当前请求类别
            当前分支
            当前签名层
        排除证据
            字段集合由明确白名单选择且不含该字段
            规范化函数明确过滤该字段
            原语输入边界的完整结构已建立且没有该字段或其派生值
        排除证据强度修正
            白名单或过滤函数本身只能形成排除候选
            还必须证明该选择点是当前签名层唯一且完整的输入入口
            必须排除字段通过派生值、另一个对象或并行路径进入原语
            未建立候选字段全集和选择边界时，不能声称排除列表完整
            只有完整原语输入边界及其全部来源路径得到证明时，排除结论才能达到 ESTABLISHED
        不能作为排除证据
            静态搜索没有命中字段名
            A/B 中签名没有变化一次
            字段在另一个对象中出现
        签名字段自身
            最终 signature 字段常在计算后加入请求
            但不能不经代码证据就假设其一定被排除

    同名字段
        Query、Header、Cookie 和 Body 中可以存在同名字段
        同名不等于同一来源或同一值
        分别记录
            位置
            原始类型
            规范化规则
            是否进入签名
            最终文本表示
        不使用一个 FIELD-ID 代表不同位置的同名字段

    参数容器
        普通对象
            一个对象不能同时保留两个完全相同的自有字符串键
            后一次赋值通常覆盖同名属性值
        数组
            以索引和 length 表示有序元素
            元素顺序可能直接参与签名
        键值对序列
            可以保留重复名称和明确顺序
        Map
            按插入顺序迭代键值项
            键可以不是字符串
        URLSearchParams
            内部是有序 name-value tuple 列表
            允许重复名称
        FormData
            内部是有序 entry list
            允许重复名称和文件条目
        Headers
            具有名称验证、大小写规范化、值规范化和 guard 规则
        字符串与字节
            已经失去原始字段结构时，需要记录如何形成该表示

    缺失与空值
        必须分别记录
            字段缺失
            undefined
            null
            空字符串
            数值 0
            布尔 false
            空数组
            空对象
        可能处理方式
            保留
            省略
            转换为文本
            转换为 null
            使用默认值
            导致异常
        结论要求
            不能把 falsy 值统一写成空值
            不能从一次非空样本推断空值规则

    普通对象的自有键顺序
        OrdinaryOwnPropertyKeys 的稳定规则
            数组索引字符串按数值升序
            其他字符串键按创建先后顺序
            Symbol 键按创建先后顺序
        数组索引限制
            不是所有看起来像数字的字符串都是数组索引
            具有前导零的 01 不是数组索引形式
            -0 不是数组索引
            4294967295 不是数组索引
        结论
            “对象键全部按插入顺序”是错误概括
            “对象键自动按字母顺序”也是错误概括
        Proxy
            Proxy 的 ownKeys trap 可能提供不同顺序，但仍受规范不变量限制
            观察到 Proxy 时需要单独记录

    Object.keys
        返回范围
            对象自身属性
            可枚举属性
            字符串键
        不包含
            继承属性
            不可枚举属性
            Symbol 键
        顺序
            基于对象自有键顺序过滤后的结果
        签名影响
            使用 Object.keys 不能保留 Symbol 字段
            整数索引键会先于普通字符串键
        术语修正
            上面的“整数索引键”在普通对象自有键顺序语境中应精确写为“数组索引字符串”
            integer index 是范围不同的规范术语，不能代替 array index
            4294967295 等不属于数组索引的数字外观字符串不会进入数组索引优先顺序

    Reflect.ownKeys
        返回范围
            对象自身全部字符串键
            对象自身全部 Symbol 键
            包括不可枚举键
        普通对象顺序
            数组索引字符串
            其他字符串
            Symbol
        签名影响
            后续过滤和字符串转换仍可能改变顺序与表示
            不能把 Reflect.ownKeys 的结果等同最终签名字段

    for...in
        范围
            遍历可枚举字符串键
            可能包含原型链上的属性
            不包含 Symbol 键
        风险
            原型、动态增删、可枚举性变化、Proxy 和其他 exotic object 会影响观察
            同名继承属性可能被抑制
        结论
            不能把 for...in 简化为 Object.keys
            需要记录实际对象、原型和运行时环境
        现行规范的基准顺序
            对未发生规定结构变化的普通对象和普通原型链，顺序不是完全未知
            每一层按该对象的自有键顺序处理可枚举字符串键
            随后沿原型链继续
            已访问过的同名键会被抑制
        visited 集合精确规则
            每一层会按自有键顺序检查全部字符串键，不只检查可枚举字符串键
            字符串键先加入 visited 集合
            只有当前可枚举的键才会被产出
            因此不可枚举的自有字符串键也会抑制原型链上同名的可枚举键
        基准保证失效或需单独核对的情况
            枚举期间增删属性或改变可枚举性、原型
            Proxy
            Integer-Indexed exotic object
            Module Namespace exotic object
            其他实现提供的 exotic object

    Map 与键值对数组
        Map
            迭代保持插入顺序
            对象键与字符串键的表示不同
        键值对数组
            每一项可以显式保存 name 和 value
            允许重复名称
            可以在整体数组上排序
        转换风险
            转成普通对象可能丢失重复键
            非字符串键可能发生隐式字符串转换
            从对象转回键值对时顺序可能已改变

    Array.prototype.sort
        行为
            原地修改数组并返回该数组
        默认比较
            元素先转换为字符串
            按 UTF-16 code unit 的字典序比较
            不是数值升序
            不是 Unicode code point 顺序
            不是语言区域排序
        稳定性
            当前 ECMAScript 要求稳定排序
            比较结果相等的元素保留原相对顺序
            ES2019 以前的旧引擎没有统一稳定性保证
        undefined 与空位
            undefined 排在其他已定义元素之后
            稀疏数组空位保留为空位，并位于 undefined 之后
        比较器
            自定义比较器决定实际顺序
            需要记录比较器返回值和比较单位
        默认比较修正
            上面的“元素先转换为字符串”只概括普通已定义值
            undefined 由排序算法单独放在其他已定义元素之后，不对其执行普通字符串比较
            稀疏数组空位不作为普通元素传给比较过程
        比较器一致性
            比较器需要满足规范所要求的一致比较关系
            比较器若随时间变化、违反传递性或对同一输入返回不一致结果，排序结果由实现决定
            不能把一次运行结果写成跨环境规范

    localeCompare
        结果可能受影响
            locale
            sensitivity 等选项
            Unicode 与 Intl 数据版本
            浏览器和操作系统
        签名边界
            没有代码和环境证据时不能把 localeCompare 写成固定字节顺序
            区域相关排序不适合作为未明确规定的跨环境签名规则

    排序需要记录的维度
        排序对象
            键
            值
            键值对
            编码前文本
            编码后文本
        比较单位
            UTF-16 code unit
            Unicode code point
            UTF-8 byte
            数值
            自定义权重
        方向
            升序
            降序
        大小写
            原样
            转小写后比较
            转大写后比较
            大小写不敏感比较
        重复键
            是否保持原相对顺序
            是否同时比较 value
        位置
            编码前排序与编码后排序可能产生不同结果

    JSON.stringify
        输出
            返回 JavaScript 字符串
            不直接返回 UTF-8 字节
        普通对象属性范围
            自身属性
            可枚举属性
            字符串键
        默认属性顺序
            与 Object.keys 使用的顺序一致
            稳定不等于已经按键排序
            稳定不等于 canonical JSON
        replacer 数组

            按该列表顺序选择对象属性
            不改变数组按索引读取的规则
        space 参数
            可以插入缩进和换行

    JSON.stringify 的特殊值
        对象属性中
            undefined 被省略
            Function 值被省略
            Symbol 值被省略
        数组中
            undefined 写为 null
            Function 值写为 null
            Symbol 值写为 null
            空位写为 null
        数值
            NaN 写为 null
            Infinity 写为 null
            -Infinity 写为 null
        顶层值
            顶层 undefined、Function 或 Symbol 返回 JavaScript 的 undefined
        BigInt
            若处理后仍为 BigInt，默认抛出 TypeError
        循环引用
            默认抛出 TypeError

    JSON.stringify 的执行钩子
        属性读取
            可以执行 getter
            Proxy get trap 也可能运行
        toJSON

        replacer 函数

        记录修正

            敏感字符串只在内存中核对，笔记记录脱敏结构、长度和 VALUE-ID

    JSON 字符串版本差异

        旧引擎可能产生不同表示
        目标包含异常 Unicode 数据时需要记录引擎版本
        正常文本也不能忽略 Unicode 规范化形式

    canonical JSON
        普通 JSON 语义允许多种等价文本表示
        差异可能来自
            属性顺序
            空白
            数字表示
            字符转义
        JSON.stringify 不是通用 canonical JSON 工具
        RFC 8785 定义 JSON Canonicalization Scheme
        目标代码出现 RFC 8785 或 JCS 名称也只构成候选
        必须确认实际实现和输出字节

    字符串规范化
        可能步骤
            trim
            转小写或大写
            Unicode normalize
            换行统一
            空白折叠
            路径分隔处理
        记录要求
            函数名称
            参数
            输入与输出字符长度
            输入与输出字节长度
            使用的 Unicode normalization form
        风险
            大小写转换可能受语言规则影响
            可见文本接近不等于码点相同

    数值表示
        需要记录
            number、BigInt 还是字符串
            整数或小数
            是否取整
            小数位数
            指数表示
            正负号
            前导零
            -0
        JavaScript 边界
            Number 使用二进制浮点表示
            超过安全整数范围的整数不能默认精确表示
            String 转换和 JSON 序列化可能形成特定文本
        结论
            数值相等不保证原始文本相同
            不应先转 Number 再假定可恢复原文本

    路径边界
        需要记录
            前导斜杠
            尾随斜杠
            连续斜杠
            大小写
            百分号编码
            点路径段处理
            是否包含 Query
        不可替换
            编码的 %2F 与路径分隔符 / 不能未经证据互换

        浏览器 URL 解析
            可能规范化部分 URL 表示
            签名可能发生在解析前或解析后

    Query 的数据模型
        原始 Query 是有顺序的文本或键值对序列
        允许
            重复键
            空名称
            空值
            只有名称没有显式等号的文本形式
        解析损失
            转为普通对象会丢失重复键
            某些解析器会合并值
            解码后值不能恢复原始百分号大小写和编码选择
        签名要求
            记录原始表示与解析表示
            记录签名前使用哪一层

    URLSearchParams
        内部结构
            有序 name-value tuple 列表
            允许同名项
        字符串构造
            只移除开头一个问号
            按 application/x-www-form-urlencoded 规则解析
            不会把完整 URL 自动当作 URL 对象解析
        iterable 构造
            保持迭代顺序
            每一项必须恰有两个元素
        append
            在列表末尾添加新项
        set
            保留第一个同名项的位置并替换其值
            删除其余同名项
            如果不存在同名项，则把新项追加到列表末尾
        sort
            只按 name 的 UTF-16 code unit 升序稳定排序
            同名项保持原相对顺序
            不比较 value
        toString
            按当前 tuple 顺序序列化
            每项使用 name=value
            项之间使用 &
            返回文本不带开头的问号

    application/x-www-form-urlencoded
        编码基础
            字符先按 UTF-8 形成字节
        空格
            序列化为空格时使用 +
        不编码集合
            ASCII 字母
            ASCII 数字
            星号
            连字符
            句点
            下划线
        其他字节
            使用百分号编码
            内建序列化器使用大写 A 到 F 表示百分号后的十六进制数字
        解析
            先把 + 解释为空格
            再做百分号解码
        结论
            字面加号需要按规则编码才能与空格区分
            form 编码不是只把 %20 替换成 +

    encodeURIComponent
        不转义集合
            ASCII 字母和数字
            连字符、下划线和句点
            感叹号、波浪号、星号、单引号和圆括号
        空格
            编码为 %20
            不编码为 +
        百分号文本
            内建算法使用大写 A 到 F 表示十六进制数字
        异常代理项
            孤立 UTF-16 surrogate 会抛出 URIError
        与 form 编码的区别
            form 编码还会编码部分 encodeURIComponent 不转义的字符
            只替换空格表示不能使两者完全相同
        与 RFC 3986
            encodeURIComponent 也不能未经额外规则就称为 RFC 3986 canonical encoding

    百分号编码层次
        需要区分
            原始字符
            UTF-8 字节
            第一次百分号编码文本
            再次编码百分号后的文本
        双重编码
            百分号自身再次变为百分号编码时形成不同文本
            不能看到两个百分号层次就直接判断错误
        大小写
            百分号后的十六进制字母大小写可以不同
            解码字节可相同，但签名文本字节不同
        大小写来源修正
            任意已有 URL 文本可以包含大写或小写百分号十六进制数字
            URLSearchParams 的 form 序列化和 encodeURIComponent 的内建输出使用大写 A 到 F
            因此需要区分外部原始文本与具体内建编码器的确定输出
        排序位置
            编码前排序与编码后排序可能不同

    重复键
        键值对序列可以包含同名项
        需要记录
            原始相对顺序
            排序是否稳定
            是否按 value 二次排序
            序列化时是否重复输出名称
        信息损失
            把重复键转换为普通对象会丢失至少一个值或组合关系
        结论
            a=1&a=2 与只保留 a=2 不是同一输入

    数组与嵌套结构
        数组需要记录
            元素顺序
            空位
            undefined
            重复值
            索引是否进入名称
        嵌套对象需要记录
            深度遍历顺序
            路径表示
            数组下标表示
            空容器处理
        常见展开形式
            重复名称
            方括号名称
            点路径
            JSON 子文本
            自定义扁平化
        结论
            没有一个通用规则能从嵌套对象推出唯一 Query 文本

    分隔符与拼接
        需要记录
            键值分隔符
            字段分隔符
            前缀
            后缀
            末尾分隔符
            空元素
            转义规则
        常见表示名称
            key=value
            只拼接 key 和 value
            固定字段序列
            长度前缀
        歧义
            字段内容包含分隔符时可能产生解析歧义
            可靠规范需要明确转义或长度边界
        证据要求
            记录实际拼接语句或序列化器输出
        记录修正
            序列化器输出含有或可能含有敏感值时，不保存完整输出
            只保存分隔规则、字段顺序、长度、脱敏占位符和 VALUE-ID

    HTTP method
        HTTP method token 在协议语义上区分大小写
        常见方法通常写成大写，不等于签名输入一定使用大写
        浏览器或客户端库可能规范化常见方法
        需要分别记录
            配置对象中的原始 method
            签名输入中的 method
            Request 对象中的 method
            Network 显示的 method

    Header 名称
        HTTP 字段名在协议语义上不区分大小写
        签名规范仍可能要求
            全部转小写
            保留某个规范名称
            使用固定 signed headers 列表
        同一字段不同大小写不能当作两个不同 HTTP 字段
        但签名前的自定义字符串若保留大小写，会形成不同字节

    Header 值
        需要记录
            首尾空白
            内部连续空白
            多值顺序
            逗号和分隔规则
            是否 trim 或折叠空白
        协议与签名层不同
            HTTP 语义允许的表示不自动等于签名规范化表示
            不同字段的多值合并规则可能不同

    Headers 对象
        名称
            验证后转换为 ASCII 小写
        值
            移除首尾 HTTP whitespace
            内部空白不会被普遍折叠
        append
            添加同名值
        set
            替换第一个同名项并移除其余同名项
        迭代视图
            当前 Fetch 规范使用 sort and combine 视图
            名称按字节序排序
            同名值通常以逗号加空格组合
            set-cookie 保持独立项
        证据限制
            迭代视图不是原始 HTTP 行顺序
            不能证明 HTTP/1、HTTP/2 或 HTTP/3 的线上字节表示
        guard
            受限字段和可写性取决于 Headers guard 与浏览器实现
        guard 的规范基线
            immutable guard 下的修改操作抛出 TypeError
            request guard 遇到 forbidden request-header name 时不执行修改
            response guard 遇到 forbidden response-header name 时不执行修改
            request-no-cors guard 还受 no-CORS-safelisted request-header 规则限制
            none guard 仍需通过名称和值的有效性检查
        证据要求
            仅看到 append 或 set 调用不证明字段已经进入 header list
            需要在调用后读取实际 Headers 状态并记录 guard 相关上下文
            受限字段集合和浏览器行为仍需按目标版本核对

    浏览器自动字段
        浏览器可能在页面脚本之后添加或控制
            Host 或 authority
            Cookie
            Content-Length
            Origin
            Fetch metadata
            连接和传输相关字段
        HttpOnly Cookie
            页面 JavaScript 不能读取其值
            浏览器仍可能按 Cookie 规则自动发送
        签名结论
            页面脚本看不到的最终 Header 不可能仅凭当前 Scope 证明进入了页面签名输入
            协议也可能通过另一份可见元数据表示同一语义

    signed headers
        有些规范明确列出参与签名的 Header 名称
        需要记录
            名称列表顺序
            名称大小写
            值规范化
            多值连接
            缺失字段处理
        列表本身也可能进入签名输入
        不能因为 Header 最终存在就认为它被签名

    Body 总体边界
        可能签名对象
            结构化业务对象
            序列化文本
            UTF-8 字节
            Body 摘要
            multipart 的某些字段
            最终 multipart 正文字节
        必须区分
            签名发生时的表示
            Request 构造后的表示
            Network 解析视图
            传输层字节
        Content-Type
            决定接收方怎样解释正文
            不单独证明签名使用哪一层表示

    JSON Body
        常见链路
            业务对象
            JSON.stringify 返回字符串
            字符串编码为请求正文的 UTF-8 字节
        需要记录
            stringify replacer 与 space
            实际返回字符串
            Content-Type
            签名在 stringify 之前还是之后
        记录修正
            实际返回字符串仅在确认无敏感值时才能完整写入笔记
            否则只记录 JSON 结构、字段路径、字符长度、字节长度和 VALUE-ID
        风险
            先签对象字段再 stringify 与直接签 JSON 文本不是同一规则
            后续重新 stringify 可能改变属性顺序或钩子结果

    URLSearchParams Body
        作为 Body 时通常形成 form-urlencoded 文本
        tuple 顺序和重复名称会进入正文表示
        Content-Type 可能由请求构造过程设置
        需要记录签名使用
            原始业务对象
            URLSearchParams.toString 文本
            最终正文摘要

    FormData
        数据模型
            有序 entry list
            允许重复名称
        append
            追加条目
        set
            替换第一个同名项并删除其余同名项
            如果不存在同名项，则把新条目追加到 entry list 末尾
        multipart 构造
            Fetch 接收 FormData 后由 multipart 编码过程生成正文和 boundary
            Content-Type 包含实际 boundary 参数
        Content-Type 条件修正
            Fetch 的 BodyInit 提取过程会计算带实际 boundary 的媒体类型
            Request 构造只在 Header list 尚无 Content-Type 时自动加入该媒体类型
            调用方已经设置的 Content-Type 会被保留
            因此已有 Content-Type 可能缺少 boundary 或与实际正文 boundary 不一致
        文件条目
            文件名
            内容类型
            文件字节
            条目顺序
            都可能影响最终 multipart 正文
        multipart 字节规则补充
            字符串字段值和字段名涉及规范规定的换行标准化
            字段名与文件名需要经过 multipart name escaping
            CR、LF、双引号等字符会改变最终头部与正文表示
            还需要记录换行形式、名称转义和每个 part 的头部
        证据限制
            FormData 不能直接当作最终字符串
            只签字段值不等于签最终 multipart 正文字节
            一次 boundary 不能当成算法固定常量

    multipart boundary
        boundary 由实现生成
        需要满足不与 part 内容冲突等格式要求
        具体文本与浏览器和版本有关
        手动设置不含实际 boundary 的 multipart Content-Type 可能与正文不匹配
        签名范围
            如果签最终 multipart 字节，boundary 属于输入
            如果只签业务字段，boundary 可能在签名完成后才生成
        必须通过实际调用链确定是哪一种

    字符串 Body
        浏览器请求构造会把字符串形成正文字节
        需要记录
            字符串产生位置
            字符编码
            Content-Type
            签名使用字符串还是编码后的字节
        不能用 String.length 代替正文字节长度

    Blob 与字节视图 Body
        Blob
            包含字节和可选类型信息
            签名可能针对 Blob 字节或其摘要
        ArrayBuffer
            表示整个缓冲区
        TypedArray 或 DataView
            可能只覆盖缓冲区的一段
            byteOffset 和 byteLength 决定视图范围
        关键差异
            传递视图与传递 view.buffer 可能包含不同字节范围

    Body 摘要
        某些签名链先计算正文摘要
        需要分别记录
            正文表示
            摘要算法
            摘要原始字节
            摘要文本编码
            摘要怎样进入外层规范字符串
        不能把正文摘要直接称为最终签名

    timestamp
        来源
            Date.now
            Date 对象
            performance 时间
            服务端下发时间
            状态中缓存时间
            未知
        Date.now
            返回自 Unix epoch 起的毫秒数
            不能只凭位数断言字段来自 Date.now
        需要记录
            生成时机
            秒、毫秒或其他单位
            number 还是 string
            取整、四舍五入或截断
            UTC 绝对时间还是格式化本地时间
            十进制或其他文本表示
        一致性
            传输字段和签名输入可能复用同一个值
            也可能分别读取两次时间
            两次读取的值不能默认相同

    nonce
        可能来源
            CSPRNG
            普通随机函数
            counter
            UUID 类标识
            timestamp 组合
            服务端下发值
            未知
        需要记录
            生成时机
            原始类型
            字节长度
            文本编码
            是否复用同一个变量进入请求和签名
        不能证明
            字段名不能证明随机性
            字段名不能证明唯一性
            字段存在不能证明服务端防重放

    requestId、traceId 与幂等键
        这些字段可能用于
            请求关联
            日志追踪
            幂等控制
            签名输入
            其他业务状态
        不能根据 UUID 外观命名作用
        必须分别记录产生逻辑、签名包含关系和服务端语义证据

    字符到字节
        JavaScript 字符串
            length 以 UTF-16 code unit 计数
            不等于 Unicode code point 数
            不等于 UTF-8 字节数
        TextEncoder
            按 UTF-8 编码
            返回 Uint8Array
            不自动执行 Unicode normalization
        TextEncoder 精确边界
            encode 输入按 USVString 处理
            孤立 UTF-16 surrogate 会先替换为 U+FFFD
            输出不自动添加 UTF-8 BOM
            这与 encodeURIComponent 对孤立 surrogate 抛 URIError 的行为不同
            也与 JSON.stringify 转义孤立 surrogate 的表示不同
        需要记录
            编码前字符串
            字符长度
            码点或规范化状态是否相关
            编码后 byteLength
            换行形式
        记录修正
            编码前字符串受敏感值记录优先规则约束
            敏感内容不写入文件，只记录脱敏结构和字节边界
        结论
            可见文本相同不证明输入字节相同

    TypedArray 字节边界
        需要记录
            buffer
            byteOffset
            byteLength
        视图
            只代表底层 buffer 的指定范围
        整个 buffer
            可能包含视图前后其他字节
        密码学调用
            传入视图与传入整个 buffer 不能默认等价
            在原语入口记录实际参数类型和范围
        多字节元素与字节序
            Uint16Array、Uint32Array 等多字节 TypedArray 写入数值时使用当前 agent 的字节序
            相同数值数组在讨论原始字节时必须记录目标环境字节序
            DataView 的多字节 get 和 set 由 littleEndian 参数控制
            littleEndian 未提供或为 false 时按大端解释
            只记录 byteOffset 和 byteLength 仍不足以还原多字节数值怎样落入字节

    CryptoJS WordArray 边界
        WordArray 常以 32 bit word 保存数据
        sigBytes 表示有效字节数
        words 数组长度不能直接当作有效字节数
        需要记录
            入口值是字符串还是 WordArray
            使用的 encoder
            sigBytes
            是否存在未使用尾部字节
        与 Uint8Array 转换
            字节顺序和有效长度必须由实际转换代码确认

    密码学入口
        需要记录
            实际函数或 Web Crypto 操作
            算法名称
            算法参数
            输入类型
            输入 byteLength
            密钥类型与用途
            当前调用帧和源码位置
        普通哈希
            没有 secret key 参数
        HMAC
            使用共享秘密或相应 CryptoKey
        数字签名
            使用 private key
            对应 public key 用于验证
        结论
            函数名不能代替运行时参数证据

    密钥证据边界
        允许记录
            secret、private、public 或 derived 类型
            key length
            CryptoKey.algorithm
            CryptoKey.usages
            extractable 状态
            来源类别
            脱敏 key id
        禁止记录
            真实密钥字节
            可导出的秘密文本
            Token、Cookie 或密码值
        名称限制
            key 变量可能实际是 key id、salt、nonce 或不透明句柄
            必须依据使用位置分类

    普通哈希中的秘密拼接
        可能结构
            secret 作为消息前缀
            secret 作为消息后缀
            secret 与规范字符串之间使用分隔符
            secret 先经过编码或派生再参与普通消息字节
        密码学分类
            如果代码只是把这些字节交给普通 Hash，它仍属于普通哈希调用
            secret 参与不自动把机制变成 HMAC
            只有标准 HMAC 构造或相应 HMAC API 才记录为 HMAC
        需要记录
            secret 位于前部还是后部
            分隔符和编码
            secret 的来源类别与字节长度
            最终完整 Hash 输入的 byteLength
        禁止记录
            secret 的真实文本或字节
            可复用的拼接结果
        浏览器边界
            静态下发到浏览器的长期值不能被视为服务端独占秘密
            发现该值不构成提取、复用或传播授权

    多层密码学处理
        可能结构
            Body 先计算摘要
            摘要加入规范字符串
            规范字符串再计算 HMAC 或数字签名
            输出再加入版本和 key id
        每一层单独记录
            输入
            输出
            字节边界
            算法参数
            密钥模型
            封装
        不能把所有中间摘要统一称为签名

    原语输出
        需要记录
            原始输出类型
            原始字节长度
            是否 Promise 异步返回
            是否复制为新缓冲区
        不在原语边界完成的步骤
            Hex 转换
            Base64 转换
            Base64url 转换
            截断
            大小写
            前缀和版本拼接

    Hex 输出
        一个字节通常表示为两个 Hex 字符
        需要记录
            小写或大写
            是否固定宽度
            是否有前缀
            截断发生在字节还是字符层
        大小写不同
            解码字节可以相同
            文本签名字段仍然不同

    Base64 与 Base64url
        Base64url
            使用连字符和下划线替代 Base64 中的部分字符
        padding

            字符表
            等号处理
            换行处理
        Query 放置

    截断
        可能对象

            Hex 文本
            Base64 文本
            整个封装字段
        方向
            前部
            后部
            中间指定范围
        单位
            bit
            byte
            character
        结论
            相同可见长度不能证明截断发生在同一层

    输出放置
        可能位置
            Query
            Header
            Cookie
            Body 顶层字段
            Body 嵌套字段

    包装器与拦截器
        请求包装器可能

            生成 timestamp 或 nonce
            计算签名
            添加 Header
        拦截器可能
            在签名前修改请求
            在签名后修改请求
            异步取得状态后继续处理
        版本边界
            拦截器执行顺序属于库和版本相关事实
            不能根据其他库或旧版本经验推断
        记录要求
            注册位置
            实际执行顺序
            同步调用栈
            异步来源
            每层输入与输出

    签名后的请求变化
        需要检查
            method 是否改变
            path 或 Query 是否改变
            Header 是否增加、删除或规范化
            Body 是否重新序列化
            Content-Type 是否改变
            浏览器是否生成 boundary
        影响
            如果签名覆盖的是变化前表示，服务端必须按同一协议理解
            如果某字段在签名后加入，不能自动认为它未被间接包含

    Worker、Service Worker 与 WASM 边界
        本阶段只记录
            数据进入边界
            数据离开边界
            消息类型和长度
            可见调用位置
            未知内部处理
        不进入内部实现
            Worker 与 Service Worker 的运行时追踪在第 7 阶段
            WASM 和构建产物阅读在后续阶段
        结论
            边界不可见时只能形成部分规范

    A/A 重复观察
        目的
            区分自然动态字段和稳定业务字段
        不表示
            timestamp 必须相同
            nonce 必须相同
            会话状态必须完全不变
        需要记录
            页面状态
            时间
            会话
            重试次数
            缓存
            构建
        解释
            同一公开操作的输出变化只说明存在动态输入或状态候选

    A/B 单变量观察
        名称精确含义
            “单变量”表示计划只改变一个公开业务变量
            它不证明两次执行中实际只有一个状态发生变化
        限定
            只使用页面正常提供的公开输入变化
            不修改请求
            不重放请求
        方法
            在每个流水线阶段寻找最早分歧点
            比较字段来源、规范化文本、最终字节和输出
        不能证明
            一次同步变化不能证明因果关系
            只比较最终 signature 不能确定哪个字段进入了输入
        直接证据
            仍需要同一次执行中的参数、返回值和原语边界

    A/B 会话记录模板
        A 侧

        B 侧

            A 与 B 两次独立会话中首次出现不同表示的已记录阶段

        限制
            两次会话不属于同一次调用链

        记录
            STAGE-ID

            输出类型与长度
            已知变化变量
            尚未控制变量

    调试器干扰
        暂停会改变
            timestamp 与发送时间差
            Token 有效期
            nonce 或会话状态
            Promise 和定时器顺序
            请求超时
        记录要求
            暂停开始和恢复时间

            请求发送发生在暂停前还是之后
        结论
            暂停后失败不能直接解释为签名规则错误

    观察与证明边界
        字段随公开输入变化
            最多支持相关性
            不能证明字段被签名
        相同条件下输出稳定
            支持确定性候选
            不能证明哈希或 HMAC
        长度、Hex 或 Base64 外观
            支持编码和算法候选
            不能证明具体算法
        函数名包含 sign 或 hash
            支持静态候选
            不能证明实际执行语义
        断点命中候选函数
            证明当前路径执行了该函数
            不能证明其输出进入目标请求
        原语调用前观察完整 byte 参数
            证明当前调用的输入字节
            不能单独证明输出进入目标字段
        观察算法对象和参数
            证明当前调用的算法配置
            不能证明服务端使用同一规则
        原语输出沿转换进入请求对象
            证明 JavaScript 请求表示中的输出封装
            不能证明传输层最终原始字节
        请求成功
            证明整体请求得到某响应
            不能证明服务端具体校验字段或算法

    签名逻辑追踪顺序
        第一步：固定会话
            关联 CAPTURE-ID、DEBUG-SESSION-ID 和 BUILD-ID
        第二步：确定最终字段
            记录位置、文本长度、外层编码和脱敏摘要
        第三步：定位发送边界
            记录 method、path、headers 和 body 的 JavaScript 表示
        第四步：追踪字段写入
            找到最终字段的赋值和输出转换
        第五步：定位原语出口
            记录原始输出类型和字节长度
        第六步：定位原语入口
            记录算法、参数、输入 byte range 和密钥模型
        第七步：追踪最终输入字节
            记录字符编码前文本和编码后字节
        第八步：拆分规范化阶段
            字段选择、排序、空值、重复键、拼接和序列化分别编号
        第九步：追踪字段来源
            为每个 FIELD-ID 建立来源、条件和数据流证据
        第十步：检查签名后变化
            记录包装器、拦截器和浏览器继续处理的内容
        第十一步：形成四条证明轴
            缺少任何一轴则标记部分还原

            大小写：<RULE-OR-NOT-APPLICABLE>

        请求后续处理
            签名后 method 变化：<CHANGE-OR-NONE-OR-UNKNOWN>

            签名后 Header 变化：<CHANGE-OR-NONE-OR-UNKNOWN>
            签名后 Body 变化：<CHANGE-OR-NONE-OR-UNKNOWN>
            浏览器生成内容：<BOUNDARY-HEADERS-OTHER>
        结论
            四轴状态：<INPUT-ALGORITHM-KEY-OUTPUT-STATUS>

            矛盾证据：<CONTRADICTIONS>
            未知：<UNKNOWNS>

        完成状态字段修正
            上面的 ESTABLISHED 和 VERIFIED 是单项结论证据等级，不应用作整份规范的统一等级
            上面的旧占位字段不再用于最终记录
            整体覆盖状态只使用 PARTIAL 或 COMPLETE
            整体覆盖状态：<PARTIAL-COMPLETE>
            整体 COMPLETE 不表示整条规范统一 VERIFIED
        旧占位符处理
            “完成状态：<PARTIAL-ESTABLISHED-VERIFIED>”仅作为被纠正的历史占位符保留在教程中
            创建实际记录时不得复制、填写或解析该旧占位符
            实际记录只使用下面的最终有效结论 schema

    服务端未知边界

    必须保留的替代解释
        候选字段由服务端预先下发，页面只转发
        候选字段是缓存值、会话标识、幂等键或普通随机值
        候选值是摘要、校验和、MAC、数字签名或密文的一部分
        输出变化来自时间、随机数、会话或环境
        候选函数只是包装器或调度器
        原语输出只是中间值，后续还有二次计算
        key 名称实际表示 key id、salt、nonce、公钥或句柄
        CryptoKey 用于 verify、encrypt 或 derive，而不是 sign
        Source Map 与部署字节不匹配
        当前观察到未执行分支或旧构建
        JSON、URL、Headers 或表单序列化使用隐式默认行为
        页面签名后请求又被客户端库、Service Worker 或浏览器修改
        同名字段在不同请求位置具有不同语义
        Network 解析视图不等于签名文本或传输字节
        输出经过截断、版本前缀、拼接或编码后才成为最终字段
        异步状态在规范化与发送之间发生变化

    常见错误
        按 sign 字段名确认数字签名
            问题
                字段名不包含密钥关系和算法证据
            修正
                按第 4 阶段的原语分类记录
        把对象键概括为全部插入顺序
            问题
                数组索引键优先按数值顺序
            修正
                记录实际枚举 API 和键类别
        把默认 sort 当作数字排序
            问题
                默认按字符串的 UTF-16 code unit 比较
            修正
                记录比较器和比较单位
        把 JSON.stringify 当作 canonical JSON
            问题
                属性顺序、钩子、空值和数字规则仍影响文本
            修正
                记录实际字符串和调用参数
        把业务对象当作签名输入字节
            问题
                中间还有序列化和字符编码
            修正
                一直追踪到原语实际 BufferSource 或字节输入
        丢失重复 Query 键
            问题
                普通对象不能无损表示重复项
            修正
                使用有序 tuple 证据记录
        把 encodeURIComponent 当作 form 编码
            问题
                空格和不转义字符集合不同
            修正
                记录实际编码 API 和输出
        把解析后的 Query 当作原始签名文本
            问题
                解码会丢失编码选择和百分号大小写
            修正
                同时记录原始文本和解析结构
        把 Headers 迭代顺序当作线上顺序
            问题
                Headers 使用规范化与 sort-and-combine 视图
            修正
                只把它记录为 API 视图
        把 FormData 当作最终字符串
            问题
                multipart 正文和 boundary 由请求构造生成
            修正
                确认签名发生在字段层还是最终字节层
        把字符长度当作字节长度
            问题
                JavaScript 字符串以 UTF-16 code unit 计数
            修正
                在 TextEncoder 或原语入口记录 byteLength
        传入 view.buffer 后仍按视图范围记录
            问题
                整个 buffer 可能包含视图之外字节
            修正
                记录实际参数与 byteOffset、byteLength
        把中间 Body 摘要当作最终签名
            问题
                外层可能还有 HMAC 或数字签名
            修正
                每层建立独立 STAGE-ID
        跨两次执行拼接调用链
            问题
                动态值和分支可能不同
            修正
                每次会话独立记录，通过阶段编号比较
        用请求成功证明服务端实现
            问题
                成功响应不显示服务端内部验证路径
            修正
                服务端行为保持未知，除非有独立直接证据
        为验证猜想修改或重放请求
            问题
                超出本阶段被动观察范围
            修正
                只使用页面正常操作与只读断点

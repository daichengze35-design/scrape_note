Web API 加密逻辑分析
    第 9 阶段：分析报告与验证

    学习目标
        能把第 0 至第 8 阶段的观察、证据、结论、未知和边界组织成一份可复核报告
        能区分报告结构完整、分析覆盖完整、单项结论等级和验证检查结果
        能为逻辑报告和每个不可变修订建立独立身份
        能把每个分析问题映射到必需 CONCLUSION-ID、EVIDENCE-ID 和验证检查
        能验证 ID 唯一性、引用完整性、范围一致性、证据充分性和版本身份
        能说明重复观察、独立执行、独立复核和服务端验证之间的区别
        能为每个结论记录支持证据、反证、替代解释、证伪条件和适用范围
        能在构建、部署、浏览器、上下文或协议版本变化时判断旧结论是否仍适用
        能记录 FAIL、INCONCLUSIVE、NOT-RUN 和 UNKNOWN，而不删除不利证据
        能形成不包含真实凭证、密钥、许可证、媒体内容或未脱敏业务数据的共享副本
        能建立修订、复核、撤回和 supersede 关系
        能判断一份报告是否达到可交付状态，但不把整份报告统一标为 VERIFIED

    本阶段不学习
        不提供真实站点、靶场、练习或实战任务
        不重新抓取、重放、修改或构造任何请求
        不为验证报告而刷新页面、重新连接长连接或触发额外媒体请求
        不测试服务端签名错误分支、权限分支、风控分支或重放防护
        不绕过认证、授权、验证码、频率限制、地域限制、付费限制或 DRM
        不读取、保存或共享 Cookie、Token、密码、密钥、许可证、initData、key ID 或媒体内容
        不生成可用于访问真实资源的请求样例、Header、查询参数或签名值
        不把报告模板当作服务端接口复现模板
        不用报告审批代替技术证据
        不进入新的实战阶段

    skill 使用边界
        hads
            只采用事实、上下文、已验证错误和未知项分开的组织原则
            不使用 Markdown HADS 标签
            不改变 note 文件夹的纯文本四空格层级
            不把模板规则冒充项目事实

    分析报告的定义
        分析
            根据授权范围内的证据回答明确问题
        报告
            把范围、方法、证据、结论、未知、冲突和限制组织成可复核记录
        验证
            按预先写明的条件检查一项结论或报告属性是否得到支持
        校验
            对格式、字段、ID、引用、状态或确定性规则执行检查
        复现
            在新执行身份下按已记录条件再次观察同一行为
        独立复核
            由没有形成原结论的人检查证据与推理
        发布
            把一个不可变报告修订标记为可交付
        重点
            报告是有范围和版本的技术记录
            报告不是脱离 BUILD-ID、时间和环境的永久事实

    六个不能合并的状态
        文档结构状态
            必需章节和字段是否存在
        引用完整性状态
            每个 ID 引用是否能找到唯一目标
        分析覆盖状态
            必需问题和必需结论是否达到覆盖要求
        单项证据等级
            每个 CONCLUSION-ID 的 UNKNOWN、CANDIDATE、OBSERVED、ESTABLISHED 或 VERIFIED
        验证检查结果
            每个 VERIFICATION-CHECK-ID 的执行结果
        报告生命周期状态
            当前修订处于草稿、复核、可交付、被替代或撤回中的哪一种状态
        禁止
            不把任一状态复制为其他状态
            不把所有状态压缩成一个置信度

    正式证据等级
        UNKNOWN
            当前证据不能支持具体分类或关系
        CANDIDATE
            只有名称、外观、时间邻近、静态文本或其他弱线索
        OBSERVED
            在明确执行中直接观察到对象、值、调用、事件、请求或状态
        ESTABLISHED
            已建立完整边界、来源、上下文、条件和相邻数据流关系
        VERIFIED
            在 ESTABLISHED 基础上又有当前规范、服务端验证实现或独立已知结果验证
        聚合限制
            每个 CONCLUSION-ID 独立评级
            VERIFIED 不能从一个结论传播到另一个结论
            整份报告没有统一 VERIFIED 等级

    正式结论来源
        DIRECT-OBSERVATION
            当前授权执行中的直接观察
        STANDARD
            已绑定固定版本或核验快照的规范事实
        BUILD-METADATA
            当前构建、部署、Source Map 或生成物元数据
        INFERENCE
            由其他证据推导但不是直接观察的结论
        规则
            CONCLUSION-SOURCE 与证据等级分别记录
            INFERENCE 不是第六级证据等级
            STANDARD 必须引用规范版本或 SPEC-CHECK-ID

    正式验证结果
        NOT-RUN
            检查尚未执行
        PASS
            实际结果满足当前检查的明确判定条件
        FAIL
            实际结果违反当前检查的明确判定条件
        INCONCLUSIVE
            已执行检查，但证据不足、结果冲突或环境不满足判定条件
        NOT-APPLICABLE
            检查在当前报告范围内不适用
        规则
            PASS 只适用于一个 VERIFICATION-CHECK-ID
            PASS 不提升 CONCLUSION-ID 的证据等级
            FAIL 不允许被删除或改写为 NOT-RUN
            INCONCLUSIVE 不等于 PASS
            NOT-APPLICABLE 必须写明不适用依据

    正式报告生命周期
        DRAFT
            内容仍可编辑
        IN-REVIEW
            已冻结当前候选内容并等待复核
        REVIEWED
            必需复核已经完成，但不表示所有结论 VERIFIED
        RELEASED
            当前修订符合既定交付门禁
        SUPERSEDED
            已被一个明确的新修订替代
        WITHDRAWN
            因范围、证据、敏感信息或重大错误不再作为有效交付版本
        规则
            生命周期是文档治理状态
            生命周期不是技术证据等级

    正式报告覆盖状态
        PARTIAL
            至少一个必需问题、必需结论、核心范围或关键引用未满足
        COMPLETE
            所有必需问题均有结论记录
            所有完整分析必需结论至少达到 ESTABLISHED
            没有核心未知和未解释矛盾
        规则
            沿用第 5 阶段整体覆盖状态
            COMPLETE 不表示所有结论 VERIFIED
            报告结构完整与分析覆盖 COMPLETE 分开记录

    本章新增本地 ID
        REPORT-ID
            表示一份逻辑分析报告
        REPORT-REVISION-ID
            表示 REPORT-ID 的一个不可变内容修订
        ANALYSIS-QUESTION-ID
            表示报告需要回答的一个明确问题
        EVIDENCE-MANIFEST-ID
            表示一个报告修订引用的证据清单
        VERIFICATION-PLAN-ID
            表示针对一个报告修订的验证计划
        VERIFICATION-CHECK-ID
            表示一个具有明确输入、规则和判定条件的检查
        VERIFICATION-RUN-ID
            表示一次实际执行验证计划的记录
        REVIEW-ID
            表示一次人工独立复核记录
        REDACTION-PROFILE-ID
            表示一个报告修订采用的脱敏规则集
        OPEN-ITEM-ID
            表示一个尚未解决的未知、冲突、缺失或后续检查项
        所有新增 ID
            都是分析者本地编号
            都不得使用真实账号、域名、Token、sessionId 或业务主键

    禁止重新定义的正式 ID
        FRAME-ID
            继续只表示 DevTools 调用帧
        DOCUMENT-FRAME-ID
            表示具体文档实例
        REQUEST-OBSERVED-ID
            表示一次浏览器请求或请求尝试观察
        API-OPERATION-REF
            指向一个已有正式 API 操作身份
        WS-MESSAGE-ID
            表示浏览器 WebSocket API 交付的一条消息
        GRPC-WEB-RECORD-ID
            表示 gRPC-Web data 或 trailers 记录
        SEGMENT-REF-ID
            表示 manifest 中的声明引用
        MEDIA-SEGMENT-ID
            表示运行时已识别的媒体 segment
        规则
            第 9 阶段不创建这些实体的第二套 ID

    不得继续使用的失效短名
        ASSET-ID
            使用 GENERATED-ASSET-ID
        CHUNK-ID
            使用 CHUNK-OBSERVED-ID
        MODULE-ID
            使用 MODULE-LOCAL-ID 或 MODULE-EVAL-ID
        OBJECT-LOCAL-ID
            使用具体对象类型的正式本地 ID
        REQUEST-ID
            使用 REQUEST-OBSERVED-ID
        OPERATION-ID
            使用 API-OPERATION-REF
        PROTOCOL-MESSAGE-ID
            WebSocket 使用 WS-MESSAGE-ID
            SSE 使用 SSE-EVENT-ID
            应用记录使用 APPLICATION-RECORD-ID
        GRPC-WEB-ENVELOPE-ID
            使用 GRPC-WEB-RECORD-ID
        GRPC-WEB-CALL-ID
            使用 PROTOCOL-TRACE-ID 与 REQUEST-OBSERVED-ID 表示调用范围
        规则
            旧短名可以在历史说明中出现
            新报告不得为旧短名分配值

    REPORT-ID 与 REPORT-REVISION-ID
        REPORT-ID
            逻辑身份在多个修订间保持不变
        REPORT-REVISION-ID
            每次内容变化建立新身份
        不可变条件
            修订进入 IN-REVIEW 后不原地覆盖正文
            发现错误时建立新修订
            旧修订保留原状态和原检查结果
        supersede
            新修订可以声明替代一个旧修订
            关系必须单向且无循环
            被替代修订仍保留
        不能推断
            文件名相同表示同一修订
            修改时间相同表示内容相同
            内容摘要相同表示报告来源可信

    报告范围
        授权范围
            谁授权
            授权对象
            允许的账号或测试身份类别
            允许的环境
            允许的时间窗口
            允许的观察方法
        技术范围
            BUILD-ID
            DEPLOYMENT-ID
            浏览器与完整版本
            操作系统
            页面语言、浏览器语言和时区
            请求类别、执行分支和页面操作
            CONTEXT-ID 范围
        明确排除
            服务端内部实现
            未观察上下文
            未授权账号和环境
            未发生的协议路径
            未取得版本身份的构建
        原则
            报告不能通过推断扩大授权范围
            超出范围的证据不得进入报告

    分析问题
        定义
            一个可以由明确证据支持、反驳或保持未知的问题
        合格问题
            对象明确
            时间和版本范围明确
            结论单位明确
            可列出必需证据
            可列出证伪条件
        不合格问题
            这个接口是怎样加密的
            这个字段是不是安全的
            为什么服务端接受请求
            这个播放器怎样解密
        不合格原因
            对象、层次、范围或验证方不明确

    报告结构
        报告身份
            REPORT-ID 和 REPORT-REVISION-ID
        摘要
            范围、核心结论、核心未知和验证状态
        授权与范围
            允许和排除的对象、时间、环境与方法
        分析问题
            ANALYSIS-QUESTION-ID 列表
        环境与版本
            构建、部署、浏览器、上下文、执行和规范身份
        方法
            只记录实际采用的被动观察方法
        证据清单
            EVIDENCE-MANIFEST-ID
        单项结论
            CONCLUSION-ID 表
        跨层映射
            已有 RUNTIME-MAP-ID、PROTOCOL-MAP-ID 和 MEDIA-MAP-ID
        未知、冲突与替代解释
            OPEN-ITEM-ID 和 EVIDENCE-CONFLICT-ID
        验证计划与结果
            VERIFICATION-PLAN-ID、VERIFICATION-CHECK-ID 和 VERIFICATION-RUN-ID
        独立复核
            REVIEW-ID
        脱敏与共享
            REDACTION-PROFILE-ID 和检查结果
        限制
            当前证据不能回答的内容
        修订记录
            前后修订和变更原因

    报告摘要边界
        可以写
            当前报告回答了哪些问题
            哪些必需结论达到 ESTABLISHED 或 VERIFIED
            哪些核心未知仍存在
            当前分析覆盖状态
            验证检查的 PASS、FAIL、INCONCLUSIVE 和 NOT-RUN 数量
        不能写
            整份报告已经 VERIFIED
            服务端一定按客户端逻辑验证
            所有环境都适用
            没有观察到就不存在
            REVIEWED 等于结论正确
        原则
            摘要中的每个技术陈述必须引用 CONCLUSION-ID

    方法记录
        只记录实际执行的方法
            Network 被动观察
            Sources 断点和只读暂停观察
            构建与 Source Map 阅读
            原页面正常执行的 runtime 追踪
            原页面正常执行的协议和媒体状态观察
        每种方法记录
            工具和版本
            设置
            开始和结束时间
            对执行的可能扰动
            可见边界
            不可见边界
        禁止写成
            已观察服务端验证
            已观察 TLS packet
            已观察 CDM 内部密钥
            已观察浏览器未公开的协议 frame

    脱敏的定义
        目标
            移除不需要共享的秘密、个人数据和可访问资源标识
        脱敏副本
            与原始观察不是同一字节对象
        允许保留
            类型
            长度和明确单位
            枚举状态
            字段类别

    结果对结论等级的影响

        FAIL

        INCONCLUSIVE

            不提升等级
        ERROR
            修复工具或输入后重跑

        ABORTED
            记录停止条件
            未执行部分保持 NOT-RUN
        NOT-APPLICABLE
            不进入通过率分母
            必须保存范围依据

    报告一致性检查顺序
        第一步：固定目标字节
            确认 REPORT-REVISION-ID 和内容摘要
        第二步：检查范围
            授权、时间、环境、构建和 cutoff
        第三步：检查格式
            按文件格式配置验证编码和排版
        第四步：检查 ID
            唯一性、存在性、类型和图无循环
        第五步：检查证据 manifest
            entry、范围、脱敏和 cutoff
        第六步：检查问题覆盖
            每个必需问题和关闭条件
        第七步：检查单项结论
            原子性、来源、等级、条件和范围
        第八步：检查追踪矩阵
            问题、结论、证据和验证的完整链
        第九步：检查冲突与未知
            双方证据、降级、OPEN-ITEM-ID
        第十步：检查验证结果
            结果状态、计划偏差和错误
        第十一步：检查漂移与回归
            当前有效性和基线可比性
        第十二步：检查独立复核
            目标摘要、访问范围和处置
        第十三步：检查脱敏
            REDACTION-PROFILE-ID 和分享包
        第十四步：判定发布门禁
            不计分、不补偿

    检查顺序的原因边界
        先固定 revision
            防止检查过程中目标内容变化
        先检查范围
            防止对超范围内容继续处理
        先检查引用再检查语义
            缺失引用时无法确定结论依据
        最后判定发布
            发布依赖全部适用门禁结果

    必须保留的替代解释
        数据外观
            高熵可能来自压缩、媒体编码、容器或加密
            Base64、Hex 和 URL 编码不是加密证明
        字段变化
            可能来自时间、随机、会话、存储、响应或环境
        请求变化
            可能来自包装器、拦截器、Service Worker 或浏览器自动处理
        代码位置
            可能受构建、内联、复制、Source Map 和动态加载影响
        调用关系
            时间邻近不等于同步或异步因果边
        协议
            API message、stream chunk、record 和 wire frame 不是同一边界
        HTTP
            status、业务状态和协议状态分别记录
        Range
            byte range、segment 和 buffered time range 不同
        manifest
            声明引用不等于实际请求
        MSE
            append 完成不等于 decode 或 render 成功
        EME
            配置成功不等于许可证、key 可用或播放授权成功
        服务端
            客户端生成逻辑不等于服务端验证逻辑
        报告
            复核通过不等于所有技术结论正确

    常见错误
        给整份报告统一 VERIFIED
            问题
                VERIFIED 只属于单项 CONCLUSION-ID
            修正
                报告记录 PARTIAL 或 COMPLETE 和门禁结果

        使用统一置信分数
            问题
                分数会掩盖不同结论和不同门禁的失败
            修正
                每项独立评级和判定

        把 REPORT-ID 当作修订
            问题
                逻辑报告可以有多个不可变修订
            修正
                同时记录 REPORT-ID 和 REPORT-REVISION-ID

        用文件名代替 REPORT-REVISION-ID
            问题
                文件名可以重复或被改写
            修正
                分配正式修订身份并记录摘要边界

        修改正式 revision
            问题
                旧检查和复核不再对应相同内容
            修正
                任何变化建立新 REPORT-REVISION-ID

        把 DRAFT 当作可变正式 revision
            问题
                生命周期不改变不可变规则
            修正
                临时编辑缓冲区不分配正式 revision

        混合 parent 与 supersede
            问题
                派生关系不自动表示替代
            修正
                两种关系分别记录

        覆盖 current pointer 历史
            问题
                无法还原何时推荐过哪个修订
            修正
                使用追加式索引事件

        同一 CONCLUSION-ID 改变语义
            问题
                不同修订无法比较同一身份
            修正
                新建 CONCLUSION-ID 并记录 supersede

        只有等级变化就新建结论
            问题
                丢失同一结论的证据演进
            修正
                文本和范围不变时沿用 CONCLUSION-ID

        一个结论包含多个独立断言
            问题
                不能独立评级和证伪
            修正
                拆分为原子 CONCLUSION-ID

        把 INFERENCE 当成最高等级
            问题
                INFERENCE 是来源，不是等级
            修正
                同时记录来源和五级证据等级

        用 STANDARD 证明当前实现
            问题
                规范事实不证明页面实际执行
            修正
                补充当前运行证据

        用 URL 200 证明 revision
            问题
                可达性不固定动态文档内容
            修正
                记录 revision、commit 或 UNKNOWN

        用成功响应证明服务端验证逻辑
            问题
                成功响应不显示内部验证路径
            修正
                服务端规则保持 UNKNOWN 或使用授权实现证据

        缺少范围字段却写 OBSERVED
            问题
                无法绑定构建、执行和上下文
            修正
                降为 CANDIDATE 并补齐范围

        跨 EXECUTION-ID 拼接具体值
            问题
                动态状态和对象身份不同
            修正
                每个执行独立记录

        跨 BUILD-ID 沿用行列号
            问题
                生成物和 Source Map 可能变化
            修正
                重新绑定构建身份

        把截图、转录和 Network 行当独立证据
            问题
                可能来自同一底层观察
            修正
                记录 SAME-OBSERVATION 依赖

        把 Pretty Print 当作原始字节
            问题
                显示变换可能改变排版
            修正
                引用原始证据并记录派生视图

        把搜索未命中写成不存在
            问题
                搜索范围和文本表示有限
            修正
                建立限定负面观察

        把断点未命中写成函数未执行过
            问题
                断点位置、上下文和附加时机可能不正确
            修正
                记录检测能力和盲区

        把 UNKNOWN 写成 false
            问题
                未知不表示否定
            修正
                保留 UNKNOWN 和形成原因

        混合 NOT-OBSERVED 与 NOT-EXPOSED
            问题
                一个表示当前未观察
                一个表示接口不公开
            修正
                按可见边界分别记录

        混合 NOT-READ 与 NOT-STORED
            问题
                未读取和读取后未保存是不同处理状态
            修正
                使用精确状态

        用 NOT-APPLICABLE 掩盖缺失证据
            问题
                不适用必须有范围依据
            修正
                缺证写 NOT-RUN 或 INCONCLUSIVE

        删除冲突证据
            问题
                报告无法解释结论降级
            修正
                保留双方并建立 EVIDENCE-CONFLICT-ID

        根据期望选择冲突一方
            问题
                没有解决依据
            修正
                保持 UNKNOWN 或补充授权证据

        使用旧 ID 短名
            问题
                破坏跨阶段引用类型
            修正
                使用正式完整 ID

        把联合占位符当作 ID
            问题
                一个字段引用了不存在的身份
            修正
                选择一个具体正式 ID

        把 PASS 当作 VERIFIED
            问题
                PASS 只适用于当前检查规则
            修正
                单独评估结论必要条件

        把 ERROR 当作 FAIL
            问题
                工具失败不是目标行为失败
            修正
                修复运行条件后新建 VERIFICATION-RUN-ID

    前置条件到检查结果真值表
        检查开始前 PASS
            允许执行检查
        检查开始前 FAIL
            检查结果 NOT-RUN
            GATE-CONTRIBUTION NOT-RUN
        检查开始前 INCONCLUSIVE
            检查结果 INCONCLUSIVE
            GATE-CONTRIBUTION INCONCLUSIVE
        检查开始前 ERROR
            检查结果 ERROR
            GATE-CONTRIBUTION ERROR
        检查开始后条件由 PASS 变为 FAIL
            命中停止条件
            检查结果 ABORTED
            GATE-CONTRIBUTION ABORTED
        检查开始后条件无法判定
            命中停止条件
            检查结果 ABORTED
            GATE-CONTRIBUTION ABORTED
        检查开始后发生条件求值工具错误
            检查结果 ERROR
            GATE-CONTRIBUTION ERROR
        规则
            检查已经开始后不得写 NOT-RUN
            前置条件阻断时不形成技术领域 outcome
            前置条件结果和检查结果都保留
            不得按运行者偏好在多个状态间选择

    总体运行状态真值
        COMPLETED
            所有已开始检查都有终态结果
            没有 run-level ABORTED
            没有阻止结果落表的 run-level ERROR
            单项 FAIL 或 INCONCLUSIVE 不妨碍总体状态为 COMPLETED
        ABORTED
            运行开始后命中全局停止条件
            未完成检查记录 ABORTED
        ERROR
            工具、输入或账本错误使运行无法形成完整终态记录
        规则
            总体 COMPLETED 不表示每个检查 PASS
            总体运行状态不覆盖单项 CHECK-RESULT

    NOT-APPLICABLE 依据校验谱系
        原始检查运行
            保留原 CHECK-RESULT NOT-APPLICABLE
            不改写已经冻结的 VERIFICATION-RUN-ID
        依据校验
            使用独立 VERIFICATION-CHECK-ID
            使用独立 VERIFICATION-RUN-ID
            绑定原始检查、原始运行和 NOT-APPLICABLE 依据
        原始检查为 NOT-APPLICABLE 时
            依据校验 check 自动成为 REQUIRED
            两个 check 都进入门禁固定输入集合
        依据校验 PASS
            原始 NOT-APPLICABLE 可以按合法 N/A 聚合
        依据校验 FAIL
            依据校验 GATE-CONTRIBUTION FAIL
            原始结果仍保留 NOT-APPLICABLE
        依据校验 INCONCLUSIVE
            依据校验 GATE-CONTRIBUTION INCONCLUSIVE
        依据校验 ERROR
            依据校验 GATE-CONTRIBUTION ERROR
        依据校验 NOT-RUN
            依据校验 GATE-CONTRIBUTION NOT-RUN
        规则
            前文“改判”为 FAIL 或 INCONCLUSIVE 只表示聚合被依据校验阻断
            不表示改写原始 CHECK-RESULT
            需要纠正原始结果时建立新的 VERIFICATION-RUN-ID

    OTHER 领域门禁边界
        检查类别 OTHER
            可以用于非发布诊断
            是否发布门禁必须为 NO
        领域 OTHER
            可以记录非门禁 outcome
            GATE-CONTRIBUTION 使用 NOT-AVAILABLE
            不进入发布门禁聚合
        新领域需要进入发布门禁时
            先在新文档 revision 中固定领域 outcome 枚举
            固定每个 outcome 到 GATE-CONTRIBUTION 的映射
            建立新的 VERIFICATION-PLAN-ID 和 VERIFICATION-CHECK-ID
        禁止
            由单个 plan 临时定义 OTHER 的门禁映射
            把未知领域 outcome 按名称猜测为 PASS 或 FAIL

    重跑输入身份最终规则
        可以沿用同一 VERIFICATION-CHECK-ID
            所有输入正式 ID 完全相同

    条件门禁 NOT-TRIGGERED 终态
        门禁结果新增
            NOT-TRIGGERED
        适用条件
            门禁必需性为 CONDITIONAL
            所有固定 CONDITIONAL check 的触发判定均为 FALSE
            没有触发判定 INCONCLUSIVE
            没有触发判定 ERROR
        结果
            门禁 NOT-TRIGGERED
            不要求 CHECK-RESULT
            不创建伪造 NOT-APPLICABLE 结果
            不受实质 PASS 非空要求约束
        混合触发
            至少一个 TRUE 时门禁进入正常聚合
            FALSE 的 check 从适用集合排除
        发布判定
            NOT-TRIGGERED 只允许满足未触发的 CONDITIONAL 门禁
            REQUIRED 门禁不得使用 NOT-TRIGGERED
            已触发 CONDITIONAL 门禁必须 PASS

    门禁逐项表的触发 FALSE 行

        触发判定：FALSE

        选用 CHECK-RESULT：NOT-AVAILABLE

        GATE-CONTRIBUTION：NOT-AVAILABLE
        选用输入数量：0
        规则

    门禁检查用途分类
        VERIFICATION-CHECK-ID 增加
            PASS-COUNT-ROLE：<SUBSTANTIVE-META-VALIDATION>
        SUBSTANTIVE
            PASS 可以满足门禁实质 PASS 非空要求
        META-VALIDATION
            PASS 只证明元数据、排除依据或聚合配置有效
            PASS 不计入门禁实质 PASS 非空要求
            FAIL、ERROR、ABORTED、INCONCLUSIVE 和 NOT-RUN 正常阻断门禁

    NOT-APPLICABLE 依据检查冻结时点
        固定计划时
            为每个可能产生 NOT-APPLICABLE 的原始 check 预先建立依据校验 VERIFICATION-CHECK-ID
            依据校验 check 属于同一 VERIFICATION-PLAN-ID
            依据校验 check 使用同一 TARGET-RELEASE-TYPE
            依据校验 check 的必需性为 CONDITIONAL
            依据校验 check 的 PASS-COUNT-ROLE 为 META-VALIDATION
            触发规则固定为原始 check 的选用结果等于 NOT-APPLICABLE
        运行后
            不得追加依据校验 check
            原始结果为 NOT-APPLICABLE 时触发判定 TRUE
            原始结果不是 NOT-APPLICABLE 时触发判定 FALSE
        聚合
            依据校验 PASS 只允许原始 check 按合法 N/A 排除
            依据校验 PASS 不产生实质 PASS
            所有 SUBSTANTIVE check 均被合法 N/A 排除时门禁不得 PASS
            除门禁定义整体 N/A 外，此时门禁 INCONCLUSIVE

    VERIFICATION-RUN-ID 检查覆盖表
        VERIFICATION-RUN-ID：<VERIFICATION-RUN-ID>
        VERIFICATION-PLAN-ID：<VERIFICATION-PLAN-ID>
        VERIFICATION-CHECK-ID：<VERIFICATION-CHECK-ID>
        纳入状态：<INCLUDED-EXCLUDED>

        终止状态：<NOT-FINISHED-FINISHED-STOPPED>
        CHECK-RESULT：<CHECK-RESULT>
        排除或停止原因：<PRECISE-REASON-OR-NOT-APPLICABLE>
        规则

            EXCLUDED 必须是 NOT-STARTED、NOT-FINISHED 和 NOT-RUN
            INCLUDED 且从未开始时 CHECK-RESULT 为 NOT-RUN
            INCLUDED、已经开始且完成时按实际判定记录结果
            INCLUDED、已经开始后因停止条件终止时 CHECK-RESULT 为 ABORTED
            已经开始后发生工具错误时 CHECK-RESULT 为 ERROR
            不把从未开始的检查写成 ABORTED

    总体运行状态覆盖修正
        COMPLETED
            检查覆盖表包含所属 plan 的全部 check
            每个 INCLUDED check 都是 FINISHED
            每个 EXCLUDED check 明确记录 NOT-RUN
            不存在 run-level stop 或 run-level error
        ABORTED
            运行开始后命中全局停止条件
            已经开始但未完成的 INCLUDED check 记录 ABORTED
            尚未开始的 INCLUDED check 记录 NOT-RUN
            EXCLUDED check 仍记录 NOT-RUN
        ERROR
            run-level 工具或账本错误阻止完整正常运行
            已经开始且受错误影响的 check 记录 ERROR
            尚未开始的 check 记录 NOT-RUN
        规则
            每个 plan check 都有覆盖行
            不允许静默遗漏
            前文“未完成检查记录 ABORTED”只适用于已经开始的检查

            任一条件 ERROR 得到前置聚合 ERROR

            否则任一条件 FAIL 得到前置聚合 FAIL

        前置聚合 ERROR
            CHECK-RESULT ERROR
        前置聚合 INCONCLUSIVE
            CHECK-RESULT INCONCLUSIVE
        前置聚合 FAIL
            CHECK-RESULT NOT-RUN
        前置聚合 PASS
            检查可以开始
        检查开始后

            否则任一新求值 FAIL 或 INCONCLUSIVE 得到 CHECK-RESULT ABORTED

    门禁前置校验与正常贡献总顺序
        第一层：配置完整性
            revision、digest、release type、plan、check 集合或 cutoff 不一致
            缺少必需 envelope 字段
            缺少选择行
            同一 check 选用输入多于一个
            缺少必需领域 outcome 或贡献
            非法 supersede 状态转换
        第一层命中
            门禁 ERROR
            不进入后续聚合
        第二层：CONDITIONAL 触发完整性
            任一触发判定缺失或重复得到 ERROR
            否则任一触发判定 ERROR 得到 ERROR
            否则任一触发判定 INCONCLUSIVE 得到 INCONCLUSIVE
            否则全部 FALSE 且门禁为 CONDITIONAL 得到 NOT-TRIGGERED
            否则只把 TRUE check 加入适用集合
        第二层得到终态
            不进入后续聚合
        第三层：适用 check 贡献
            任一 FAIL 得到 FAIL
            否则任一 ERROR 得到 ERROR
            否则任一 ABORTED 得到 ABORTED
            否则任一 INCONCLUSIVE 得到 INCONCLUSIVE
            否则任一 NOT-RUN 得到 NOT-RUN
        第四层：PASS 与空集
            至少一个 SUBSTANTIVE check 为 PASS
            其余适用 check 为 PASS 或合法排除
            才得到 PASS
            META-VALIDATION PASS 不计入实质 PASS 数量
            没有 SUBSTANTIVE PASS 时不得 PASS
            门禁定义整体不适用且依据有效时才得到 NOT-APPLICABLE
            其他空实质集合得到 INCONCLUSIVE
        优先级结论
            配置 ERROR 优先于技术 FAIL
            触发 ERROR 或 INCONCLUSIVE 优先于普通贡献
            进入正常贡献后沿用 FAIL、ERROR、ABORTED、INCONCLUSIVE、NOT-RUN 的固定顺序

    REPORT-ID 索引 WITHDRAW 真值
        前文索引事件 WITHDRAW
            正式名称解释为 WITHDRAW-REPORT
        WITHDRAW-REPORT 字段
            前一 current REPORT-REVISION-ID 必须等于事件前 current 或 NONE
            前一 current 分离式摘要记录与前一 current 同时存在或同时为 NONE
            新 current REPORT-REVISION-ID 必须为 NONE
            新 current 分离式摘要记录必须为 NONE
            必须填写精确原因
            REVIEW-ID 按索引策略填写已有值或 NONE
        结果
            REPORT-ID 派生状态为 WITHDRAWN
            current pointer 原子地清空
        终态
            WITHDRAWN 后 SET-CURRENT、CLEAR-CURRENT 或重复 WITHDRAW-REPORT 均非法
            非法事件保留并产生 report-index 配置 ERROR
        CLEAR-CURRENT
            只清空 current pointer
            REPORT-ID 仍为 ACTIVE
        SET-CURRENT
            只允许 REPORT-ID 当前状态为 ACTIVE

            纳入状态 INCLUDED
        CONDITIONAL 且触发 TRUE
            纳入状态 INCLUDED
        CONDITIONAL 且触发 FALSE

        CONDITIONAL 且触发 INCONCLUSIVE 或 ERROR
            纳入状态 EXCLUDED

            纳入状态 EXCLUDED

            每个 run 在开始前固定本次触发判定快照

            不得通过 EXCLUDED 隐藏 REQUIRED 或触发 TRUE 的 check

    单项终态与总体运行状态分离
        单项终态结果
            NOT-RUN
            PASS
            FAIL
            INCONCLUSIVE
            ERROR
            ABORTED
            NOT-APPLICABLE
        总体 COMPLETED
            检查覆盖表包含 plan 的全部 check
            每一行都有一个单项终态结果
            没有 run-level 全局停止
            没有 run-level ERROR
        COMPLETED 允许
            check-local 停止产生 STOPPED 和 ABORTED
            check-local 前置条件 FAIL 产生 NOT-STARTED 和 NOT-RUN
            check-local 前置条件 INCONCLUSIVE 产生 NOT-STARTED 和 INCONCLUSIVE
            EXCLUDED 产生 NOT-STARTED 和 NOT-RUN
        总体 ABORTED
            只由 run-level 全局停止产生
        总体 ERROR
            只由 run-level 工具、输入或账本错误产生
        规则
            前文 COMPLETED 要求每个 INCLUDED check 都 FINISHED 的条件失效
            终态结果已经完整落表即可完成 run 级编排
            总体 COMPLETED 不改变任何单项结果

            各 INCLUDED check 保持 INCLUDED
            各行 NOT-STARTED 和 NOT-RUN
            记录完整时总体运行状态 COMPLETED
        检查开始前 INCONCLUSIVE
            各 INCLUDED check 保持 INCLUDED
            各行 NOT-STARTED 和 INCONCLUSIVE

        检查开始后 ERROR

    CONDITIONAL 触发依赖字段

            WITHDRAWN 后的任何 lifecycle 事件

            基础状态不改变
            revision-bound 前置校验 ERROR

            MARK-REVIEWED 必须引用匹配目标 digest 的有效 REVIEW-ID
            RELEASE 必须引用对应发布类型的 PASS 门禁视图
        SUPERSEDED

            只按 active ENTIRE-REVISION supersede 边派生
            WITHDRAWN 的显示优先级高于 SUPERSEDED

        VERIFICATION-RUN-ID：<VERIFICATION-RUN-ID>
        VERIFICATION-PLAN-ID：<VERIFICATION-PLAN-ID>
        目标 REPORT-REVISION-ID：<REPORT-REVISION-ID>
        目标 revision 分离式摘要记录：<DETACHED-DIGEST-REFERENCE>
        TARGET-RELEASE-TYPE：<INTERIM-FINAL>
        TRIGGER-SNAPSHOT-CUTOFF：<DATE-TIME-TIMEZONE>
        run 开始时间与时区：<DATE-TIME-TIMEZONE>
        conditional check 数量：<NONNEGATIVE-INTEGER>
        快照字节边界：<EXACT-SERIALIZED-ROWS-IN-RUN-RECORD>
        规则
            TRIGGER-SNAPSHOT-CUTOFF 不得晚于 run 开始时间
            目标、digest、plan 和 release type 必须与 run 完全一致
            快照行进入 VERIFICATION-RUN-ID 不可变记录
            快照由 run 的分离式摘要记录共同保护
            不建立新的 trigger snapshot ID

    verification run 触发快照逐项表
        VERIFICATION-RUN-ID：<VERIFICATION-RUN-ID>
        VERIFICATION-CHECK-ID：<VERIFICATION-CHECK-ID>
        运行前触发判定行引用：<STABLE-LOCAL-ROW-REFERENCE>
        运行前触发判定：<TRUE-FALSE-INCONCLUSIVE-ERROR>
        判定记录时间与时区：<DATE-TIME-TIMEZONE>
        判定 LEDGER-CUTOFF-TIME：<DATE-TIME-TIMEZONE>
        纳入状态：<INCLUDED-EXCLUDED>
        规则
            所属 plan 的每个 CONDITIONAL check 恰有一行
            判定行引用解析到 CONDITIONAL 触发判定表的精确历史行
            判定记录时间和判定 cutoff 都不得晚于 TRIGGER-SNAPSHOT-CUTOFF
            TRUE 对应 INCLUDED
            FALSE、INCONCLUSIVE 或 ERROR 对应 EXCLUDED
            检查覆盖表引用本表精确行
            REQUIRED check 不伪造触发快照行

    run-time 与 release-time 触发判定分离
        run-time trigger
            决定该 VERIFICATION-RUN-ID 是否执行 conditional check
            由 run 触发快照固定
        release-time trigger
            决定当前门禁 cutoff 下 conditional check 是否适用
            由门禁固定输入引用的触发判定行固定
        两次判定相同
            按正常选择规则处理
        run-time TRUE 且 release-time FALSE
            运行记录保留
            当前发布视图排除该 check
            不选择该运行贡献门禁
        run-time FALSE、INCONCLUSIVE 或 ERROR 且 release-time TRUE
            该 run 对该 check 不合格
            选择其他运行
            没有其他合格运行时选用结果 NOT-RUN
        两次判定一个为 INCONCLUSIVE 或 ERROR
            分别保留两次判定
            release-time 判定按门禁前置校验总顺序决定当前门禁终态
        判定变化
            建立触发判定差异记录
            记录两个精确行引用、输入差异和解释
            不改写旧判定行或旧 VERIFICATION-RUN-ID
        规则
            门禁不得用 release-time 判定回填 run 触发快照
            run 纳入状态不得由晚于 run start 的判定证明

    发布判定 Gate 集合完整性
        固定来源
            使用 TARGET-RELEASE-TYPE 对应的固定发布门禁矩阵
        必须满足
            矩阵中的每个 Gate-name 恰有一个门禁固定输入头表引用
            矩阵中的每个 Gate-name 恰有一个门禁结果
            头表引用 Gate-name 集合等于结果 Gate-name 集合
            两个集合都等于固定发布门禁矩阵集合
            每项 TARGET-RELEASE-TYPE 与发布判定视图相同
        配置错误
            缺少 Gate-name
            重复 Gate-name
            出现矩阵外 Gate-name
            头表和结果集合不相等

    第 4 阶段 BUILD-ID 字段正式解释
        前文页面构建标识：<BUILD-ID>
            正式解释为 <BUILD-ID-OR-UNKNOWN>
        BUILD-ID 尚未由第 6 阶段规则建立时
            必须填写 UNKNOWN
            不得在第 4 阶段自行分配 BUILD-ID
        已有正式 BUILD-ID 时
            只有证据证明当前 CRYPTO-RECORD-ID 属于该构建才可填写
            文件名、URL 相似或代码文本相同不能单独证明绑定
        规则
            BUILD-ID 只按第 6 阶段身份规则正式建立
            UNKNOWN 不得用临时名称、时间戳或猜测值替代

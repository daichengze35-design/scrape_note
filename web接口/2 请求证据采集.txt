Web API 加密逻辑分析
    第 2 阶段：请求证据采集

    学习目标
        能使用 Chrome DevTools Network 记录一次已授权操作产生的请求与响应
        能区分请求列表、Headers、Payload、Preview、Response、Initiator、Timing 和 Cookies 中的信息
        能先建立重复基线，再通过一次只改变一个公开测试变量进行受控差分
        能把直接观察、派生事实、推断和未知内容分开记录
        能检查 HAR 中的敏感信息，并生成不包含凭证和个人数据的共享副本

    本阶段不学习
        不使用 Sources、XHR/fetch 断点、Scope、Watch、调用栈调试、Pretty Print 或 Source Map
        不使用 Replay XHR、Edit and Resend、Copy as cURL、Copy as fetch 或其他请求重放功能
        不修改、阻断、伪造或自动重发任何请求
        不使用代理拦截、Local Overrides、CDP 自动采集、浏览器自动化或 Python requests 复现
        不分析参数排序、规范化、哈希、HMAC、AES、RSA、Web Crypto、CryptoJS 或签名生成函数
        不分析 webpack、Vite、压缩代码、混淆、Worker、WASM、WebSocket Frames、GraphQL 或 Protobuf
        不操作未授权系统，不测试权限、验证码、风控、付费内容或 DRM

    版本差异
        Chrome DevTools 会随浏览器版本更新界面
        Network 中的按钮位置、菜单名称、列名和部分详情标签可能发生变化
        本阶段只使用长期稳定的功能概念，不依赖某个版本的具体图标位置
        开始采集前需要记录浏览器名称和完整版本号
        如果当前界面名称与教程不同，应根据功能含义查找，不应根据图标位置推断

    Network 的证据范围
        能直接观察
            DevTools 打开并处于记录状态期间，浏览器记录到的网络活动
            请求列表中显示的请求方法、请求地址、状态、类型、发起者、大小和时间等信息
            请求详情中显示的请求头、响应头、查询参数、请求体表示和响应内容表示
            当前浏览器显示的缓存来源、重定向、预检、Service Worker 和 Cookie 状态信息
        不能直接证明
            某个字段由哪个 JavaScript 函数生成
            某个字段使用什么密码学算法
            某个请求头由页面脚本、浏览器、扩展或 Service Worker 中的哪一层最终产生
            服务端怎样验证请求
            服务端内部实际执行时间
            Network 显示内容与传输层原始字节完全相同
        结论原则
            Network 中直接显示的内容可以记录为观察事实
            根据长度、字符集、相等关系和差分计算出的内容属于派生事实
            字段用途、生成原因、算法类型和因果关系属于推断，除非后续阶段获得直接证据

    采集前的授权记录
        记录内容
            分析对象的所有者
            授权人或授权来源
            允许使用的账号或测试身份
            允许观察的功能和数据范围
            允许采集的开始时间和结束时间
            不允许执行的操作
        最小原则
            只观察完成当前学习目标所需的请求
            不采集与目标无关的第三方内容
            不采集其他用户数据
            不保存不必要的凭证、个人信息或完整响应正文
        停止条件
            请求超出已记录的授权范围
            响应包含其他用户数据或未预期的敏感数据
            页面要求进行权限、验证码、风控、付费或 DRM 绕过
            当前操作可能修改真实数据，而该修改未获得授权

    一次采集会话
        概念
            从确定采集环境开始，到完成一组相关请求记录并保存证据为止，称为一次采集会话
        每次会话需要固定或记录
            浏览器名称与完整版本
            操作系统
            采集日期、时间和时区
            页面语言、浏览器语言和时区设置
            是否使用设备模拟
            是否使用网络限速
            是否启用 Preserve log
            是否启用 Disable cache
            当前是否登录以及使用哪一个授权测试身份
            页面进入采集前的可见状态
        原因
            浏览器版本、语言、时区、缓存和会话状态都可能改变请求
            未记录环境时，后续差异可能无法区分是输入变化还是环境变化

    Network 记录状态
        打开时机
            在触发目标操作之前打开 DevTools 和 Network
            操作已经发生后再打开 Network，之前的请求通常不会自动补录
        记录指示
            Network 通常有启用或暂停记录的状态
            采集前必须确认当前处于记录状态
        清空请求列表
            清空请求列表只删除当前 DevTools 中显示的记录
            清空请求列表不等于清除浏览器缓存、Cookie、Storage 或登录状态
        建议顺序
            打开 Network
            确认记录已启用
            记录 Preserve log 与 Disable cache 状态
            清空当前请求列表
            只执行一个已授权操作
            等待该操作相关请求结束
            停止继续操作并开始记录证据

    Preserve log
        作用
            页面导航或重载时，Network 请求列表可能被清空
            启用 Preserve log 后，DevTools 会保留跨导航的请求记录
        适用情况
            点击后发生页面跳转
            登录流程发生重定向
            操作先打开新页面再发送请求
            需要观察多个文档之间的请求链
        注意
            Preserve log 会让不同页面和不同阶段的请求混在同一列表中
            使用时必须记录每个操作的开始时间和请求顺序
            Preserve log 不会证明列表中的所有请求都属于当前目标操作

    Disable cache
        作用
            DevTools 提供禁用浏览器缓存的设置
            该设置通常只在 DevTools 打开时生效
        影响
            禁用缓存后，浏览器可能重新请求原本可从缓存读取的资源
            请求数量、状态、Size、Timing 和响应来源可能发生变化
        记录原则
            每次采集都必须记录缓存是否禁用
            A/A 和 A/B 差分必须保持相同缓存设置
            不能把禁用缓存前后的差异直接解释为业务参数变化

    请求列表
        常见列
            Name
                请求资源名称或地址摘要
            Status
                HTTP 状态码或当前请求状态
            Type
                浏览器识别的资源类型
            Initiator
                触发请求的来源摘要
            Size
                传输大小、资源大小或缓存来源的界面表示
            Time
                请求总持续时间的界面表示
            Waterfall
                请求在时间轴中的开始位置和各阶段长度
        可选列
            Method
            Domain
            Protocol
            Scheme
            Priority
            Remote address
            Set-Cookies
            不同版本提供的可选列可能不同
        重要限制
            列表中的 Name 不是完整请求证据
            必须打开详情查看完整 URL、方法、参数、请求头和响应
            Size 不自动等于响应正文长度
            Time 不自动等于服务端处理时间

    Type 过滤
        常见类型
            Doc 或 Document
            Fetch/XHR
            JS 或 Script
            CSS 或 Stylesheet
            Img 或 Image
            Media
            Font
            WS 或 WebSocket
            Other
        重点
            Fetch/XHR 过滤器不包含全部可能的接口请求
            页面导航、表单提交、Beacon、预检和其他类型也可能承载业务通信
            找不到请求时，应先清除类型过滤，再检查完整列表
        错误结论
            “Fetch/XHR 中没有请求，所以页面没有接口请求”属于无证据结论

    文本与属性过滤
        作用
            根据名称、地址、方法、状态、域、类型或其他条件缩小请求列表
        使用原则
            每次截图或导出前记录当前过滤条件
            得出“未观察到请求”结论前清除所有过滤条件并重新检查
            过滤结果为空，只能说明当前条件下没有显示匹配项
            过滤不删除请求，但会隐藏不匹配的列表项
        易错点
            忘记清除上一次采集留下的过滤条件
            只按接口名称过滤，而目标名称只存在于响应体
            只看成功状态请求，忽略失败、重定向或预检请求

    定位候选请求
        时间关系
            记录触发操作的准确时刻
            优先检查紧随该操作出现的请求
            时间接近只能说明相关性，不能单独证明因果关系
        响应内容
            检查响应是否包含当前页面出现的公开测试数据
            响应包含目标数据可以支持候选判断，但不能证明它是唯一数据来源
        请求语义
            检查方法、路径、查询参数和请求体是否与当前操作一致
            不能只根据路径名称判断用途
        重复验证
            在相同条件下重新采集
            候选请求应在相同操作下重复出现
            如果每次出现的请求序列不同，应先记录差异，不要立即选择一个请求作为唯一目标

    请求详情标签
        常见标签
            Headers
            Payload
            Preview
            Response
            Initiator
            Timing
            Cookies
        版本与类型差异
            不同 Chrome 版本可能调整标签名称或顺序
            某些请求没有请求体时，可能不显示 Payload
            某些请求类型会增加专用标签
            标签缺失不能单独证明数据不存在

    Headers 中的 General
        常见内容
            Request URL
            Request Method
            Status Code
            Remote Address
            Referrer Policy
        Request URL
            记录 scheme、host、port、path 和 query
            URL fragment 不会作为 HTTP 请求目标发送给服务器
            查询参数可能包含凭证、标识符或个人数据，记录前必须检查
        Request Method
            记录实际显示的方法
            不根据页面动作猜测 GET、POST、PUT、PATCH、DELETE 或 OPTIONS
        Status Code
            记录 HTTP 状态码
            HTTP 200 不等于业务处理成功
            业务状态需要结合响应结构判断
        Remote Address
            可能受代理、CDN、连接复用和浏览器实现影响
            不能仅凭 Remote Address 判断真实业务服务器位置

    Request Headers
        记录内容
            头部名称
            脱敏后的值或值类型
            是否每次存在
            是否随输入、会话、时间或环境变化
        常见类别
            内容协商
                Accept
                Accept-Language
                Accept-Encoding
            请求体说明
                Content-Type
                Content-Length
            来源与上下文
                Origin
                Referer
                Sec-Fetch-* 系列
            缓存条件
                If-None-Match
                If-Modified-Since
            身份与状态
                Authorization
                Cookie
                自定义认证头
            客户端信息
                User-Agent
                User-Agent Client Hints
            业务自定义头
                名称以实际观察为准
        证据限制
            Network 显示某个头部，不证明它由页面 JavaScript 设置
            浏览器、扩展、Service Worker、代理和运行时都可能影响头部
            HTTP/2 与 HTTP/3 的头部名称、顺序和传输表示不能直接由界面显示还原
        Provisional headers
            某些请求会显示 provisional headers 或同类提示
            这表示界面展示的头部可能不是最终实际发送的完整头部
            遇到该提示时，应记录提示本身，并把头部状态标为未完全确认

    Response Headers
        记录内容
            Content-Type
            Content-Encoding
            Cache-Control
            ETag
            Location
            Set-Cookie
            业务相关自定义头
        注意
            Response Headers 描述 HTTP 响应元数据
            Set-Cookie 出现不代表 Cookie 一定被浏览器接受和保存
            Content-Encoding 表示传输内容编码，不等于应用层加密
            Location 常用于重定向，但必须结合状态码和后续请求判断

    Query String Parameters
        位置
            查询字符串位于 URL 的 ? 之后
        记录内容
            参数名称
            参数顺序
            原始编码表示
            DevTools 解析后的值
            是否重复出现同名参数
            是否为空值或缺少等号
        重点
            解析后的值不等于原始 URL 字节表示
            空格可能显示为解码后的空格，而原始表示可能是 %20 或 +
            同名参数可以出现多次
            记录签名分析前的证据时，应同时保留原始表示和解析表示
        脱敏
            查询参数会出现在地址、日志和 HAR 中
            Authorization code、Token、邮箱、手机号、用户标识和签名 URL 值必须脱敏

    Payload
        可能显示的内容
            Query String Parameters
            Form Data
            Request Payload
            文件上传或二进制内容的摘要表示
        Content-Type
            application/json
            application/x-www-form-urlencoded
            multipart/form-data
            text/plain
            application/octet-stream
            其他实际观察到的类型
        JSON 请求体
            记录可见字段名、值类型、嵌套路径和数组结构
            不保存真实凭证或个人数据
            Preview 或格式化视图可能改变空白和缩进显示
        表单请求体
            application/x-www-form-urlencoded 与 URL 查询参数外观接近，但位置不同
            multipart/form-data 包含 boundary 和多个部分
            boundary 可能由浏览器或库生成并在不同请求间变化
        二进制请求体
            界面可能无法完整显示所有字节
            不能根据空白界面断定请求体不存在
        原始表示与解析表示
            解析视图便于阅读字段
            源文本视图更接近页面传入的文本表示
            两者都不自动等于传输层原始字节
        错误结论
            “POST 请求体一定是 JSON”是错误结论
            “查询参数和请求体可以互换”是错误结论

    Preview 与 Response
        Preview
            Preview 通常按浏览器识别的格式解释响应
            JSON、HTML、图片或其他内容可能被结构化或可视化显示
        Response
            Response 显示响应内容的文本或可用表示
            大型、流式、二进制或被缓存的响应可能无法完整按原始形式显示
        区别
            Preview 是浏览器解释后的视图
            Response 更接近响应内容表示，但仍不等于传输层原始字节
        压缩
            浏览器通常会处理 Content-Encoding 后再向页面提供内容
            Network 中可读的响应可能已经解压
            不能用可读文本长度直接代替网络传输字节长度
        业务状态
            HTTP 状态码与业务状态是两个层次
            HTTP 200 响应体仍可能表示业务失败
            HTTP 4xx 或 5xx 响应体仍可能包含有用的错误结构
        业务结果的证据限制
            Network 能直接观察的是响应中声明的业务代码、状态字段和消息
            响应声明不自动等于实际业务结果
            只有接口契约、授权测试页面的独立状态变化或其他直接证据，才能进一步验证业务结果
            证据模板中的“业务状态”必须按“响应声明的业务代码与消息”理解，并标记是否独立验证

    Initiator
        作用
            Initiator 提供请求由什么类型的活动触发的线索
            可能显示解析器、脚本位置、调用链、重定向或其他请求依赖
        本阶段记录
            发起类型
            显示的文件名或资源名
            显示的行列位置
            可见的调用链或依赖链摘要
        证据限制
            Initiator 指向的位置不自动等于字段生成位置
            请求发送函数可以接收已经在其他位置构造完成的数据
            本阶段只记录 Initiator，不进入源码和调用栈调试

    Timing
        常见阶段
            Queueing
            Stalled
            DNS Lookup
            Initial connection
            SSL
            Request sent
            Waiting 或 TTFB
            Content Download
        版本差异
            当前请求未经历的阶段可能不显示
            连接复用、缓存、Service Worker 和协议版本会改变阶段结构
        TTFB
            TTFB 表示从请求相关处理开始到收到第一个响应字节的时间范围
            TTFB 包含网络往返、连接状态和服务端处理等多种因素
            TTFB 不等于服务端函数执行时间
        TTFB 精确边界
            DevTools 的 Waiting 或 TTFB 主要表示请求发送后到收到首个响应字节的等待时间
            它可以包含网络往返与服务端等待，但 DNS、TCP 建连和 TLS 通常由独立阶段显示
            上面的“连接状态”只能作为整体采集环境因素记录，不能把独立的建连阶段直接计入 TTFB
        Stalled
            Stalled 可能包含客户端排队、连接可用性和其他等待
            Stalled 不自动表示服务端限速
        记录原则
            记录总时间和可见阶段
            不根据单次 Timing 结果判断服务端性能原因
            比较 Timing 时保持缓存、网络限速和会话环境一致

    Cookies
        Request Cookies
            表示当前请求携带的 Cookie
        Response Cookies
            表示响应尝试设置的 Cookie 及相关属性
        Cookie 请求头
            Cookie 请求头是实际请求头中的状态数据表示
        Set-Cookie 响应头
            Set-Cookie 是服务端要求浏览器设置 Cookie 的响应头
        被阻止 Cookie
            浏览器可能因为 Domain、Path、Secure、SameSite、第三方 Cookie 策略或其他规则拒绝 Cookie
            当前版本可能显示被拒绝原因
        Cookie 状态精确分类
            Request Cookies 中需要区分已实际发送的 Cookie 和被浏览器排除、未发送的 Cookie
            Response Cookies 中需要区分响应尝试设置的 Cookie 和被浏览器拒绝、未保存的 Cookie
            不同 Chrome 版本的分组名称可能不同，应以当前界面显示的 included、excluded、blocked 或同类状态为准
            Path 主要控制 Cookie 后续发送范围，不应把 Path 单独当成通用的 Set-Cookie 拒绝原因
            记录时必须写明方向、是否发送或保存，以及浏览器显示的具体原因
        证据限制
            Network 的 Cookies 视图只与当前请求和响应相关
            它不是浏览器全部 Cookie 的完整仓库
            看到 Set-Cookie 不证明 Cookie 已成功保存
        敏感性
            Session Cookie、认证 Cookie 和防跨站请求伪造值可能等同于凭证或安全状态
            不应在截图、HAR、聊天记录或共享教程中保留真实值

    重定向链
        识别方法
            一个用户操作可能先收到 3xx，再请求 Location 指向的新地址
            Preserve log 有助于保留跨导航请求
            每个请求都需要单独记录方法、状态、Location 和后续请求
        注意
            重定向前后的方法和请求体可能不同
            不能只记录最终 200 请求并忽略前面的重定向
            重定向链中的 URL 也可能包含敏感参数

    CORS 预检
        现象
            浏览器可能在实际跨源请求前发送 OPTIONS 请求
            该 OPTIONS 请求通常称为预检请求
        记录内容
            预检请求的方法和地址
            Access-Control-Request-Method
            Access-Control-Request-Headers
            预检响应状态和 Access-Control-Allow-* 头部
            与预检对应的实际请求
        证据限制
            预检成功不等于实际业务请求成功
            OPTIONS 请求不自动等于业务数据请求
            本阶段只识别预检与实际请求关系，不展开 CORS 机制

    缓存来源
        常见来源
            Memory cache
            Disk cache
            Service Worker
            网络响应
        记录内容
            请求是否实际从网络获取
            Size 或状态栏是否显示缓存来源
            是否启用 Disable cache
        注意
            缓存命中可能没有新的响应体传输
            304 表示资源未修改，浏览器可能继续使用本地缓存内容
            从缓存得到页面数据，不证明服务端当前重新返回了该数据

    Service Worker
        现象
            Service Worker 可以拦截页面范围内的请求并返回缓存或网络结果
            Network 可能显示请求由 Service Worker 处理
        本阶段记录
            是否显示 Service Worker 来源
            请求是否继续产生下游网络请求
            缓存与 Timing 显示是否发生变化
        边界
            本阶段不查看 Service Worker 内部代码
            本阶段不修改、绕过或停用 Service Worker

    请求序列
        单个操作可能包含
            文档请求
            静态资源请求
            配置请求
            预检请求
            业务请求
            轮询或心跳
            统计或日志请求
            重定向后的请求
        记录方法
            按开始时间为候选请求编号
            记录前后依赖关系
            标记预检、重定向、缓存和 Service Worker 来源
            把目标操作前已经周期运行的请求标为背景请求候选
        重点
            时间相邻不证明请求属于同一业务流程
            需要结合重复采集、Initiator、参数和响应内容判断

    基线采集 A/A
        目的
            识别在输入不变时仍会自然变化的字段
            避免把时间、随机值、会话状态或后台请求误认为输入导致的变化
        条件
            使用同一授权测试身份
            使用相同页面起始状态
            使用相同公开测试输入
            保持浏览器版本、语言、时区、缓存和网络设置一致
            每轮只执行一个相同操作
        示例编号
            A1
            A2
            A3
        比较内容
            请求是否每轮出现
            请求顺序是否相同
            方法、路径和状态是否相同
            参数名称和出现位置是否相同
            字段值、长度和字符集是否变化
            响应结构是否相同
        结论限制
            三次相同不证明字段永久固定
            三次不同不证明字段是随机数、timestamp、nonce 或密文
            只能先记录为稳定候选、运行时变化候选或尚不能确定

    单变量差分 A/B
        目的
            在保持其他条件不变时，只改变一个公开测试变量
            观察请求结构和字段怎样随该变量变化
        正确顺序
            先完成 A/A 重复基线
            选择一个不敏感的公开测试变量
            建立 B 条件，只修改该变量
            对 B 条件重复采集
            比较 A 组与 B 组
        示例编号
            A1、A2、A3 使用输入 A
            B1、B2、B3 使用输入 B
        不适合作为测试变量
            真实密码
            真实认证 Token
            他人账号或个人数据
            权限级别
            付费状态
            验证码、风控结果或 DRM 状态
        结论限制
            A 与 B 同时变化只能支持相关性判断
            如果多个环境因素一起变化，不能形成单变量结论
            即使某字段只在 B 组变化，也不能仅据此确定生成算法

    字段变化分类
        稳定字段候选
            多次采集中保持相同
            仍需说明观察次数和环境范围
        每请求变化候选
            同一条件下每次请求都可能变化
            不能直接命名为 nonce 或随机数
        时间相关候选
            值与采集时间存在重复观察到的关系
            在未验证单位、时区和产生逻辑前，不直接命名为 timestamp
        输入相关候选
            公开测试输入变化时，该字段重复发生对应变化
            不能仅据此确定是明文、编码、哈希、签名或密文
        会话相关候选
            同一会话稳定，不同授权测试会话变化
            不自动等于 Cookie、Token 或 Session ID
        环境相关候选
            浏览器版本、语言、时区、设备或缓存变化时发生变化
        尚不能确定
            样本不足
            多个变量同时变化
            观察结果互相矛盾
            Network 表示不足以判断原始字节

    字段位置记录
        URL path
        Query String
        Request Headers
        Cookie
        Form Data
        JSON Request Payload
        Binary Request Payload
        Response Headers
        Response Body
        重点
            相同字段名出现在不同位置时，必须分别记录
            字段位置是请求语义的一部分
            不能把查询参数、请求头和请求体中的同名字段视为同一个证据项

    值的表示记录
        记录内容
            显示值类型
            可见字符集
            字符长度
            可见编码特征
            原始视图与解析视图是否不同
            是否为空、缺失或 null
        不记录
            真实凭证
            完整个人信息
            未经授权的响应内容
            可以用于恢复秘密的前缀、后缀或完整长度组合
        重点
            字符长度不等于 UTF-8 字节长度
            Network 格式化结果不等于传输层原始字节
            Base64 或 Hex 外观不能单独证明字段分类

    证据等级
        直接观察
            当前 Network 记录直接显示的内容
        重复观察
            在相同条件的多次独立采集中重复出现
        受控差分
            在单变量 A/B 条件中重复出现对应变化
        推断
            根据观察形成、但尚未通过源码或服务端规则验证的解释
        未知
            当前证据无法支持具体分类
        写法
            事实
                A1、A2、A3 中字段长度均为 32 个字符
            推断
                该字段可能与会话状态有关
            未知
                生成位置、输入字节和算法均未验证

    HAR
        概念
            HAR 是 HTTP Archive 的缩写
            HAR 通常使用 JSON 表示一组 HTTP 请求与响应记录
        可能包含
            完整 URL 与查询参数
            请求方法
            请求头与响应头
            Cookie 与 Set-Cookie
            请求体或 postData
            响应内容
            Timing
            服务器地址与连接信息
            Base64 表示的二进制内容
        不等于
            HAR 不是 PCAP
            HAR 不是传输层原始数据包
            HAR 不是完整浏览器状态
            HAR 不一定包含所有请求体和响应体
            HAR 不证明服务端内部逻辑
        导出前
            确认当前过滤条件
            确认是否只需要导出当前目标请求
            检查列表中是否存在第三方请求
            检查页面是否产生了个人数据或凭证
            不需要 HAR 时，不应为了保存而保存

    HAR 敏感信息
        高风险位置
            Authorization
            Proxy-Authorization
            Cookie
            Set-Cookie
            自定义 Token 或 API key 头
            URL query
            postData
            multipart/form-data 文件名和内容
            响应正文
            重定向 Location
            Base64 内容
            用户名、邮箱、手机号、地址和内部标识符
            log.pages[].title
            entries[].serverIPAddress
            entries[].connection
            entries[]._initiator 中的源码 URL、行列位置和调用信息
            entries[].response.redirectURL
        Sanitized HAR
            某些 Chrome 版本可能提供 sanitized 或同类脱敏导出方式
            功能名称和默认行为可能随版本变化
            sanitized 不代表文件可以直接公开
            自定义认证头、请求体、响应体和编码内容仍需要人工检查
        原则
            不共享未经人工检查的 HAR
            不在聊天、工单或公开仓库中上传原始 HAR
            不把真实 Cookie、Token 或会话值保留为示例

    HAR 脱敏步骤
        第一步
            优先使用合成测试数据重新采集
        第二步
            创建专门用于共享的副本
            原始证据如确有保留需要，应置于授权范围内的受限位置
        第三步
            检查每个 entry 的 URL、queryString、headers、cookies 和 postData
        第四步
            检查 response.headers、response.cookies 和 response.content
        第五步
            把敏感值替换为明确占位符
            例如 <REDACTED-AUTHORIZATION>、<REDACTED-COOKIE>、<REDACTED-PERSONAL-DATA>
        第六步
            检查 Base64 内容是否解码后包含敏感数据
            本阶段只进行敏感性判断，不分析加密内容
            如果 response.content.encoding 仍为 base64，不能把 text 直接替换为非 Base64 占位符
            可以在共享副本中同时移除敏感 text 与对应 encoding，或写入合法 Base64 形式的无敏感占位内容
            修改内容后，需要同步检查 content.size、bodySize、compression 和其他长度相关字段是否仍表达正确含义
        第七步
            验证脱敏后文件仍是有效 JSON
        第八步
            重新全文搜索凭证名称、个人信息和原始值片段
        第九步
            由另一位授权人员复核共享副本

    截图与文本记录
        截图风险
            请求列表可能显示完整 URL 和查询参数
            Headers、Payload、Cookies 和 Response 可能显示凭证与个人数据
            浏览器右上角、扩展和页面内容也可能泄露身份
        截图原则
            截图前收起无关敏感区域
            对凭证、个人数据和内部地址进行不可逆遮盖
            不使用模糊后仍可辨认的弱遮盖
            保留采集编号和必要上下文
        文本记录
            优先记录字段名称、位置、类型和脱敏后的结构
            不复制完整 Cookie、Token、Authorization 或响应正文

    常见错误
        只打开 Fetch/XHR 过滤器
            问题
                可能遗漏 Document、Other、Beacon、预检或其他类型的业务请求
            修正
                清除类型过滤并检查完整请求列表
        操作完成后才打开 Network
            问题
                已发生的请求通常没有被记录
            修正
                在触发操作前打开 Network 并确认记录状态
        把 HTTP 200 当成业务成功
            问题
                响应体可能表示业务失败
            修正
                分别记录 HTTP 状态和业务状态
        把 Preview 当成原始字节
            问题
                Preview 是浏览器解释后的表示
            修正
                标注视图来源，并保留原始表示是否可见的状态
        把 Size 当成响应正文长度
            问题
                压缩、缓存和界面统计方式会影响 Size
            修正
                分别记录传输、资源和缓存来源信息
        把 Initiator 当成字段生成位置
            问题
                Initiator 只提供请求触发链索引
            修正
                本阶段只记录，下一阶段再追踪调用链
        把 TTFB 当成服务端执行时间
            问题
                TTFB 还包含网络和连接因素
            修正
                只记录观察值，不推断单一原因
        看到 Set-Cookie 就认定保存成功
            问题
                浏览器可能拒绝 Cookie
            修正
                检查 Cookies 视图和被阻止原因
        直接共享 sanitized HAR
            问题
                自定义头、请求体、响应体和编码内容仍可能泄露秘密
            修正
                始终执行人工脱敏检查
        只采集两次就判断因果关系
            问题
                自然波动和其他环境变量可能影响结果
            修正
                先建立 A/A 重复基线，再做重复的单变量 A/B 差分

    排查 Network 没有目标请求
        检查记录是否启用
        检查 DevTools 是否在操作前打开
        清除所有过滤条件
        检查 Preserve log 是否需要启用
        检查请求是否来自缓存或 Service Worker
        检查操作是否实际完成
        检查候选是否显示为 Document、Other、Media 或预检
        检查是否发生重定向或新页面打开
        重新执行一次相同授权操作并记录时间
        如果仍未观察到
            记录“当前条件下未观察到”
            不写“页面没有该请求”

Web API 加密逻辑分析
    第 7 阶段：浏览器运行时追踪

    学习目标
        能区分同步调用栈、浏览器任务、微任务和异步因果栈
        能记录一次用户操作从事件触发到请求、密码学操作或存储操作的时间线
        能区分 JavaScript API 调用、浏览器请求、Service Worker 处理和缓存命中
        能记录 fetch 与 XMLHttpRequest 的调用、响应头、Body 读取和 Promise 延续
        能记录 Web Crypto 操作的算法参数、输入字节边界、输出类型和 Promise 状态
        能区分 localStorage、sessionStorage、IndexedDB、Cache Storage、Cookie 和内存状态
        能识别 iframe、Dedicated Worker、Shared Worker 和 Service Worker 的上下文边界
        能追踪动态 import 的加载、模块求值和导出函数调用
        能识别框架事件代理、批处理、延迟更新、hydration 和开发模式重复执行
        能把第 6 阶段的 asset、chunk、module、runtime 映射到运行时上下文和异步边
        能把第 5 阶段的 CALL-ID、STAGE-ID 和 LAYER-ID 映射到运行时 API 操作
        能建立不包含秘密值、不修改运行时的被动追踪记录

    本阶段不学习
        不提供真实站点、靶场、练习或实战任务
        不使用 Hook、Monkey Patch、函数替换、代理注入或自定义拦截器
        不使用 Local Overrides、Snippets 或修改后的 bundle
        不向页面或生产代码添加日志、埋点、debugger 或追踪代码
        不执行未知 eval 或 Function 构造器文本
        不修改、阻断、重放、伪造或自动发送请求
        不从 CryptoKey、Storage、Cookie、IndexedDB、Cache Storage 或页面对象中提取秘密
        不读取或复制未脱敏的 Token、密码、会话材料和长期凭据
        不绕过 CORS、认证、授权、验证码、风控、反调试、自校验、付费限制或 DRM
        不改变定时器、时间、堆栈、console、函数源码或浏览器状态
        不把 DevTools 的观察行为写成应用本身的运行逻辑
        不把浏览器内部线程、调度器或原生实现当作页面可以直接证明的事实
        不进入媒体协议、扩展协议和 DRM 细节
        观察扰动修正
            “不改变”表示不主动修改应用语义状态、调度参数或浏览器设置
            DevTools 暂停和 Performance 录制仍可能扰动时间线
            这些观察扰动必须记录，不能声称追踪过程绝对无扰动
            不在同一 RUNTIME-TRACE-ID 中切换缓存、节流或 Service Worker 绕过设置

    本阶段与前六阶段的关系
        第 0 阶段
            提供授权、范围和证据边界
        第 2 阶段
            提供请求采集、CAPTURE-ID 和 Network 时间线
        第 3 阶段
            提供只读断点、调用栈、暂停现场和 DEBUG-SESSION-ID
        第 4 阶段
            提供 Web Crypto、编码和密码学原语分类
        第 5 阶段
            提供 EXECUTION-ID、CALL-ID、STAGE-ID、LAYER-ID 和签名数据流
        第 6 阶段
            提供 BUILD-ID、GENERATED-ASSET-ID、CHUNK-OBSERVED-ID、MODULE-LOCAL-ID、RUNTIME-ID 和 Source Map 状态
        第 7 阶段
            只补充执行时间线、上下文和异步边
            不重新定义密码学算法
            不用请求结果代替函数调用证据
            不用 DevTools 显示的异步祖先代替实际运行栈

    运行时追踪的定义
        被动追踪
            使用页面原本存在的行为
            使用浏览器 DevTools 已提供的断点、面板和记录
            不注入新代码
            不改变对象、函数、请求或存储
        运行时证据
            发生了什么
            发生在哪个浏览器上下文
            发生在什么时间线位置
            由哪个生成位置触发
            产生了哪个后续异步边
        运行时追踪不等于
            重新执行函数
            复制参数后调用 API
            修改返回值
            代替页面发起请求
            证明服务端内部实现

    版本和结论范围
        每次追踪至少绑定
            BUILD-ID
            页面部署标识
            浏览器名称和完整版本
            操作系统和设备类别
            CAPTURE-ID
            DEBUG-SESSION-ID
            EXECUTION-ID
            浏览器上下文
            DevTools 版本或浏览器版本
            追踪面板和断点设置
        浏览器会影响
            任务调度
            定时器节流
            缓存行为
            隐私分区
            Storage 可见性
            Service Worker 生命周期
            DevTools 栈显示
        框架会影响
            事件代理
            状态批处理
            渲染时机
            开发模式重复执行
            hydration
            错误边界
        版本结论规则
            观察到的行为只绑定当前 BUILD-ID 和浏览器环境
            不能把一次页面操作写成所有页面操作都相同
            不能把一个浏览器的调度顺序写成跨浏览器保证
            未能区分浏览器实现与页面行为时记录 UNKNOWN

    前置术语与本地 ID
        CORS
            全称为 Cross-Origin Resource Sharing
            表示浏览器依据请求模式、响应 Header 和 Fetch 规则判断脚本能否取得跨源响应
        XHR
            全称为 XMLHttpRequest
            表示 XMLHttpRequest 请求和事件 API
        HTTP cache
            表示浏览器 HTTP 缓存与重新验证机制
            不等于 Cache Storage
        Cache Storage
            表示 Cache API 管理的 Request 与 Response 存储
            常与 Service Worker 配合，但不是 HTTP cache
        Transferable
            表示在结构化序列化过程中可以执行转移步骤的对象类别
            转移不是结构化复制之外的第二套消息格式
        WORKER-ID
            Worker 或 Service Worker 实例的本地编号
        PORT-ID
            MessagePort 或 Shared Worker 连接端口的本地编号
        TIMER-ID
            setTimeout 或 setInterval 注册实例的本地编号
        XHR-LOCAL-ID
            一个 XMLHttpRequest 对象在当前 CONTEXT-ID 中的本地编号
        TRANSACTION-ID
            一个 IndexedDB transaction 的本地编号
        API-OPERATION-REF
            指向 REQUEST-OBSERVED-ID、CRYPTO-OP-ID、STORAGE-OP-ID 或 MODULE-EVAL-ID 中恰好一种
            它是联合引用字段，不创建新的 OPERATION-ID 身份
        阅读顺序
            先理解本表，再阅读各 API 章节
            完整字段在后文“本章运行时证据实体”中统一列出

    运行时证据等级
        UNKNOWN
            当前没有足够证据区分多个执行解释
        CANDIDATE
            只有名称、时间邻近、initiator 或静态调用关系
        OBSERVED
            在同一 EXECUTION-ID 中观察到事件、调用或结果
        ESTABLISHED
            观察结果已与上下文、生成位置和异步边绑定
            关键替代解释已被排除或单独保留
        VERIFIED
            还有当前标准、构建元数据或独立重复观察支持
        INFERRED
            由多个证据推导但没有直接暂停或调用证据
            必须与 OBSERVED 分开记录
        记录原则
            运行时结论和构建结论分别评级
            一条时间线不能自动提升算法、服务端或密钥结论
        证据模型修正
            正式证据等级仍只有 UNKNOWN、CANDIDATE、OBSERVED、ESTABLISHED、VERIFIED
            INFERRED 不是第六个或更高的证据等级
            CONCLUSION-SOURCE 单独记录 DIRECT-OBSERVATION 或 INFERENCE
            一个 INFERENCE 仍需从五级证据等级中选择置信等级

    浏览器上下文的最小模型
        CONTEXT-ID
            分析者为一个可区分执行环境建立的本地编号
            不是浏览器向页面公开的稳定 ID
        Window 上下文
            包含 Window、Document、JavaScript Realm 和页面脚本
        iframe 上下文
            有独立 Window、Document、Realm、脚本加载和事件传播范围
            同源不等于共享同一个全局对象
        Worker 上下文
            有独立全局作用域和脚本执行环境
            通过消息或端口与其他上下文通信
        Service Worker 上下文
            有独立生命周期
            可以参与 fetch、缓存和消息事件
            可能被终止后再次启动
        浏览器扩展隔离世界
            可能与页面脚本使用不同 Realm 或权限边界
            不属于本阶段内部实现追踪范围
        浏览器内部实现
            网络线程、渲染线程、原生加密实现和存储后端不直接等于页面可见调用

    上下文表的基本字段
        CONTEXT-ID：<CONTEXT-ID>
        类型：<WINDOW-IFRAME-DEDICATED-WORKER-SHARED-WORKER-SERVICE-WORKER-OTHER>
        父上下文：<PARENT-CONTEXT-ID-OR-NONE>
        Origin 状态：<SAME-ORIGIN-CROSS-ORIGIN-OPAQUE-UNKNOWN>
        URL 或脚本标识：<REDACTED-URL-OR-SOURCE-LABEL>
        BUILD-ID：<BUILD-ID>
        GENERATED-ASSET-ID：<GENERATED-ASSET-ID-OR-UNKNOWN>
        创建时间：<TIME>
        销毁或失联时间：<TIME-OR-UNKNOWN>
        是否仍可调试：<YES-NO-UNKNOWN>
        Source Map 状态：<SOURCE-MAP-STATUS>
        证据等级：<LEVEL>
        未知项：<UNKNOWNS>

    Window、Document 和 Realm
        Window
            提供页面脚本可见的窗口对象和 Web API 入口
        Document
            表示当前文档和 DOM 事件目标集合
        Realm
            提供一组独立的内置对象、全局环境和对象身份
        对象身份边界
            不同 iframe 的 Array、Promise、Error 和函数原型可能不同
            同名构造器不能只凭名称判断来自同一个 Realm
        追踪要求
            记录对象所属 CONTEXT-ID
            记录跨上下文传递是结构化复制、Transferable 还是消息引用
            不把同源对象和跨 Realm 对象合并

    iframe
        独立内容
            独立 Window
            独立 Document
            独立脚本和模块记录
            独立事件循环观察范围
            事件循环修正
                此处“独立”只表示 iframe 需要独立 CONTEXT-ID 和证据归属
                不表示每个 iframe 必然独占一个 event loop
                多个 Window 可能在同一 agent 或 agent cluster 范围共享事件循环
                是否共享不能仅凭 iframe 身份推断
        同源 iframe
            可以在授权范围内通过 DOM 或 Window 接口交互
            仍需为 iframe 单独建立 CONTEXT-ID
        跨源 iframe
            受 Same-Origin Policy 和 WindowProxy 限制
            页面脚本不能把跨源对象当作普通同源对象读取
            消息通信需要记录 origin 和 targetOrigin 约束
        资源证据
            iframe 的 HTML、JS、CSS、Source Map 和请求单独编号
            不能把顶层页面的 BUILD-ID 自动套给另一个部署
        事件证据
            事件可能在 iframe 内部触发
            父页面监听消息不等于父页面直接执行了子页面函数

    Dedicated Worker
        建立
            由页面创建独立 Worker 上下文
            Worker 脚本有自己的 asset、模块和调用栈
            创建者修正
                Dedicated Worker 也可能由允许使用 Worker 的其他 Worker 上下文创建
                统一记录 CREATOR-CONTEXT-ID，不能固定写成页面创建
        通信
            Worker 对象与 worker_global_scope 通过消息通信
            message、messageerror 和 close 等结果分别记录
            Worker 事件修正
                Worker 接口的相关标准事件包括 message、messageerror 和 error
                close 是 WorkerGlobalScope 的方法，不是标准 close 事件
                worker 内部 close()、创建侧 terminate() 和实际终止状态分别记录
        不能直接访问
            页面 DOM
            页面同步调用栈
        追踪边界
            页面创建 Worker 的调用是一个 CALL-ID
            Worker 内部处理是另一个 CONTEXT-ID
            postMessage 是 ASYNC-EDGE-ID 的候选
            创建调用修正
                “页面创建”扩展为任意已记录的 CREATOR-CONTEXT-ID 创建
        Worker 终止
            终止后原调用栈不能继续使用
            新启动的同类脚本需要新的上下文记录

    Shared Worker
        特征
            可能被多个页面上下文连接
            通过 MessagePort 区分连接方
        记录要求
            WORKER-ID
            PORT-ID
            SENDER-CONTEXT-ID
            RECEIVER-CONTEXT-ID
            连接建立和关闭时间
        限制
            不能把一个端口的消息归因到所有页面
            不能把同一脚本文本当作同一执行实例

    Service Worker
        生命周期候选
            install
            activate
            fetch
            message
            push 或其他事件（若当前环境存在）
        事件分类修正
            install 和 activate 属于生命周期事件
            fetch、message、push 属于运行或功能事件
            以上都可记录为 EVENT-ID，但不能全部称为生命周期事件
        重要边界
            Service Worker 不属于页面 Window 内存
            Service Worker 可以返回 Cache Storage 中的 Response
            Service Worker 可以合成 Response 或转发请求
            Service Worker 可能在请求之间停止并重新启动
        控制状态分层
            registration 表示已存在注册记录
            installing、waiting 和 active 表示 worker 生命周期状态
            client controller 表示当前页面是否由某个 active worker 控制
            fetch EVENT-ID 表示本次请求实际触发了 fetch 事件
            已注册或 active 不证明当前页面受控
            当前页面受控也不证明每个请求都取得了本次 fetch EVENT-ID 证据
        证据要求
            页面 fetch 调用
            Service Worker fetch 事件
            Cache Storage 操作
            网络请求或无网络响应
            Response body 读取
            分别记录时间和上下文
        禁止
            通过注销、替换或修改 Service Worker 改变观察结果
            清空缓存以制造不同分支
            强制跳过 fetch 事件

    事件循环和任务的层级
        同步调用栈
            当前 JavaScript 执行段中的函数帧
            同步返回或抛出后该栈段结束
        任务
            浏览器从某个任务源取出的可执行工作单元
            可能来自用户事件、定时器、网络、消息或其他宿主事件
            规范模型修正
                task source 决定任务进入哪个 task queue
                event loop 从选定的 task queue 取得 runnable task
                不能写成 event loop 直接从 task source 取任务
        微任务
            在微任务检查点运行的 Promise reaction、queueMicrotask 或类似工作
        渲染机会
            浏览器可能在适合的位置安排更新渲染
            具体时机不是页面脚本可完全控制的全局队列
        异步因果栈
            DevTools 可能把注册点与后续回调关联展示
            它是调试器提供的因果信息，不等于一个连续的同步栈

    任务的记录原则
        TASK-ID
            分析者为一次任务观察建立的本地编号
        任务来源
            DOM 事件
            定时器
            网络事件
            消息事件
            模块或资源事件
            其他来源
        必须记录
            来源上下文
            注册位置或 initiator
            实际开始时间
            实际结束时间
            同步调用栈
            产生的微任务
            产生的后续异步边
        不得推断
            所有任务源共享一个全局 FIFO 队列
            所有任务都能跨浏览器比较精确顺序
            任务编号是浏览器提供的永久标识

    微任务
        常见来源
            Promise reaction
            await 后续代码
            queueMicrotask
            MutationObserver 回调
        执行边界
            微任务通常在宿主规定的微任务检查点运行
            一个微任务可以继续产生新的微任务
            微任务队列过长可能延迟渲染和其他任务
        记录要求
            MICROTASK-ID
            产生它的 Promise、await 或 API
            注册位置
            实际执行位置
            是否产生新的微任务
            是否发生异常或 rejection
        重要区分
            queueMicrotask 不是 setTimeout(0)
            Promise reaction 不是当前同步栈的下一帧
            微任务顺序不能替代所有任务源的全局顺序

    事件分发
        浏览器事件
            用户输入、资源、网络或生命周期事件由宿主触发
            事件监听器通常在事件分发过程中执行
        dispatchEvent
            可以在当前同步调用栈中同步触发事件分发
            不能只凭事件名称判断其任务边界
        事件传播
            capture
            target
            bubble
        事件代理
            框架可能只在根节点或文档节点注册监听器
            业务处理可能通过内部分派器进入组件代码
        记录要求
            EVENT-ID
            target CONTEXT-ID
            target 类型
            传播阶段
            注册位置
            实际处理位置
            是否由框架代理
            后续 CALL-ID 和 ASYNC-EDGE-ID

    Promise 状态与延续
        状态
            pending
            fulfilled
            rejected
        记录内容
            Promise 创建位置
            resolve 或 reject 来源
            then、catch、finally 或 await 注册位置
            reaction 实际执行位置
            rejection 是否被处理
            是否形成 unhandled rejection
        不同阶段
            Promise 创建不等于完成
            Promise fulfilled 不等于 Body 已读
            reaction 注册不等于 reaction 已执行
            reaction 执行不等于业务函数已经返回最终值
        异步栈
            DevTools 可能显示注册点作为异步祖先
            Source Map 可能改变显示的函数名和位置
            异步栈可能被截断、合并、关闭或受优化影响
        记录字段
            ASYNC-EDGE-ID
            上游 CALL-ID 或 PAUSE-ID
            下游 reaction 位置
            Promise 状态
            DevTools 是否显示因果链
            直接证据或推断

    async/await
        await 之前
            属于当前同步执行段
            当前函数可以在 await 处挂起
        await 之后
            作为 Promise 延续执行
            通常不保留完整的普通同步调用帧
        追踪要求
            分别记录 await 前 CALL-ID
            记录 Promise 或异步 API 来源
            记录 await 后新的 CALL-ID 或暂停位置
            记录异常是在哪一段抛出
        常见误判
            把 await 后代码当作同一栈连续返回
            把异步祖先当作当前栈帧
            把同一函数名称出现两次合并成一次执行

    Promise 组合
        Promise.all
            输入项可以并发完成
            结果数组按输入顺序组织
            不能用完成顺序代替结果顺序
        Promise.race
            先完成的结果决定外层 Promise
            其他输入仍可能继续运行
            精确表述
                首个 settled 的输入决定外层 Promise
                settled 包括 fulfilled 和 rejected
        Promise.allSettled
            同时保留 fulfilled 和 rejected 的结果记录
        追踪原则
            每个子 Promise 建立独立 ASYNC-EDGE-ID
            外层 Promise 建立新的关联记录
            共享一个 STAGE-ID 不代表是同一个 Promise

    定时器和动画
        需要记录的 API
            setTimeout
            setInterval
            clearTimeout
            clearInterval
            requestAnimationFrame
            cancelAnimationFrame
        其他消息任务
            MessageChannel
            postMessage
            BroadcastChannel
            scheduler.postTask（当前浏览器支持时）
        记录字段
            TIMER-ID 或 SCHEDULER-ID
            注册位置
            计划延迟或周期
            实际回调时间
            页面可见性
            是否取消
            回调上下文
            是否发生暂停、节流或录制扰动
        限制
            setTimeout(0) 不是立即执行
            setInterval 不是固定精度时钟
            后台页面、隐藏标签页和省电策略可能节流
            requestAnimationFrame 的回调不是屏幕已经完成绘制的证明

    MessageChannel、postMessage 和 BroadcastChannel
        MessageChannel
            创建一对 MessagePort
            消息通过端口进入接收方上下文
        Window.postMessage
            可以在 Window 上下文之间发送结构化数据

            发送位置
            接收位置

            Transferable 类型
            接收者是否仍存在
        边界
            消息到达不表示接收者已完成业务处理

    fetch 追踪的阶段
        Request 形成
            method、URL、Headers、Body 和 signal 等输入对象形成
            Body 可能是字符串、ArrayBuffer、TypedArray、Blob、FormData 或流
        fetch 调用
            JavaScript 创建 fetch Promise
            记录调用位置和当前 CONTEXT-ID
        Service Worker 或缓存处理
            请求可能被 Service Worker 事件接收
            可能直接命中 HTTP cache 或其他浏览器缓存
        网络或合成响应
            可能发生实际网络请求
            也可能由 Service Worker 或缓存返回 Response
        Response headers 可用
            fetch Promise 通常在 Response 可用时 fulfilled
            不等于 Body 已完整取得或读取
        Response body 读取
            json、text、arrayBuffer、blob 或流读取形成后续异步边
        Promise 延续
            解析、业务判断、错误处理和下一次 API 调用分别记录

    fetch 的关键边界
        fetch Promise fulfilled
            通常表示响应对象可用
            HTTP 404 或 500 仍可能得到 fulfilled 的 Response
            需要单独记录 response.ok、status 和业务错误
        Body 读取
            response.json() 可能在解析阶段失败
            response.arrayBuffer() 可能在读取阶段失败
            Body 只能按其锁定和消费状态使用
            一次读取失败不自动等于请求没有发送
        AbortController
            signal 可能在请求或读取过程中触发取消
            Promise 可能以 AbortError 拒绝
            取消时间和请求失败时间分开记录
        缓存
            缓存命中时可能没有网络往返
            Network 面板显示和页面 Promise 时间线必须分开
        Service Worker
            可以返回缓存 Response
            可以合成 Response
            可以转发到网络
            可以在页面请求前后改变可见路径
        CORS
            浏览器可能阻止脚本读取 Response
            脚本可见失败不等于服务器没有收到请求
            失败路径修正
                CORS check 失败在 Fetch 层形成 network error
                fetch Promise 通常以 TypeError rejected，脚本不能取得该 Response
                mode 为 no-cors 时得到 opaque Response 属于另一条受限路径
                仅凭 TypeError rejection 不能区分 DNS、TLS、CORS 或其他 network error

    fetch、XHR 与 Network 的连接
        JavaScript 调用位置
            记录 fetch、open、send 或其他页面 API 调用
        浏览器请求记录
            记录 Request、响应、Timing、Initiator 和缓存状态
        Service Worker
            记录 fetch 事件和返回 Response 的来源
        预检
            CORS 预检可能由浏览器自动发起
            不一定存在对应的页面 fetch 调用
            预检结果修正
                预检失败会阻止对应的实际 CORS 请求继续发送
                无需预检的请求可能已经发送后才因响应 CORS check 失败
                已通过预检的实际请求也可能已经到达服务器
                Promise rejection 不能单独证明实际请求是否发送
        重定向
            最终请求可能与初始 Request 的 URL、方法或凭据状态不同
            每个可观察请求建立独立 REQUEST-OBSERVED-ID 或关联链
        失败和取消
            DNS、连接、TLS、CORS、HTTP、解析、Abort 和超时分别记录
        缓存分层
            HTTP cache fresh hit 可以没有网络往返
            HTTP cache revalidation 会发送条件请求，并可能收到 304
            脚本最终使用的缓存表示与 304 网络响应分别记录
            Cache Storage 是显式 Web API 存储，不等于 HTTP cache
            Service Worker 可以选择 Cache Storage、HTTP cache 或网络路径
        结论边界
            网络请求出现不等于业务逻辑成功
            业务逻辑执行不等于服务器已收到请求
            Network 解析视图不等于原始签名输入字节

    Web Crypto 的同步与异步边界
        subtle 方法
            通常返回 Promise
            需要记录调用时刻和 Promise 延续
        getRandomValues
            同步填充给定的 TypedArray
            需要记录视图类型、byteOffset 和 byteLength
            不把随机源内部实现写成页面可直接证明的线程行为
            输入限制修正
                只接受整数型 TypedArray，不接受任意 TypedArray
                视图 byteLength 超过 65536 时抛出 QuotaExceededError
                记录异常时仍不得重新调用以探测边界
        randomUUID
            同步返回字符串
            不等于签名、摘要或会话认证
        CryptoKey
            是受保护的密钥对象
            只记录已可见的非秘密元数据
            不调用 exportKey 尝试取得密钥材料
            结构化复制边界
                CryptoKey 可以按规范结构化序列化并保持 CryptoKey 类型
                结构化复制不等于导出密钥材料
                extractable 为 false 仍不应被解释为不可复制
        Promise rejection
            算法不支持
            参数类型错误
            key usage 不匹配
            密钥类型不匹配
            不安全上下文
            不可导出的 CryptoKey
            这些失败分别记录
        错误分类修正
            不安全上下文通常影响 API 是否暴露或可用，不能统一写成每次 subtle 调用的 rejection
            不可导出主要影响 exportKey、wrapKey 或其他需要取得密钥材料的操作
            extractable 为 false 不妨碍满足 key usages 的 sign、verify、encrypt 或 decrypt 等操作
            Web IDL 参数转换可能同步抛出异常，算法步骤也可能返回 rejected Promise
            每个具体操作分别记录同步异常、Promise rejection 和 DOMException 名称
            Promise-returning 操作再修正
                SubtleCrypto 的 Promise-returning 方法把绑定、转换或算法执行中的异常反映为 rejected Promise
                getRandomValues、randomUUID 等同步 Crypto 方法的异常另栏记录
                页面代码在进入 Web Crypto API 之前产生的同步异常也必须单独归类
                不能把 SubtleCrypto 参数转换普遍写成调用者可见的同步 throw

    Web Crypto 算法参数边界
        digest
            没有密钥参数
            不能仅凭 API 名称称为 HMAC 或数字签名
        sign
            需要同时记录算法、密钥类型、key usages 和输入字节
            输出格式不能凭经验假定为 DER、裸连接或固定长度
        verify
            true 或 false 是验证结果
            不等于页面已经生成签名
        AES-GCM
            iv、additionalData、tagLength 等参数必须分别记录
            不把 iv 自动称为密钥或签名
        ECDSA、RSA 或其他算法
            参数结构和输出编码受 Web Crypto 规范及实现影响
            不以常见库默认值替代实际观察
            输出格式修正
                已知 Web Crypto 算法的输出格式由对应规范算法规定
                先依据实际算法和参数查当前规范，再解释输出字节
                实现差异只能作为兼容性异常另行取证，不能当作常态
        deriveKey、deriveBits
            记录派生目标、长度、salt、info 或等效参数类别
            不记录秘密材料

        业务输入
            记录来源类别和脱敏摘要
            秘密处理修正
                只有原执行已产生且获准记录的非秘密摘要才可引用
                不为脱敏而额外读取、复制或散列秘密输入
                无可用安全证据时记录 NOT-READ 或 NOT-STORED
        字节视图
            记录类型、offset、length 和编码来源
        Crypto API 调用
            记录 CRYPTO-OP-ID 和同步调用栈
        Promise 延续
            记录 ASYNC-EDGE-ID、完成状态和后续调用
        输出封装
            记录编码、截断、拼接或字段放置
        请求关联
            通过同一 EXECUTION-ID 连接到 REQUEST-OBSERVED-ID
        不能跨执行拼接
            一个执行的 Crypto 输出不能与另一个执行的请求字段直接合并

    Web Crypto 观察限制
        可以观察
            已在调用栈或 DevTools 对象预览中出现的安全元数据
            API 名称和非秘密算法参数
            输入输出类型和长度
            Promise 状态和错误类别
        不可以做
            调用 exportKey 获取秘密
            修改 extractable 或 key usages
            替换 CryptoKey
            重放 sign、encrypt 或 derive 调用
            把输出复制到新请求中
        结论
            CryptoKey 不可见不表示没有密钥
            页面可见参数不一定包含底层实现的全部内部状态

    起点选择
        UI 事件起点
            适合追踪用户动作到业务处理
        请求断点起点
            适合从 fetch/XHR 回溯请求构造
        Crypto 调用起点
            适合连接字节输入、Promise 和输出封装
        Storage 操作起点
            适合查状态来源和异步事务
        动态模块起点
            适合区分装载、求值和调用
        选择原则
            优先使用已经在前几章建立的 CALL-ID
            不为找到起点添加新代码
            起点不是因果链起源的证明

    观察窗口
        开始前
            记录页面、frame、Worker、Service Worker 和缓存的当前状态
            只做快照，不清理状态
        操作中
            记录事件、同步栈和异步边
        操作后
            记录网络、Storage、模块和框架状态变化
        多次正常观察
            每次建立新的 EXECUTION-ID
            只比较结构和顺序
            不拼接具体值
        时间扰动
            断点暂停和 Performance 录制分别标记
            不用被暂停放大的时间差证明页面正常行为

    同步栈记录步骤
        当前帧
            生成位置
            Source Map 状态
            CONTEXT-ID
            this 类别
            参数类型和长度
        调用者
            逐帧记录 CALL-ID
            标记框架、runtime、业务或 Web API 包装层
        异步祖先
            单独列出
            不加入同步帧编号
        返回后
            同步栈消失
            后续工作使用 ASYNC-EDGE-ID 连接

    异步边记录步骤
        确定注册点
            then、await、timer、event、message、network、storage 或 module
        确定下游触发
            callback、reaction、event handler 或 module completion
        确定上下文
            发送端与接收端是否相同
        确定时间
            注册、触发和完成分别记录
        确定证据
            DevTools Async Stack
            暂停位置
            Network initiator
            Message 或 Promise 身份候选
        无法直接证明
            标记 INFERRED
            保留替代解释

    请求追踪步骤
        调用前
            记录 Request 或 XHR 对象形成位置
        调用时
            记录 method、脱敏 URL 结构、Header 名称和 Body 类型
        浏览器处理
            记录 Service Worker、缓存、预检和重定向
        响应
            记录 headers 可用时间
        Body
            记录读取方法的原始页面调用
            不在控制台额外读取
        业务延续
            记录解析、错误和下一次 CALL-ID
        网络关联
            使用 CAPTURE-ID 和 REQUEST-OBSERVED-ID

    Crypto 追踪步骤
        上游
            记录字符串到字节的编码位置
        调用
            记录 API、算法参数、CryptoKey 元数据和 BufferSource 范围
        异步完成
            记录 Promise 状态和 ASYNC-EDGE-ID
        下游
            记录输出编码、截断、拼接和请求放置
        安全
            不导出密钥
            不复制输入输出秘密
            不重新调用原语

    Storage 追踪步骤
        识别类型
            localStorage、sessionStorage、IndexedDB、Cache Storage、Cookie 或内存
        记录上下文
            origin、frame、Worker 和分区状态
        记录操作
            读取、写入、删除、事务、事件或快照
        记录结果
            同步返回、Promise、IDBRequest 或 transaction 事件
        关联业务
            值进入哪个 CALL-ID、STAGE-ID 或请求
        安全
            不额外读取秘密
            不修改或清空数据

    动态模块追踪步骤
        说明符或 runtime 请求
            记录生成位置
        chunk 或模块取得
            记录 Network 和 cache
        注册或实例化
            记录 runtime 或浏览器 ESM 层
        求值
            记录 MODULE-EVAL-ID
        import Promise
            记录 fulfilled 或 rejected
        导出调用
            只有实际调用才建立 CALL-ID
        结论
            六个阶段不合并

    框架调度追踪步骤
        识别框架和版本
        识别事件代理入口
        标记 scheduler、render、commit 和 effect 候选
        找到业务 handler
        记录状态更新和请求触发的相对阶段
        区分开发模式重复执行
        与生产 BUILD-ID 分开

    证据冲突处理
        Network 显示请求但没有页面调用栈
            检查资源加载、Service Worker、sendBeacon、导航和 Worker
        页面调用 fetch 但没有网络往返
            检查缓存、Service Worker、取消和 CORS
        Crypto 调用完成但请求字段未出现
            检查输出封装、缓存、错误分支和另一次请求
        Storage 有值但本次没有读取
            快照不证明本次使用
        动态 chunk 已下载但函数未调用
            区分预加载、模块求值和业务调用
        Async Stack 与调用时序矛盾
            记录 DevTools 合成信息和实际暂停时间
        处理原则
            不强行选择一种解释
            保留冲突证据和 UNKNOWN

    必须保留的替代解释
        Promise 调度而不是同步返回
        浏览器缓存而不是网络服务器
        Service Worker Response 而不是服务器 Response
        CORS 可见性失败而不是请求未发送
        事件代理而不是组件自身监听器
        框架批处理而不是重复业务调用
        开发模式检查而不是生产重复执行
        Worker 重启而不是普通调用栈丢失
        Worker 重启用词修正
            Service Worker 可以被终止后按后续事件重新启动
            Dedicated Worker 或 Shared Worker 终止后需要新建实例，不能称为同一实例自动重启
        预加载而不是业务提前执行
        模块缓存而不是代码没有加载
        定时器节流而不是随机延迟
        DevTools 暂停造成时间变化
        Performance 录制造成额外开销
        浏览器隐私分区而不是 Storage API 失效
        CryptoKey 不可见而不是没有密钥
        Source Map 或 Async Stack 的调试器合成信息
        错误恢复、重试或取消而不是算法分支

    常见错误
        把“JavaScript 单线程”写成“整个浏览器只有一个线程或事件循环”
            问题
                Window、Worker 和浏览器内部执行范围不同
            修正
                每个可观察上下文建立 CONTEXT-ID
        把所有事件监听器回调写成独立任务
            问题
                dispatchEvent 可以同步分发
            修正
                记录事件来源和当前同步栈
        把 Promise 延续当作同步调用栈
            问题
                reaction 在微任务检查点执行
            修正
                使用 ASYNC-EDGE-ID
        把微任务顺序当作所有任务源的全局顺序
            问题
                宿主任务源和渲染调度有独立规则
            修正
                只记录本次观察的局部时间线
        把 setTimeout(0) 当成立即执行
            问题
                回调仍需等待任务调度和最小延迟规则
            修正
                记录注册与实际回调时间
        把 fetch fulfilled 当作 Body 已完整读取
            问题
                Response 和 Body 读取是不同阶段
            修正
                分别记录 headers 和 Body Promise
        把 response.json 失败归因于网络请求失败
            问题
                JSON 解析可在请求成功后失败
            修正
                记录失败阶段
        把 HTTP 404 或 500 当作 fetch Promise 必然 rejected
            问题
                fetch 通常仍提供 Response
            修正
                分开记录网络错误、HTTP 状态和业务错误
        把缓存命中当作服务器本次响应
            问题
                可能没有网络往返
            修正
                记录 cache 和 Service Worker 状态
        把 Service Worker Response 当页面 fetch 直接返回
            问题
                中间有独立上下文和 fetch 事件
            修正
                建立 Service Worker CONTEXT-ID
        把 CORS 预检当作页面代码直接调用
            问题
                浏览器可以自动发起
            修正
                用 initiator 和请求类型区分
        把 XHR readyState 常见顺序写成所有场景保证
            问题
                abort、timeout、错误和缓存会改变观察
            修正
                记录实际事件序列
        把 Web Crypto API 名称当完整算法规范
            问题
                参数、密钥和输入输出仍未知
            修正
                使用 CRYPTO-OP-ID 参数表
        把 CryptoKey 当普通可序列化对象
            问题
                密钥材料受 extractable 和 API 限制
            修正
                只记录非秘密元数据
            事实修正
                CryptoKey 在 Web Crypto 规范中是 serializable
                它可以经结构化序列化传递，也可以存入 IndexedDB
                克隆结果仍是 CryptoKey，不是普通 JSON 键值对象
                extractable 为 false 限制密钥材料导出，不等于禁止结构化复制
                真正的错误是把结构化复制等同于导出秘密密钥材料
        把 getRandomValues 当 Promise API
            问题
                它同步填充 TypedArray
            修正
                记录同步调用和视图范围
                还必须确认它是整数型 TypedArray 且 byteLength 不超过 65536
        把 localStorage、IndexedDB、Cache Storage 和 Cookie 混为一谈
            问题
                同步性、事务、可见性和生命周期不同
            修正
                每类独立 STORAGE-OP-ID
        把 storage 事件写成源文档同步事件
            问题
                事件通常面向其他相关文档
            修正
                记录发送和接收上下文
        把同源 iframe 当成同一 Realm
            问题
                两个 Window 仍有独立全局对象
            修正
                分别建立 CONTEXT-ID
        把 postMessage 写成对象引用共享
            问题
                通常使用结构化复制或 Transferable
            修正
                记录复制和转移语义
        把跨源消息的 origin 校验写成字符串包含
            问题
                origin 比较有明确结构
            修正
                记录 targetOrigin 和 event.origin
        把 Worker 内部线程实现当作页面可证明事实
            问题
                页面只能观察 API 和消息边界
            修正
                内部实现写 UNKNOWN
        把 chunk 下载当作 module evaluation
            问题
                还有注册、实例化和求值阶段
            修正
                使用 MODULE-EVAL-ID
        把 dynamic import Promise 完成当作导出函数执行
            问题
                namespace 可用后函数仍可能未调用
            修正
                只有实际调用才建立 CALL-ID
        把框架调度函数当业务签名函数
            问题
                scheduler、render 和 effect 是框架层
            修正
                标记框架层后继续追踪业务 handler
        把开发模式重复执行当服务器重复请求
            问题
                重复 render 不保证重复 Network
            修正
                分别统计 CALL-ID 和 REQUEST-OBSERVED-ID
        在控制台调用 getter、Proxy、Body 或 CryptoKey 方法
            问题
                会产生副作用或秘密读取
            修正
                只读已物化原始值和安全元数据
        用 DevTools 暂停后的延迟证明页面原本超时
            问题
                暂停本身改变时间
            修正
                标记时间扰动并保留替代解释
        跨 BUILD-ID、CONTEXT-ID 或 EXECUTION-ID 拼接具体值
            问题
                对象、状态和分支身份不同
            修正
                每次执行独立记录
        把 TASK-ID 写成浏览器稳定 ID
            问题
                本章 ID 是分析者本地编号
            修正
                在表中标明 LOCAL-ID
        为获得更多信息添加 Hook、日志、补丁或请求重放
            问题
                改变了原运行时和证据
            修正
                只使用被动 DevTools 观察

        上下文
            顶层页面、iframe、Worker 和 Service Worker 已建立 CONTEXT-ID
            每个上下文已绑定 BUILD-ID 和 asset 证据
        时间线
            同步栈、任务、微任务和异步因果边已分开
            TASK-ID 和 MICROTASK-ID 明确为本地编号
        事件

            未修改请求、运行时、源代码、Storage 或缓存

    本阶段验收
        能说明
            同步调用栈、任务、微任务和异步因果栈的区别
            dispatchEvent 为什么不自动形成新任务
            Promise fulfilled 为什么不等于所有后续工作完成
            await 前后为什么需要 ASYNC-EDGE-ID
            setTimeout(0) 为什么不是立即执行
            iframe、Worker 和 Service Worker 为什么需要独立 CONTEXT-ID
            fetch fulfilled 为什么不等于 Body 已读完
            Network 请求为什么不等于 JavaScript Promise 时间线
            Service Worker 和缓存为什么会改变请求证据
            XHR readyState、事件和 response 读取为什么分别记录
            Web Crypto 操作为什么需要参数、密钥模型、输入字节和 Promise 状态
            getRandomValues 为什么不是 Promise API
            localStorage、IndexedDB、Cache Storage 和 Cookie 的主要边界
            structured clone 与 Transferable 为什么改变对象身份判断
            dynamic import 的装载、求值、Promise 和导出调用为什么不能合并
            框架事件代理、批处理和开发模式重复执行为什么不能直接当业务调用
            Call Stack 与 Async Stack 为什么必须分栏
            DevTools 暂停和 Performance 录制为什么需要标记时间扰动

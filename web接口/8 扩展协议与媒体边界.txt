Web API 加密逻辑分析
    第 8 阶段：扩展协议与媒体边界

    学习目标
        能区分网络传输、HTTP 消息、内容编码、应用分帧、序列化、业务语义和密码学处理
        能说明浏览器可见的流块为什么不等于 TCP、QUIC、HTTP/2 或 HTTP/3 帧
        能区分 WebSocket 握手、连接、消息、协议帧和应用层记录
        能区分 Server-Sent Events、普通流式响应和轮询
        能识别 NDJSON、JSON Text Sequences、Protocol Buffers、CBOR、MessagePack 和自定义二进制候选
        能区分 GraphQL 操作、HTTP 传输、持久化查询标识和订阅传输
        能区分 gRPC-Web 的消息记录、trailers、压缩标志和业务载荷
        能说明 Range、206、Content-Range 和 multipart/byteranges 的证据边界
        能区分 HTMLMediaElement、媒体清单、媒体分段、容器、codec、MSE 和 EME
        能说明 HLS、DASH、MSE 和 DRM 为什么处于不同层
        能识别加密媒体边界，但不读取许可证消息、密钥材料或加密媒体内容
        能把第 7 阶段的上下文、异步边和 API 操作映射到协议消息与媒体状态
        能形成不包含真实目标、秘密值、媒体内容或绕过步骤的协议记录

    本阶段不学习
        不提供真实站点、靶场、练习或实战任务
        不使用抓包代理、MITM、TLS key log、证书替换或 HTTPS 解密
        不使用 Wireshark、tshark、tcpdump、mitmproxy、Burp 或 Scapy 捕获真实目标流量
        不主动构造、注入、修改、模糊测试、重放或发送协议消息
        不重新连接 WebSocket、EventSource、WebTransport、WebRTC 或媒体会话进行探测
        不调用页面未调用的解析器、解码器、解压器或媒体 API
        不批量导出 WebSocket 消息、流式 Body、二进制载荷、清单或媒体分段
        不保存未脱敏的 URL、Header、Cookie、Token、消息或查询变量
        不读取、保存、解析、修改或重放许可证请求和许可证响应
        不提取、导出、猜测、派生或传播内容密钥、会话密钥和 DRM 标识材料
        不解密、拼接、下载或导出付费媒体、加密媒体和受 DRM 保护的内容
        不修改 MediaKeys、MediaKeySession、CDM、SourceBuffer、MediaSource 或播放器状态
        不绕过认证、授权、签名 URL、地域限制、付费限制、媒体加密或 DRM
        不进入第 9 阶段的最终报告与独立验证

    skill 使用边界
        protocol-reverse-engineering
            只采用协议分层、边界识别、字段记录和状态机文档方法
            不采用抓包、MITM、TLS 解密、主动测试、fuzzing、生成器或重放方法
        hads
            只采用事实、推断、未知和错误条件分开的组织原则
            文件仍严格沿用 note 文件夹的纯文本缩进风格

    版本和规范状态
        WebSocket
            按当前 WHATWG WebSockets 标准和实际浏览器版本记录
        Server-Sent Events
            按当前 WHATWG HTML Server-sent events 章节记录
        Streams
            按当前 WHATWG Streams 和 Fetch 标准记录
        HTTP
            按 RFC 9110、RFC 9112、RFC 9113 和 RFC 9114 的对应层记录
        GraphQL over HTTP
            当前仍需绑定 GraphQL over HTTP 文档版本和媒体类型
            不能把 draft 行为写成所有服务实现保证
        HLS
            RFC 8216 是 2017 年 Informational 基线
            当前 Apple HLS 和 Low-Latency HLS 扩展必须另记版本
        DASH
            本章只使用已核对的 DASH-IF 或 ISO 文档事实
            未核对的 MPD 扩展保持 UNKNOWN
        MSE
            按当前 Media Source Extensions 规范和浏览器实现记录
        EME
            按当前 Encrypted Media Extensions 规范记录接口边界
            CDM、key system 和许可证协议的实现细节保持 UNKNOWN
        版本原则
            协议名称不等于协议版本
            MIME、文件后缀或 API 名称不能替代版本证据
            浏览器和 DevTools 的显示层会隐藏底层分帧细节

    证据等级与来源
        正式证据等级
            UNKNOWN
            CANDIDATE
            OBSERVED
            ESTABLISHED
            VERIFIED
        结论来源
            DIRECT-OBSERVATION
            STANDARD
            BUILD-METADATA
            INFERENCE
        记录原则
            INFERENCE 不是独立的第六级证据等级
            标准规定和本次运行观察分别记录
            协议字段存在不自动证明业务语义
            浏览器隐藏的底层帧保持 NOT-EXPOSED 或 UNKNOWN

    本章证据实体
        PROTOCOL-TRACE-ID
            表示一个 RUNTIME-TRACE-ID 内的协议层分析记录
        CHANNEL-ID
            表示 WebSocket、EventSource、WebTransport、WebRTC 或其他长连接通道的本地编号
        HTTP-REPRESENTATION-ID
            表示一份 HTTP 表示及其元数据的本地编号
        BODY-STREAM-ID
            表示一个 Fetch Body ReadableStream 的本地编号
        STREAM-CHUNK-ID
            表示 JavaScript 层一次流读取结果的本地编号
            不是 TCP、QUIC 或 HTTP 帧编号
        WS-MESSAGE-ID
            表示浏览器 WebSocket API 交付的一条完整消息
        SSE-EVENT-ID
            表示 EventSource 解析后分发的一次事件
        SERIALIZATION-ID
            表示一项序列化格式分类记录
        APPLICATION-RECORD-ID
            表示应用层在流或消息内定义的一条逻辑记录
        GRAPHQL-OP-ID
            表示一次 GraphQL 操作观察
        GRPC-WEB-RECORD-ID
            表示一个 gRPC-Web 消息或 trailers 记录候选
        RANGE-REQUEST-ID
            表示一次带 Range 或 Content-Range 关系的 HTTP 请求记录
        MEDIA-SESSION-ID
            表示一个媒体元素和相关加载路径的本地分析会话
        MANIFEST-ID
            表示一份媒体清单候选
        REPRESENTATION-ID
            表示一个清单中的码率、codec 或轨道表示候选
        MEDIA-SEGMENT-ID
            表示一个媒体分段或字节范围候选
        MEDIA-SOURCE-LOCAL-ID
            表示一个 MediaSource 实例
        SOURCE-BUFFER-LOCAL-ID
            表示一个 SourceBuffer 实例
        MEDIA-KEY-SESSION-LOCAL-ID
            表示一个 MediaKeySession 的本地编号
            不保存实际 sessionId
        EME-MESSAGE-METADATA-ID
            只记录 EME 消息类型、长度和状态
            不读取或保存消息字节
        所有 ID
            都是分析者本地编号
            必须绑定 BUILD-ID、EXECUTION-ID、CONTEXT-ID 和时间

    协议分层总模型
        网络路径层
            IP、TCP、UDP、QUIC 和路由
            浏览器页面通常不直接看到原始包或连接密钥
        传输安全层
            TLS、DTLS 或 QUIC 内建加密
            页面看到安全通道结果，不看到会话密钥
        HTTP 语义层
            method、status、Header、representation 和缓存语义
        HTTP 分帧层
            HTTP/1.1 message framing
            HTTP/2 frame 和 stream
            HTTP/3 frame 和 QUIC stream
            DevTools 通常将这些抽象为请求和响应
        内容编码层
            gzip、br、deflate 或其他 Content-Encoding
        应用分帧层
            长度前缀、分隔符、事件、WebSocket 消息或自定义记录
        序列化层
            JSON、Protocol Buffers、CBOR、MessagePack 或其他格式
        业务语义层
            operation、event、command、response、error 和状态
        应用密码学层
            Hash、MAC、数字签名、应用加密和输出封装
        媒体清单层
            HLS playlist、DASH MPD 或自定义清单
        媒体容器层
            ISO BMFF、MPEG-TS、WebM 或其他容器
        codec 层
            音频、视频和字幕编码
        媒体加密与 DRM 层
            加密样本、initData、key system、CDM 和许可证状态
        核心原则
            每一层单独建立证据
            相邻层使用同一种字节外观也不能合并

    浏览器可见边界
        Network 面板
            通常显示请求、响应、Header、Timing、缓存和部分消息视图
            不等于原始 TCP、QUIC、TLS 或 HTTP/2 frame capture
        JavaScript API
            Fetch 提供 Response 和 ReadableStream
            WebSocket 提供 message 事件
            EventSource 提供解析后的事件
            MediaSource 接收应用提供的媒体字节
            EME 提供 key system 会话接口
        DevTools 限制
            显示的 WebSocket 项通常是消息视图，不保证是原始协议帧
            显示的流块不保证对应网络包
            显示的 Body 可能已解压或经过字符解码
        本章限制
            不使用外部抓包补齐浏览器不可见层
            不导出原始消息或媒体字节

    五种边界不能混写
        网络包边界
            TCP segment、UDP datagram 或 QUIC packet
        HTTP frame 边界
            HTTP/2 或 HTTP/3 内部协议帧
        Fetch stream chunk 边界
            ReadableStream reader 的一次读取结果
        WebSocket message 边界
            浏览器完成协议重组后交付的一次 message 事件
        application record 边界
            应用在消息或流内定义的逻辑记录
        结论
            任意两者都可能一对多或多对一
            只看到长度相等不能证明边界相同

    HTTP representation
        表示元数据
            Content-Type
            Content-Encoding
            Content-Language
            Content-Length
            validators
            range metadata
        表示数据
            由媒体类型定义语义
            可能再经过内容编码
        记录要求
            request 和 response 分开
            Header 原始显示和 JavaScript 可见值分开
            编码前后长度分开
            缓存和重新验证状态分开

    Content-Type
        作用
            声明 representation data 的媒体类型和参数
        常见参数
            charset
            boundary
            profile 或其他协议参数
        不能证明
            Body 一定符合声明格式
            Body 未加密
            服务端业务成功
            文件后缀正确
        记录原则
            声明值记 DECLARED
            实际解析行为记 OBSERVED
            不一致时两者同时保留

    Content-Encoding
        作用
            表示对 representation data 应用的内容编码
        常见候选
            gzip
            br
            deflate
            identity 或未设置
        与序列化的区别
            JSON 或 protobuf 是表示格式
            gzip 或 br 是内容编码
        与加密的区别
            压缩不提供秘密性或认证
            高熵不能单独区分压缩、加密或随机数据
        浏览器边界
            Fetch Body 通常暴露内容解码后的数据
            Network 面板可能同时显示 transferred size 和 resource size
            必须记录浏览器与面板口径

    Transfer-Encoding 与 HTTP 版本
        HTTP/1.1
            message framing 可以使用 Content-Length、连接关闭或 chunked transfer coding
        HTTP/2
            使用二进制 frame 和 stream
            不使用 HTTP/1.1 chunked 语法表达 Body 边界
        HTTP/3
            在 QUIC stream 上使用 HTTP/3 frame
            不使用 HTTP/1.1 chunked 语法
        重要区分
            Transfer-Encoding 不等于 Content-Encoding
            HTTP/2 DATA frame 不等于 Fetch stream chunk
            QUIC stream 不等于 JavaScript ReadableStream
        DevTools
            Protocol 列只能作为协商结果证据
            页面 JavaScript 通常不能读取底层 frame 序列

    Content-Length
        表示
            当前 HTTP message content 的字节长度语义
        不能直接等于
            JavaScript 字符串 length
            解压后 Body byteLength
            媒体播放时长
            WebSocket message 长度
        记录要求
            Content-Encoding
            HTTP 版本
            transferred size
            decoded 或 resource size
            JavaScript 实际读取长度
        冲突处理
            长度不同先检查压缩、缓存、重定向、Range 和 DevTools 口径

    HTTP/2 与 HTTP/3 多路复用
        stream
            多个请求可以共享一个连接并使用不同 stream
        顺序
            单一连接的请求显示顺序不等于应用业务依赖顺序
        Header 压缩
            HTTP/2 使用 HPACK
            HTTP/3 使用 QPACK
            这不是业务 Body 加密
        优先级和调度
            浏览器与服务器可能调整传输顺序
            页面不能从完成顺序反推完整网络调度
        证据边界
            不记录底层 stream id，除非 DevTools 明确显示且仅作为本地元数据
            不把连接复用当作会话认证

    Fetch Body stream
        Response.body
            是 ReadableStream 候选
            reader 每次读取产生 JavaScript 层 chunk
        chunk 边界
            受网络、解压、浏览器缓冲和流实现影响
            不保证与服务器 write、HTTP frame 或应用消息对应
        结束
            done 表示该 reader 观察到流结束
            不自动表示业务记录完整或解析成功
        错误
            网络错误
            解码错误
            abort
            consumer 取消
            应用解析错误
            分别记录
        安全边界
            不在暂停时额外读取 stream
            不调用 tee、clone 或新 reader 复制 Body

    文本流的解码边界
        字节到文本
            字符可能跨 STREAM-CHUNK-ID 边界
            UTF-8 多字节序列可能跨读取结果
        行边界
            CR、LF 或 CRLF 可能跨 chunk
        JSON 边界
            一个 JSON 文本可能跨多个 chunk
            一个 chunk 也可能含多个记录
        decoder 状态
            流式 TextDecoder 可能保留未完成字节
            不记录 decoder 内部实现
        结论
            不能对每个 chunk 独立 decode 后拼接并宣称等价

    NDJSON 与 JSON Text Sequences
        NDJSON 候选
            通常以换行分隔 JSON 文本
            具体空行、错误恢复和 MIME 取决于实现或文档
        JSON Text Sequences
            RFC 7464 使用 Record Separator 建立记录边界
        普通 JSON
            不能仅因响应分块就称为 NDJSON
        记录要求
            分隔规则
            字符编码
            空记录行为
            错误恢复
            MIME 和协议版本
        安全
            不保存完整业务记录
            只记录类型、长度和字段名称类别

    压缩、加密和随机数据
        压缩候选
            Content-Encoding
            WebSocket extension
            应用记录中的压缩标志
        加密候选
            TLS 或 QUIC 通道
            应用加密字段
            媒体加密样本
        随机候选
            nonce
            padding
            opaque identifier
        禁止按外观分类
            高熵不是加密证明
            固定块长度不是 AES 证明
            Base64 不是加密证明
            gzip magic 只证明候选格式，不证明业务语义
        证据
            声明字段
            实际 API
            已知规范
            同一执行中的输入输出关系

    WebSocket 的三层模型
        WebSocket API
            页面使用 WebSocket 对象和 open、message、error、close 事件
        WebSocket 协议
            定义握手、frame、message、控制帧、关闭和扩展
        应用子协议
            定义 message 内部的业务记录和状态机
        不能合并
            WebSocket 连接成功不等于应用认证成功
            WebSocket frame 不等于应用 record
            WebSocket message 不等于 JSON 对象

    WebSocket 握手
        经典 RFC 6455 路径
            通常经 HTTP/1.1 Upgrade
            成功切换使用 101 状态
        HTTP/2 和 HTTP/3
            可以通过扩展 CONNECT 机制承载 WebSocket
            不能把 Upgrade 和 101 写成所有 WebSocket 的固定事实
        浏览器 API
            页面通常只观察连接事件和 selected protocol
            DevTools 可能显示握手请求与响应
            页面不能直接控制所有握手 Header
        认证边界
            Cookie、Authorization、查询参数或应用首条消息可能承载认证状态
            握手成功本身不证明业务授权
        安全边界
            不复制握手 Cookie、Token、签名 URL 或响应 Header

    WebSocket URL 与安全通道
        ws
            不表示 TLS 保护
        wss
            表示 WebSocket 经安全传输通道
        不能推断
            wss 自动提供应用消息签名
            TLS 身份等于业务用户身份
            查询参数可公开保存
        记录
            scheme
            origin 类别
            host 和 path 脱敏结构
            实际协议版本证据
            不保存 query secret

    WebSocket 子协议和扩展
        Sec-WebSocket-Protocol
            协商应用子协议名称
            不表示加密算法
            不表示认证已经完成
        extensions
            可以协商 WebSocket 协议扩展
        permessage-deflate
            是消息压缩扩展候选
            不是加密、签名或 TLS
            压缩上下文参数需要按协商结果记录
        版本敏感
            子协议状态机由应用或独立规范定义
            同名子协议也需要记录版本

    WebSocket frame 与 message
        message
            一条应用数据消息可以是 text 或 binary
        fragmentation
            一条 message 可以由多个 data frame 构成
            控制帧可以插入 fragmented message 之间
        浏览器交付
            message 事件通常交付重组后的完整消息
            JavaScript WebSocket API 不暴露原始 frame 边界
        结论
            不能给每个 message 事件虚构一个原始 frame
            DevTools 一行消息也不必等于单一网络 frame
            frame 长度、message 长度和应用 record 长度分别记录

    WebSocket control frame
        候选
            close
            ping
            pong
        浏览器边界
            JavaScript WebSocket API 不直接暴露 ping 和 pong frame
            close 通过 close 事件和状态观察
        禁止
            为测量连接主动发送 ping 替代消息
            构造 control frame
            修改 close code 或 reason

    WebSocket masking
        RFC 6455 经典协议
            client-to-server frame 使用 masking
            server-to-client frame 不使用 masking
        masking 的作用边界
            不是加密
            不提供秘密性
            不提供服务器认证
            不等于应用签名
        浏览器边界
            JavaScript 不获得 mask key
            不从消息外观推断 mask key

    WebSocket message 数据类型
        text message
            message event 的 data 为字符串候选
            协议 text message 使用 UTF-8 语义
        binary message
            data 可为 Blob 或 ArrayBuffer
            由 binaryType 和浏览器 API 状态决定
        应用层
            binary 仍可能是 protobuf、CBOR、压缩记录、加密记录或媒体数据
            需要 SERIALIZATION-ID
        安全
            不保存完整 data
            只记录类型、byteLength 和字段类别

    WebSocket 发送与背压
        send

    HTTP Range 请求
        Range
            是 HTTP 的可选请求能力
            RFC 9110 的 Range 处理语义针对 GET
        bytes range unit
            偏移从 0 开始
            首尾位置都包含在范围内
        server 行为
            可以忽略 Range 并返回 200
            满足范围时通常返回 206
            不可满足时通常返回 416
        Content-Encoding
            byte range 针对所选表示的编码后字节序列
            不自动对应 Fetch 解码后的 offset
        结论
            Range 只证明 HTTP 表示的部分选择
            不证明 HLS、DASH、MSE、媒体加密或 DRM

    单范围和多范围
        单范围 206
            使用 Content-Range 描述返回范围
        多范围
            可以使用 multipart/byteranges
            每个 part 有自己的 Content-Range
        suffix range
            表示表示数据末尾的字节数量候选
        open-ended range
            表示从某 offset 到表示结尾
        记录原则
            不把多个 part 合并为一个连续字节范围
            Content-Range 的总长度与当前 part 长度分开

    Accept-Ranges
        作用

        限制
            缺失不证明服务器不支持 Range
            出现 bytes 不证明本次请求使用了 Range
            也不保证未来每次都返回 206
        证据
            实际 Range request
            status
            Content-Range
            Body 范围
            分别记录

    If-Range 和 validator

                说明规范化、序列化、密码学处理或封装阶段
            LAYER-ID
                说明业务层、协议层和传输层之间的边界
            VALUE-ID
                说明同一执行中值的身份与变化
        第 8 阶段对象
            PROTOCOL-MESSAGE-ID
                说明页面 API 层的一条消息
            SERIALIZATION-ID
                说明消息使用的序列化候选或已建立格式
            GRPC-WEB-ENVELOPE-ID
                说明 gRPC-Web 连续字节流中的记录边界
            STREAM-CHUNK-ID
                说明原页面实际消费的一个 stream chunk
            APPEND-OP-ID
                说明原页面向 SourceBuffer 发起的一次操作
        建立映射的最低要求
            同一 EXECUTION-ID
            同一 CONTEXT-ID
            对象身份或直接参数关系
            可说明的同步调用或 ASYNC-EDGE-ID
            与 REQUEST-OBSERVED-ID 相容的时间顺序
        不足以建立映射
            函数名包含 encode、socket、stream、media 或 license
            两条记录时间接近
            字节长度相同
            URL、MIME 或文件后缀相似
            不同执行中出现相同字符串
        输出
            已满足最低要求时记录直接映射
            只满足部分条件时记录 CANDIDATE
            不能区分多个消费者时记录 UNKNOWN

    第 6 阶段到第 8 阶段的映射
        第 6 阶段对象
            BUILD-ID
            DEPLOYMENT-ID
            ASSET-ID
            CHUNK-ID
            MODULE-ID
            SOURCE-MAP-ID
        第 8 阶段作用
            将协议实现绑定到具体构建
            将 WebSocket subprotocol、GraphQL 客户端或媒体播放器模块绑定到具体 module
            将静态字符串和运行时调用分开
            记录升级部署后协议行为是否仍属于同一实现
        可以证明
            当前构建中的某个 module 执行了一个已观察 API 调用
            某个调用位置经 Source Map 映射到一个源位置
            当前构建包含某个协议或播放器库候选
        不能单独证明
            库存在就表示当前路径使用该库
            静态字符串就是实际 endpoint、subprotocol 或 key system
            module 名称就是业务语义
            同名 asset 在不同 BUILD-ID 中内容相同
        构建变化时
            新建 BUILD-ID
            重新绑定 MODULE-ID 和调用位置
            不沿用旧构建的行列号
            不把旧构建的协议结论自动提升到新构建

    第 7 阶段到第 8 阶段的映射
        第 7 阶段对象
            CONTEXT-ID
            RUNTIME-TRACE-ID
            EVENT-ID
            CALL-ID
            ASYNC-EDGE-ID
            OBJECT-LOCAL-ID
            REQUEST-OBSERVED-ID
        第 8 阶段扩展
            为频道分配 CHANNEL-ID
            为页面消息分配 PROTOCOL-MESSAGE-ID
            为原页面读取的流分配 BODY-STREAM-ID
            为媒体播放观察分配 MEDIA-SESSION-ID
            为 EME 公开对象分配本地 ID
        上下文约束
            Window、Worker、Service Worker 和 Worklet 不自动共享对象身份

            Service Worker 观察到的请求不自动等于 Window 发起的 fetch
            media element 自动请求不自动归因于页面 JavaScript 函数

            时间邻近不能代替 ASYNC-EDGE-ID
            Promise fulfilled 只说明对应 API Promise 的结果
            Promise fulfilled 不说明后续协议、解码、授权或呈现成功

    证据冲突处理
        冲突的定义
            两条来源对同一对象、同一执行和同一层给出不相容结果
        不构成冲突
            不同层使用不同长度单位
            live manifest 的不同快照内容不同
            HTTP status 与应用 status 不同
            SourceBuffer time range 与 HTTP byte range 不同
            WebSocket API message 与 wire frame 数量未知
        处理顺序
            核对 BUILD-ID
            核对 EXECUTION-ID
            核对 CONTEXT-ID
            核对对象本地 ID
            核对时间和单位
            核对规范版本
            核对声明值与实际观察值是否被混合
        记录方式
            建立 EVIDENCE-CONFLICT-ID
            保留双方 EVIDENCE-ID
            不删除旧观察
            将依赖该冲突的结论降级
            不能消解时保持 UNKNOWN

    必须保留的替代解释
        WebSocket
            API message 可能由多个 wire frame 组成
            extension、TLS 和浏览器显示可能改变可见层次
            bufferedAmount 变化不等于服务器确认
        SSE
            网络 chunk 与 event 分隔可能不同
            连接结束、网络错误和服务器关闭可能产生不同重连结果
        Streams
            chunk 边界可能由网络、内容解码或排队策略决定
            backpressure 首先描述 stream 队列与消费关系
        二进制数据
            高熵可能来自压缩、媒体容器、编码数据或加密
            固定位置变化可能是长度、序号、时间戳、校验值或普通负载
            相同 wire type 不表示相同字段语义
        GraphQL
            persisted operation 可能是实现扩展
            subscription transport 不由 GraphQL 核心规范固定
            data 与 errors 可以同时出现
        gRPC-Web
            text mode 的 base64 chunk 可能跨 envelope
            HTTP status 与 grpc-status 属于不同层
            trailer envelope 不等于 HTTP trailer field
        HTTP Range
            Accept-Ranges 缺失不证明不支持 Range
            Range 请求可能被忽略并返回 200
            206 不证明资源是媒体 segment
            byte range 作用于所选表示的字节
        媒体 manifest
            manifest 中的 URI 不证明已经请求
            live manifest 每次响应可能代表不同窗口
            representation 改变可能来自用户选择、播放器策略、错误恢复或清单更新
        HLS 和 DASH
            protection 声明不证明当前样本已经加密
            segment 可以是独立资源或共享资源中的 byte range
            codec 声明不证明实际 bitstream 一致
        MSE
            append 完成不证明 decode 或 render 成功
            buffered 变化可能受到 coded frame eviction 或 remove 影响
            isTypeSupported 返回 true 不证明具体媒体一定可播放
        EME
            encrypted event 不证明许可证请求成功
            MediaKeySystemAccess 成功不证明获得播放授权
            update fulfilled 不证明 key status 为 usable
            usable 状态不公开密钥材料
            播放失败还可能来自网络、容器、codec、时间戳、MSE 或输出限制

    常见错误
        把 WebSocket message 当作 wire frame
            问题
                浏览器 API 交付重组后的 message
                fragmentation 和控制帧边界通常不暴露给页面 JavaScript
            修正
                只建立 PROTOCOL-MESSAGE-ID
                wire frame 保持 UNKNOWN

        把 binaryType 当作线上序列化格式
            问题
                binaryType 控制浏览器以 Blob 或 ArrayBuffer 交付二进制消息
            修正
                序列化格式单独评级

        把 WebSocket masking 当作加密
            问题
                RFC 6455 masking 不提供机密性或身份认证
            修正
                与 TLS、应用加密和签名分别记录

        把 send 返回当作已经送达
            问题
                数据可能仍在浏览器发送缓冲区
            修正
                记录 bufferedAmount
                不写成服务器已经接收或确认

        把 error 事件当作完整失败原因
            问题
                浏览器公开的错误细节可能受限
            修正
                关联 close、Network 和页面错误
                原因不足时写 UNKNOWN

        把 SSE chunk 当作 event
            问题
                SSE event 由字段行和空行解析形成
            修正
                stream chunk、文本行和 event dispatch 分栏

        把 SSE 当作双向频道
            问题
                EventSource 本身提供服务器到浏览器的事件流
            修正
                浏览器向服务器发送的数据映射到独立请求

        假定 Last-Event-ID 每次都存在
            问题
                它依赖已解析 id 和实际重连状态
            修正
                只记录实际请求 Header 是否存在

        为了观察而额外读取 stream
            问题
                会改变 locked 或 disturbed 状态并可能消费数据
            修正
                只记录原页面读取

        把 stream chunk 当作业务 message
            问题
                chunk 没有默认业务边界语义
            修正
                要求长度、分隔符或 parser 直接证据

        把 backpressure 当作网络拥塞
            问题
                backpressure 首先属于 stream 队列和消费速率
            修正
                网络层状态另行记录

        忽略 TypedArray 的 byteOffset
            问题
                view 可能只覆盖底层 ArrayBuffer 的一部分
            修正
                同时记录 view 类型、byteOffset 和 byteLength

        把字符外观当作编码证明
            问题
                同一字节序列可以被不同编码或结构解释
            修正
                要求原页面 decoder 调用或规范证据

        把高熵当作加密
            问题
                压缩数据、媒体容器和编码媒体也可能呈现高熵
            修正
                保留 compression、container、encoded media 和 encryption 候选

        仅凭偏移命名二进制字段
            问题
                稳定偏移不能提供字段业务语义
            修正
                建立 FIELD-HYPOTHESIS-ID

        把 protobuf wire type 当作字段名
            问题
                wire type 只约束编码形式
            修正
                schema 未知时字段语义保持 UNKNOWN

        把确定性 protobuf 编码当作跨实现 canonical
            问题
                确定性序列化不保证跨语言和版本形成统一 canonical bytes
            修正
                绑定具体实现与版本

        把 CBOR tag 当作完整业务 schema
            问题
                tag 只提供附加语义标记
            修正
                schema 和业务约束单独取证

        把 GraphQL endpoint 当作 schema
            问题
                URL 不提供类型、字段和授权语义
            修正
                只记录原页面实际 operation

        把所有 GraphQL 请求固定为 POST JSON
            问题
                HTTP binding 和实现可能使用不同 method 与表示
            修正
                记录实际 method、媒体类型和参数位置

        把 HTTP 200 当作 GraphQL 无错误
            问题
                GraphQL response 可以同时包含 data 和 errors
            修正
                分别记录 data、errors 和 extensions

        把 persisted query hash 当作签名
            问题
                它可能只是 operation document 的标识
            修正
                只有密码学调用和验证语义证据充分时才分类

        把 GraphQL subscription 固定为某个 subprotocol
            问题
                核心 GraphQL 规范不固定订阅 transport
            修正
                transport 独立识别并绑定版本

        把 gRPC-Web 当作浏览器原生 gRPC
            问题

        把 base64 transport chunk 当作 envelope
            问题

        把 HTTP status 当作 grpc-status
            问题

            修正

        把 message compression 与 Content-Encoding 合并
            问题

                一个属于 HTTP representation 层
            修正

            问题
                它只表示服务器声明的范围能力
            修正
                要求实际 Range 请求和响应关系

        假定 Range 请求一定返回 206
            问题
                服务器可以忽略 Range 返回 200
                不可满足时可以返回 416
            修正
                记录实际 status 和 Content-Range

        忽略 multipart/byteranges
            问题
                多个范围不是一个连续 Body 区间
            修正
                每个 part 的 Content-Range 单独记录

        把 Content-Length 当作解码后长度
            问题
                Content-Encoding 存在时声明长度对应编码后的 representation data

        把 H2 或 H3 Body chunk 当作协议 frame

        把媒体请求都归因于页面 fetch

            修正

        把 .m3u8 或 .mpd 后缀当作格式证明
            问题

            修正

        合并 HLS Master Playlist 与 Media Playlist
            问题
                两者承担不同引用层次
            修正
                分配不同 MANIFEST-ID 或快照角色

        把 live manifest 当作固定文件
            问题
                每次响应可能是不同播放窗口
            修正
                每次响应建立 MANIFEST-SNAPSHOT-ID

        按页面 URL 解析所有媒体相对 URI

            修正

        把 EXT-X-KEY 或 ContentProtection 当作密钥
            问题
                它们是保护相关元数据或描述
            修正

        把 manifest 中的 URI 当作已请求资源
            问题

        把 codec 字符串当作实际 bitstream 证明

        把 appendBuffer 返回当作 append 完成

                SourceBuffer 处理是异步过程
            修正

            一个 APPLICATION-RECORD-ID 可以跨多个 DERIVED-STREAM-CHUNK-ID
            没有 parser 直接证据时保持 UNKNOWN

    Content-Length 例外修正
        一般响应
            Content-Length 可以描述当前消息 content 的已知字节长度
            字段存在不证明当前消息一定有 Body
        HEAD 响应
            可以描述对应 GET 响应本应发送的 content 长度
            不是当前 HEAD 响应的 Body 长度
        304 响应
            可以描述相应 200 响应中所选表示的长度
            不是当前 304 响应的 Body 长度
        发送限制
            1xx 响应不得发送 Content-Length
            204 响应不得发送 Content-Length
            成功 CONNECT 响应不得发送 Content-Length
        HTTP/1.1 Transfer-Encoding
            存在 Transfer-Encoding 时不得用 Content-Length 决定当前消息 framing
        记录原则
            method、status、HTTP version 和 framing 字段必须一起解释

    SSE parser 状态修正
        空行
            运行 event dispatch 算法
            data buffer 为空时终止派发
            只有 event 或 id 字段而没有 data 时不派发事件
        data buffer
            每个 data 字段值后追加一个 U+000A
            派发前移除末尾一个 U+000A
        id 字段
            值包含 U+0000 NULL 时忽略该 id 字段
            空 id 值可以把 last event ID buffer 设为空
        retry 字段
            只有值全部为 ASCII 数字时才更新重连时间
        EOF
            不派发尚未由空行终止的未完成事件
        结论
            空行、EOF 和任意 id 行都不能单独证明产生了 SSE-EVENT-ID

    文本长度单位修正
        JavaScript string
            length 默认记录 UTF16-CODE-UNIT-LENGTH
        code point 数量
            必须明确记录 CODE-POINT-LENGTH
        byte length
            只有原页面已经提供字节序列时才记录 BYTE-LENGTH
        WebSocket text message
            API 未提供线上 UTF-8 字节长度时写 UNKNOWN
        SSE data
            不再无单位记录字符长度
            使用 UTF16-CODE-UNIT-LENGTH、CODE-POINT-LENGTH 或 UNKNOWN

    gRPC-Web flags 修正
        五字节前缀
            第一字节是 flags
            后四字节是大端 payload length
        record 类别
            flags 的 0x80 位为 1 时表示 trailers record
            0x80 位为 0 时表示 data record
        compression
            flags 的 0x01 位按协议记录 compressed 或 uncompressed
            message compression 与 HTTP Content-Encoding 分层
        保留位
            不得猜测为业务 flag
            版本和实现证据不足时保持 UNKNOWN
        长度
            表示该 record 后续 payload 的字节数
            不等于整个 HTTP Body 长度

    gRPC-Web trailers-only 修正
        trailers-only response
            可以把 grpc-status 等与响应 Header 一起发送
            Body 可以没有 message record
        检查顺序
            先记录公开响应 Header 中的状态
            再记录 Body 末尾 trailers record
        不能推断
            缺少 Body trailers record 等于缺少 RPC status
            HTTP 2xx 等于 grpc-status 0

    gRPC-Web text mode 边界修正
        HTTP 或 Fetch text chunk
            可以在任意可见字符位置切分
            可以切开一个四字符 Base64 量子
        runtime base64-encoded chunk
            是编码器 flush 形成的另一种边界
            可能包含流内 padding
            padding 不保证与 gRPC message record 边界一致
        命名
            TRANSPORT-TEXT-CHUNK 与 BASE64-FLUSH-UNIT 分开记录
            两者都不等于 GRPC-WEB-RECORD-ID
        被动限制
            只有原页面已经执行 Base64 解码时才建立 record 边界
            不为本章额外解码响应
            未解码时 record 边界保持 UNKNOWN

    protobuf wire type 版本修正
        wire type 3
            表示 start-group
        wire type 4
            表示 end-group
        legacy group
            语法已经弃用
        当前 Editions
            delimited message encoding 仍可能使用这一 wire 形式
        观察要求
            记录 proto2、proto3 或 Edition
            记录 feature set
            版本未知时保持 UNKNOWN
        结论
            不得把 wire type 3 和 4 仅写成历史数据

    MessagePack canonical 修正
        核心规范
            不提供跨实现通用 canonical encoding
        只有以下证据同时存在时才讨论稳定字节
            明确 profile 或实现选项
            明确库和版本
            明确 map 顺序、整数宽度和 extension 规则
        证据不足
            canonical 状态写 UNKNOWN
            普通序列化输出不得直接作为稳定签名字节结论
